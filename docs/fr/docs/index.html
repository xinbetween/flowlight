Installation

  1. Avec Homebrew — la même commande le met à jour plus tard :

    brew install --cask xinbetween/tap/flowlight

  2. Ou téléchargez Flowlight.dmg, ouvrez-le et glissez Flowlight dans Applications.
  3. Vous préférez un programme d’installation ? Chaque version est aussi livrée en .pkg.
  4. Compiler depuis les sources demande Xcode 16 ou une version ultérieure et xcodegen :
brew install xcodegen
git clone https://github.com/xinbetween/flowlight.git && cd flowlight
xcodegen generate && scripts/build-local.sh
open build/Build/Products/Release/Flowlight.app

Premier lancement

Les versions à partir de 0.1.6 sont signées avec un certificat Developer ID et notarisées par Apple : le premier lancement se fait donc sans détour. Vous pouvez le vérifier vous-même, spctl -a -vvv /Applications/Flowlight.app doit répondre Notarized Developer ID. Les versions jusqu’à 0.1.5 n’étaient pas signées ; pour celles-là, passez une fois par Réglages Système › Confidentialité et sécurité › Ouvrir quand même.

Le trafic commence à apparaître en moins d’une seconde. Les chiffres ↓↑ de la barre des menus sont les débits de téléchargement et d’envoi en direct.

Noms d’hôte : la configuration à faire une fois

Par défaut, macOS ne communique à Flowlight que l’adresse IP contactée par chaque app. Pour afficher de vrais noms d’hôte, Flowlight lit deux choses dans les paquets réseau : les réponses DNS, et le nom de serveur qu’un client demande à l’ouverture d’une connexion HTTPS (SNI TLS). Un filtre dans le noyau écarte tous les autres paquets avant que Flowlight les voie, et le contenu des paquets n’est jamais conservé.

macOS ne laisse que les administrateurs lire les paquets : la fenêtre Nommer votre trafic demande donc votre mot de passe une fois. Elle installe /Library/LaunchDaemons/com.flowlight.bpf-access.plist, qui donne au groupe access_bpf un accès en lecture à /dev/bpf* à chaque démarrage, la même approche que celle de Wireshark. Retirez-le à tout moment depuis Capture › Retirer l’accès à la capture de paquets.

Identifier les propriétaires de réseau étiquette le trafic sans nom d’hôte par l’exploitant de l’adresse (Cloudflare, Inc. · AS13335). C’est activé par défaut et cela envoie ces adresses IP publiques (jamais les privées) au service DNS de Team Cymru. Désactivez-le dans Capture.

Langue

Flowlight est traduit en anglais, 简体中文, 繁體中文, 日本語, 한국어, français, allemand, italien, espagnol et portugais. Par défaut, il suit votre Mac : si vos langues préférées en contiennent une que Flowlight parle, c’est celle-là qu’il utilise — et pour le chinois il distingue le simplifié du traditionnel par l’écriture et la région, de sorte qu’un Mac réglé sur zh-TW obtient le traditionnel. Tout ce dans quoi il n’a pas été traduit revient à l’anglais.

Choisissez explicitement une langue dans les Réglages ⌘,, sous Général. Le changement est immédiat, pas au prochain lancement. Quand le choix est Système, la ligne indique en dessous quelle langue cela donne.

La traduction arrive écran par écran : la navigation, les réglages et les commandes courantes sont faits, et les passages explicatifs les plus longs restent en anglais pour l’instant — une clé sans traduction affiche l’anglais correct plutôt qu’un blanc ou un identifiant.

Règles pour les agents IA

Une app compte comme agent si Flowlight la connaît par son nom (16 à ce jour, dont Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Ollama et ZCode) ou si elle appelle l’un des 27 fournisseurs d’API LLM. Les navigateurs sont exclus.

Outils & serveurs MCP

Les agents font une grande part de leur travail via d’autres processus : un outil shell lance curl, git ou npm, et les serveurs MCP tournent comme des processus à part. Flowlight remonte les parents de chaque processus jusqu’à l’agent qui l’a lancé, pour que ce trafic soit compté comme celui de l’agent. Dans Agents IA, le détail de l’agent les liste sous Outils & serveurs MCP, et les destinations indiquent via curl ou via github MCP. Dans Rapports, la ligne du processus indique via Claude Code.

Les serveurs MCP sont nommés en rapprochant leur ligne de commande de la configuration MCP de Claude Code (~/.claude.json), Claude Desktop, Cursor (~/.cursor/mcp.json), Windsurf, VS Code, Codex (~/.codex/config.toml), Zed et Gemini CLI. Les serveurs MCP distants sont reconnus par le nom d’hôte de leur URL, et les serveurs non configurés par des noms de paquets identifiables comme @modelcontextprotocol/server-github.

L’attribution se fait par processus : Flowlight ne peut pas dire quel appel d’outil, au sein d’un serveur MCP de longue durée, a ouvert une connexion.

Configuration des agents : ce que Flowlight lit sur votre Mac

Les capacités d’un agent sont écrites dans des fichiers : les skills qu’il peut charger, les sous-agents et les commandes slash qu’il définit, les hooks qui exécutent des commandes shell sur événement, les règles de permission qu’on lui a données, et les serveurs MCP qu’il démarre. Flowlight lit ces fichiers pour que l’onglet Outils puisse montrer ce que chaque agent est configuré pour faire, avant même sa première requête. Un hook qui poste vers un webhook, ou une règle qui autorise Bash(curl:*), explique un trafic qu’il faudrait sinon deviner.

  • Où il regarde par défaut : les dossiers des agents dans votre dossier de départ — ~/.claude, ~/.codex, ~/.cursor, ~/.gemini, ~/.agents et les autres du même genre. Il ne parcourt pas tout votre dossier de départ, donc macOS n’a pas à demander l’accès au Bureau, aux Documents ou aux Téléchargements.
  • Vos projets : utilisez Ajouter un dossier de projet… pour indiquer à Flowlight où vit votre code. macOS accorde alors l’accès à ce dossier-là seulement. Si le dossier se trouve dans Documents ou sur le Bureau, macOS demande d’abord, et c’est la seule demande que vous verrez.
  • Une fois, pas en permanence : le résultat est mémorisé. Flowlight ne réanalyse que si vous cliquez sur Réanalyser, et le propose au bout de deux semaines, au cas où vous auriez ajouté des agents ou des projets. Rien n’est analysé en arrière-plan.
  • Ce qu’il conserve : les noms, les descriptions, la commande qu’un hook exécute, et les commandes ou URL des serveurs MCP. Il ne copie jamais votre code, vos prompts ni vos fichiers, et rien de tout cela ne quitte votre Mac. Oublier ce qui a été trouvé l’efface.

À regarder de près

Un troisième mode dans Rapports, à côté de la répartition et des graphiques. Il compare entre elles les apps du rapport et désigne celles dont les destinations ne ressemblent pas au reste : beaucoup plus d’endroits que leurs semblables, des adresses qui ne se sont jamais résolues en un nom, des noms d’hôte qui ont l’air générés plutôt que choisis, bien plus d’envoi que de réception, et des protocoles qui sont accessoires plutôt que la raison d’être de l’app. Chaque constat porte les indices qui le fondent, et cliquer dessus restreint le rapport à cette app.

Cela s’appelle À regarder de près et non Suspect, délibérément. Ce que les données étayent, c’est « inhabituel à côté des autres apps de ce rapport » — un outil de sauvegarde parle à beaucoup d’endroits pour de bonnes raisons, et un Mac tranquille ne produit aucun constat. Cela ne dit rien du trafic que toutes les apps ont en commun.

Par où les octets sont partis

Tout le trafic ne va pas sur internet. AirDrop, Handoff, AirPlay, Sidecar et le Contrôle universel vont droit à un appareil dans la pièce, par Apple Wireless Direct Link — pas de routeur, pas d’internet, et aucune adresse joignable par quiconque. Flowlight comptait toujours ces flux ; il n’avait pas de mot pour eux, de sorte qu’un AirDrop d’un dossier de 4 GB ressemblait à quelques mégaoctets vers une adresse sans nom.

Chaque flux porte désormais un canal : Réseau, Wi-Fi pair à pair, Ce Mac (boucle locale, qui n’a jamais quitté la machine) ou Tunnel (dans un VPN ; ce qui se passe ensuite n’est pas visible ici). Restreignez un rapport à l’un d’eux depuis la barre d’outils de Rapports ; le canal voyage avec les exportations CSV et avec tout ce qui est envoyé à un collecteur.

Les lignes de pair à pair sont nommées d’après la fonctionnalité qui les a ouvertes — AirDrop and Handoff · nearby device, Continuity · nearby device — parce qu’une adresse lien-local ne vous apprend rien et que l’appareil dans la pièce n’a aucun nom que ce Mac puisse connaître. Une app qui utilise directement la radio garde son propre nom, ce qui est la réponse juste dans son cas.

Les deux moteurs répondent différemment. L’échantillonneur lit l’interface à laquelle chaque socket est liée (awdl0, llw0), ce qui est exact. L’extension réseau reçoit des sockets et non des interfaces : elle juge donc d’après l’adresse, puisque c’est ainsi qu’on adresse le trafic pair à pair, par une adresse lien-local. C’est la plus grossière des deux — une imprimante joignable en Ethernet peut être adressée de la même façon — et Flowlight préfère le dire plutôt que d’arrondir.

Rien de tout cela n’est nouvellement enregistré, et aucune nouvelle autorisation n’entre en jeu. C’est la même capture, enfin étiquetée.

Les autres alertes

  • Pic de trafic : une heure au moins 3σ au-dessus de la référence glissante de l’app (après 24 heures d’historique, au-delà de 1 MB).
  • Nombre inhabituel de destinations dans une journée, par rapport à la référence de l’app.
  • Envoi au-delà du 99e centile des envois horaires de l’app sur 30 jours.
  • Premier contact avec un nouveau domaine, et ports non standard, après une période d’apprentissage de 24 heures par app.
  • Trafic sans activité à l’écran : une app avec fenêtre que vous n’avez pas utilisée depuis 10 minutes envoie plus de 5 MB par minute.

Les apps d’Apple sont ignorées par défaut. macOS contacte Apple sans arrêt — mise à jour de logiciels, iCloud, notifications push, heure, tuiles de Plans — sur des hôtes et des ports qui sont nouveaux la première fois qu’ils apparaissent, et tout lister enterre la seule ligne qui vaut la peine d’être lue. Désactivez-le dans Réglages › Alertes si vous les voulez. Dans les deux cas le trafic est quand même enregistré, apparaît toujours dans En direct, Rapports et Demander, et reste soumis à toutes les règles, garde-fous et listes d’autorisation : le réglage décide de ce qui est listé, jamais de ce qui est permis.

Demander

Posez la question en langage courant — qu’a envoyé Claude Code hier ?, quelle app s’est mise à parler à un endroit nouveau cette semaine ?, résume la dernière heure — et obtenez une réponse tirée de l’historique enregistré sur ce Mac.

Le modèle ne reçoit jamais votre historique. On lui remet une liste de sept requêtes en lecture seule qu’il peut appeler, et rien d’autre : les totaux, les principales apps, les principales destinations, les nouvelles destinations, les alertes, les agents et une série dans le temps. Il n’existe aucune requête qui accepte du SQL, et il n’en existera pas — un modèle capable d’écrire sa propre requête peut tout lire. Flowlight exécute celle que le modèle nomme, localement, et rend les totaux et les noms. Ce qui quitte le Mac, si quelque chose le quitte, c’est votre question et ces chiffres — jamais la base de données.

Local d’abord. Là où macOS fournit un modèle sur l’appareil, c’est celui-là par défaut : il ne coûte rien, fonctionne hors ligne et n’envoie pas un octet où que ce soit. Sinon, un serveur de modèle que vous faites déjà tourner — Ollama, LM Studio, llama.cpp — fait la même chose. Les deux sont listés au-dessus des options hébergées, parce qu’un outil dont la promesse est « pas de compte, pas de cloud » ne devrait avoir besoin ni de l’un ni de l’autre pour répondre à une question sur lui-même.

Ou apportez votre propre clé pour Anthropic, OpenAI, Gemini ou n’importe quel point de terminaison compatible OpenAI. La clé va dans le trousseau de votre session, pas dans les préférences de Flowlight. Quand un fournisseur envoie quoi que ce soit hors du Mac, l’écran le dit avant que vous demandiez, et chaque requête est montrée en entier sous la réponse.

Il répond aussi aux questions sur Flowlight lui-même. Comment activer l’inspection HTTPS ?, comment empêcher un agent d’utiliser son outil shell ?, pourquoi ne vois-je aucun trafic ? — ces questions trouvent réponse dans le guide écrit de l’app pour chaque fonctionnalité, et dans un instantané de la configuration actuelle de ce Mac. Jamais dans la mémoire du modèle : les chemins de menu diffèrent d’une version à l’autre, et un chemin inventé est pire que pas de réponse. Quand la réponse demande de changer un réglage, elle dit où se trouve ce réglage et propose d’ouvrir cet écran, ce qui reste un clic que vous faites.

Des graphiques quand la forme compte. Une évolution dans le temps revient en courbe, une comparaison en barres, la répartition d’un tout en camembert. Flowlight les dessine à partir des lignes mêmes que la requête a renvoyées, donc l’image et la phrase ne peuvent pas se contredire, et le modèle peut demander une autre forme, ou aucune.

Chaque requête est listée sous la réponse, et cliquer dessus ouvre ces lignes dans Rapports. Une réponse que vous ne pouvez pas vérifier est une supposition en meilleure grammaire.

Flowlight s’applique à lui-même sa propre exigence. Tout ce que cette fonctionnalité envoie apparaît dans En direct et Rapports comme le trafic de n’importe quelle autre app — y compris quand le serveur de modèle est sur ce Mac même, le cas qu’il aurait été le plus facile de passer discrètement sous silence.

Inspection HTTPS (facultative)

Désactivée par défaut. Quand vous l’activez dans Inspecter, Flowlight fait tourner un proxy local sur 127.0.0.1:8877 avec sa propre autorité de certification, créée sur votre Mac. Pour les apps que vous faites passer par lui, il déchiffre le HTTPS et montre chaque requête et chaque réponse : en-têtes, corps, statut et temps. Dans les réponses de modèle d’un agent IA, il lit chaque appel d’outil que le modèle a demandé (Anthropic, OpenAI Chat et Responses, Gemini, et les requêtes MCP tools/call) ainsi que le résultat renvoyé par l’agent, et il relie chaque requête émise par un outil à l’appel qui l’a causée : la requête de curl vers paste.example affiche ← Bash: curl -s https://paste.example/up. Dans Agents IA, le détail d’un agent gagne Appels d’outils (chaque appel avec sa commande, son résultat ou son erreur, et les requêtes qu’il a émises), Serveurs MCP (nom et version, local ou distant ou via le fournisseur, les outils proposés, les appels et les échecs) et Outils (chaque outil que l’agent déclare au modèle, avec sa fréquence d’utilisation). La ligne d’en-tête de l’agent montre le modèle, le nombre d’appels et les jetons dépensés, y compris ceux servis depuis le cache. Les corps s’ouvrent en arborescence JSON dépliable, dans l’ordre d’origine des clés ; les flux d’événements en montrent un à la fois.

Les agents déclarent leurs outils à chaque tour : une requête inspectée montre donc plus que les appels eux-mêmes — les outils que l’agent propose, ceux que le fournisseur exécute sur ses propres serveurs (recherche web, exécution de code), et les serveurs MCP auxquels le fournisseur se connecte pour l’agent (mcp_servers chez Anthropic, l’outil mcp chez OpenAI) avec leur URL, leur jeton, leur réglage d’approbation et leurs outils autorisés. Ce dernier groupe n’apparaît jamais sur votre réseau, puisque c’est le fournisseur qui établit ces connexions, pas votre Mac.

La mise en place tient en un interrupteur. Activez l’inspection HTTPS dans Inspecter et Flowlight crée son certificat, demande votre mot de passe une fois, fait approuver le certificat et achemine les apps par le proxy. Désactiver l’interrupteur défait tout cela. Le fichier de proxy revient à une connexion directe dès que Flowlight ne tourne pas, donc le quitter ne coupe jamais votre Mac du réseau.

Les agents en ligne de commande ignorent les réglages de proxy du système : pour Claude Code, Codex, Gemini CLI ou Aider, utilisez Ouvrir un Terminal inspecté et lancez-les depuis là. Sous Avancé, vous pouvez déchiffrer les agents IA seulement plutôt que toutes les apps, modifier la liste des exclusions, copier la configuration shell pour un shell donné, ou supprimer le certificat et tout ce qui a été enregistré.

Flowlight exclut du déchiffrement sa liste intégrée de services Apple et de gestionnaires de mots de passe (modifiez la liste dans la Configuration). Les apps qui épinglent leurs certificats peuvent rejeter le certificat de Flowlight ; Flowlight s’en aperçoit et les laisse passer chiffrées. Les clés d’API, les cookies et les autres en-têtes d’identification ne sont jamais conservés, les requêtes enregistrées sont gardées 3 jours, et Supprimer le certificat & les données enregistrées supprime le certificat, son réglage d’approbation et tout ce qui a été enregistré. L’inspection est en HTTP/1.1 uniquement (Flowlight le demande aux deux parties) et n’est pas disponible en mode démo.

Réponses simulées

Pour voir comment un agent réagit quand une API échoue, se bloque ou renvoie quelque chose d’étrange, répondez vous-même à ce point de terminaison. Dans Inspecter › Réponses simulées, une règle nomme un hôte, un chemin et une méthode, et donne le statut, les en-têtes, le corps et un délai facultatif à renvoyer. La requête n’est jamais envoyée : c’est Flowlight qui y répond.

  • L’hôte est exact — api.example.com — ou *.example.com pour un domaine et ses sous-domaines. Exact par défaut, parce qu’une simulation visant un seul point de terminaison ne devrait pas répondre en silence pour tout un domaine.
  • Le chemin accepte un joker * : /v1/*, /v1/*/items, ou un chemin exact. La chaîne de requête est ignorée, sauf si votre motif en contient une.
  • La méthode correspond à un verbe, ou à n’importe lequel.
  • Les règles sont ordonnées et la première correspondance active répond. Chacune s’active et se désactive séparément.

Un échange simulé est enregistré comme n’importe quel autre et marqué Simulé dans la liste, le volet de détail précisant qu’il a été traité par Flowlight et non par l’hôte, et nommant la règle. Vous pourrez toujours savoir plus tard ce qui était réel.

Deux choses à savoir. Seul le trafic que Flowlight déchiffre peut être simulé : le point de terminaison doit donc passer par l’inspection HTTPS — une règle portant sur un hôte fait déchiffrer cet hôte par Flowlight même si votre périmètre se limite aux agents. Et la destination est quand même contactée : une simulation change la réponse, pas la possibilité d’établir la connexion, donc « l’API renvoie 500 » fonctionne alors que « l’API est complètement injoignable » non.

Règles

Une liste d’autorisation, c’est l’idée qu’un agent se fait des endroits où il peut aller. Une règle en est la version générale : elle nomme un sujet — une app, un agent, une destination, une URL, ou un couple formé de deux d’entre eux — et dit bloquer ou autoriser. Faites un clic droit sur n’importe quelle ligne dans En direct, Rapports, Agents IA ou Inspecter pour en écrire une sur ce que vous regardez ; toutes atterrissent dans le même éditeur, sur l’écran Règles, parce qu’une règle qui prendrait effet hors de votre vue serait une règle que vous ne pourriez plus jamais retrouver.

Des modèles. Vingt-deux, en cinq groupes — empêcher un agent d’atteindre des registres de paquets ou d’autres fournisseurs de modèles, fermer les voies habituelles par lesquelles les données partent (sites de partage de texte, collecteurs de webhooks, dépôts de fichiers anonymes, tunnels, DNS over HTTPS), l’analytique produit et les rapports de plantage, les politiques d’horaires de travail, et le « bloque-moi ça une heure, le temps que je comprenne ce que c’est ». Parcourez-les depuis la barre d’outils de Règles, ou faites un clic droit sur une ligne n’importe où dans En direct, Rapports, Agents IA ou Inspecter et appliquez-en un à ce que vous regardez.

Chaque modèle annonce ce qu’il va faire avant de le faire. Tout ce qui écrit plus d’une règle ouvre une fiche listant chaque hôte et chaque horaire ; tout ce qui est permanent ouvre l’éditeur prérempli ; et seules les règles qui se défont d’elles-mêmes — une heure, ou cette exécution de Flowlight — sont appliquées sans être montrées d’abord. Chacune porte aussi ses réserves, y compris le moteur qu’elle requiert : un modèle qui ne fonctionne qu’avec l’inspection HTTPS le dit.

Quelle règle gagne. La correspondance la plus spécifique décide, et quand deux règles sont aussi étroites l’une que l’autre, c’est le blocage qui tient. Ainsi une exception écrite sous un blocage large fonctionne — Cursor may reach api.github.com survit à nothing reaches github.com — tandis qu’une exception plus large que ce qu’elle excepte ne l’élargit pas en silence.

Pour combien de temps. Pour toujours ; jusqu’à une heure donnée ; jusqu’à la fermeture de Flowlight ; ou entre deux heures, certains jours. Les heures sont locales et évaluées au moment où une connexion est établie : un Mac qui a dormi pendant la fin d’une plage la trouve fermée au réveil, et un changement d’heure ou de fuseau déplace la plage avec lui. La fermeture d’une plage arrête les nouvelles connexions — elle ne coupe pas celles qui sont déjà ouvertes. Il existe aussi un Suspendre le blocage global, parce que c’est l’échappatoire qui rend des règles strictes vivables.

Débloquer fait partie du blocage. Chaque refus porte sa sortie de secours : depuis l’alerte, autorisez-le une fois, pour une heure, ou jusqu’à la fermeture de Flowlight. Chacune de ces autorisations est elle-même une règle avec une échéance, de sorte que la liste peut toujours répondre à pourquoi est-ce que ça passe ? — y compris pour l’assouplissement que vous avez validé il y a quinze jours.

Là où une règle mord, et là où elle ne peut pas. L’extension réseau refuse des connexions entières : elle connaît l’hôte, l’adresse et le port, rien des chemins, et uniquement en mode extension. L’inspection HTTPS refuse une requête : elle peut donc viser une URL et répondre par un statut que l’agent sait lire, au lieu d’une socket morte sans explication. L’échantillonneur nettop ne peut rien refuser du tout. Une règle que la configuration actuelle ne peut pas appliquer le dit dans la liste, plutôt que de rester là en faisant semblant.

Le second onglet est le flux des violations : chaque connexion qu’une règle a tranchée, avec l’app, sa destination, quelle règle a tranché et s’il s’agissait d’un refus ou d’une exception qui l’a laissée passer.

Listes d’autorisation

Sélectionnez un agent dans Agents IA et utilisez Liste d’autorisation dans son détail pour dire où il peut se connecter. Saisissez des domaines (sous-domaines inclus), des adresses IP ou des plages CIDR, ou choisissez un préréglage : GitHub, npm, PyPI, Homebrew, Docker Hub, crates Rust, modules Go ou Apple. Les fournisseurs d’IA de l’agent (sauf si vous le désactivez) et votre réseau local sont toujours autorisés.

Dès lors, tout ce que l’agent ou ses outils contactent sans être listé déclenche une alerte critique Violation de la liste d’autorisation (une fois par domaine toutes les 6 heures) et est marqué Non autorisé, avec un bouton Autoriser qui l’ajoute. Par défaut, une liste d’autorisation avertit plutôt qu’elle ne refuse les connexions ; le blocage nécessite le moteur d’extension réseau et figure à la feuille de route.

Refuser des connexions

Une liste d’autorisation avertit par défaut. Activez Refuser les connexions hors de la liste pour un agent et elle les refusera aussi : la connexion est abandonnée et une alerte consigne ce qui a été refusé, avec Autoriser … désormais pour l’ajouter à la liste en un clic. La tentative suivante de l’agent passe.

Cela nécessite l’extension réseau. Refuser une connexion suppose de se trouver sur son chemin, ce que l’échantillonneur nettop ne peut pas faire — Capture le dira plutôt que de proposer un interrupteur qui ne fait rien.

Certaines choses ne sont jamais refusées, quoi qu’en dise une liste : votre réseau local, le DNS, les services d’Apple et le trafic de Flowlight lui-même. Un Mac bloqué est un pire résultat qu’un agent bloqué : en cas de doute, la connexion est donc autorisée et enregistrée. L’application des refus cesse aussi quelques secondes après l’arrêt de Flowlight — un refus que personne ne peut voir est pire que pas de refus, et le moyen de l’annuler vit dans l’app.

L’inspection HTTPS et le blocage ne se combinent pas : le trafic acheminé par le proxy de Flowlight sort comme trafic de Flowlight, qui n’est jamais refusé.

Garde-fous des agents : bloquer un outil, un serveur ou une ressource

Quels outils cet agent peut-il utiliser est une question différente de quels hôtes peut-il joindre : elle a donc sa propre section — un onglet Garde-fous à côté de chaque agent dans Agents IA, avec un interrupteur sur chaque outil qu’il déclare et chaque serveur MCP qu’il atteint, des préréglages qui valent la peine (lecture seule, pas de shell, pas d’écriture), et le relevé de ce qui a été retiré.

Le levier le plus puissant est la déclaration. Les agents renvoient toute leur liste d’outils à chaque tour. Flowlight retire un outil refusé de cette liste avant le départ de la requête, de sorte que le modèle ne le voit jamais : pas de refus à négocier, pas de boucle de nouvelles tentatives. Cela fonctionne de la même façon pour un outil que l’agent exécute lui-même et pour un outil derrière un serveur MCP distant, et cela lit les mêmes structures que Flowlight analyse déjà pour Anthropic, OpenAI et Gemini.

Un appel refusé reçoit une réponse en règle. Pour les serveurs MCP joints en HTTP, un tools/call bloqué revient sous forme de result portant isError: true et une phrase claire, parce que c’est ainsi que le protocole décrit un outil en échec — le modèle le lit et contourne, là où une erreur de transport aurait l’air d’un serveur cassé. resources/read et prompts/get n’ont pas de forme équivalente : ils reçoivent donc une erreur JSON-RPC.

Les connecteurs sont restreints, pas interceptés. Quand le fournisseur joint un serveur MCP pour le compte de l’agent, ce trafic ne touche jamais ce Mac. Le seul levier est la requête qui le met en place : Flowlight restreint donc les outils que le connecteur est autorisé à appeler, ou supprime le connecteur entièrement.

Les serveurs stdio locaux parlent par des tubes, et aucun proxy ne peut voir cela. Ce que Flowlight peut faire là, c’est surveiller le trafic réseau du processus serveur lui-même, déjà attribué à l’agent qui l’a lancé, et vous remettre la liste de refus à coller dans les réglages de l’agent — Claude Code accepte mcp__server__tool dans permissions.deny, et ses voisins ont des équivalents. Cela prend effet au redémarrage de l’agent.

Les garde-fous nécessitent l’inspection HTTPS, parce que la liste des outils vit dans un corps de requête. Inspection désactivée, l’onglet le dit plutôt que d’avoir l’air de fonctionner.

Ce n’est pas un bac à sable. Un outil refusé cesse d’être proposé et cesse d’obtenir une réponse. Un agent qui a encore un shell peut faire à la main ce que l’outil aurait fait. Flowlight l’enregistrera ; il ne prétend pas l’empêcher.

Capture : moteurs et sources

Flowlight enregistre le trafic de deux façons, au choix dans Capture. Elles diffèrent par ce qu’elles peuvent manquer, ce qu’il vaut la peine de comprendre avant de compter sur l’une ou l’autre.

Ce que l’échantillonneur manque, ce sont des connexions entières, pas des octets. Comme il compare des compteurs cumulés, rien de ce qui dure d’un relevé à l’autre n’est perdu, quelle que soit la quantité arrivée entre-temps. Ce qui n’apparaît jamais, c’est ce qui commence et finit entre deux relevés — une résolution DNS rapide, un appel d’API éclair, un script qui lance curl et se termine. Pour surveiller un agent qui fait beaucoup de requêtes brèves, cette différence compte.

L’extension, elle, se trouve sur le chemin des données : une requête de cinq millisecondes est enregistrée comme n’importe quelle autre. Elle n’est pas magique pour autant : le trafic antérieur à son activation n’y est pas, une partie du trafic système est dispensée des filtres de contenu, et ses comptes d’octets viennent des statistiques du filtre plutôt que d’un comptage de paquets. Elle ne refuse une connexion que là où une règle ou une liste d’autorisation que vous avez écrite le demande.

Quand l’extension cesse de répondre. macOS exécute la version de l’extension qui a été activée en dernier : après une mise à jour de l’app, les deux peuvent donc être en désaccord — et dans ce cas, macOS refuse la connexion entre elles. Les Réglages Système disent que le filtre est activé, Flowlight dit que la connexion a été invalidée, et aucun des deux ne change d’avis. Flowlight s’en sort désormais tout seul : il rappelle deux ou trois fois, puis demande à macOS quelle version il exécute et réinstalle l’extension si ce n’est pas celle de cette app ; et si rien de tout cela ne marche, il capture avec l’échantillonneur nettop pour qu’il y ait quand même des données — en le disant clairement, et sans toucher à la source que vous avez choisie. Réessayer l’extension, sous Extension réseau, reprend tout à zéro.

Elle ne peut pas non plus fonctionner du tout sur certains Mac. macOS n’autorise qu’un filtre de contenu à la fois, et les logiciels de sécurité d’entreprise le détiennent d’ordinaire — Palo Alto Networks GlobalProtect, CrowdStrike Falcon et compagnie. Le filtre de Flowlight s’installera et se connectera sur ces machines, puis ne recevra jamais une seule connexion. Capture liste ceux qu’il trouve et propose de vous ramener à l’échantillonneur, qui n’a besoin d’aucun filtre et fonctionne à côté d’eux. Voyez le guide du développeur pour la façon dont c’est construit.

Appareils : Bluetooth, USB et stockage externe

Un Mac émet et reçoit par plus que TCP et UDP. L’écran Appareils couvre le reste, et il est désactivé jusqu’à ce que vous l’activiez — non parce qu’il demanderait une autorisation que Flowlight n’a pas déjà, mais parce que surveiller davantage de votre Mac devrait être votre décision plutôt que le fait d’une mise à jour.

Bluetooth montre quels appareils sont appairés, lesquels sont connectés, et quand cela a changé, lu depuis le système toutes les trente secondes. À côté se trouve la liste des applications conçues pour utiliser le Bluetooth, tirée du Info.plist de chaque app.

Ce qu’il ne peut pas vous dire, et qu’il avoue. Il n’y a pas de compte d’octets ici. macOS ne tient aucune comptabilité par app pour le Bluetooth, et les traces HCI au niveau de l’octet qui en donneraient une exigent le profil PacketLogger d’Apple, qu’une app ordinaire ne peut pas lire. De même, la liste des apps dit qui a demandé le Bluetooth, pas qui l’a obtenu : macOS garde les autorisations dans une base qu’une app ne peut pas ouvrir, et Flowlight préfère nommer cette différence plutôt que de l’estomper.

USB et stockage externe liste ce qui est branché — ce que c’est, qui le fabrique, et la capacité d’un disque — et consigne l’arrivée et le départ de chacun. Les deux moitiés fonctionnent différemment à dessein : les appareils USB sont lus périodiquement depuis le système, tandis que les volumes viennent de l’espace de travail à l’instant où l’un est monté ou éjecté, parce que l’arrivée d’un disque est l’événement qui intéresse vraiment les gens. Le débit n’est pas là non plus, pour la même raison qu’il n’est pas sous Bluetooth.

Mode Focus

Choisissez quelques apps et destinations, et chaque écran n’affiche plus qu’elles — En direct, Rapports, Alertes, Agents IA et Inspecter, ainsi que les débits dans la barre des menus. C’est fait pour regarder un agent travailler sans le reste du Mac dans le champ.

  • Faites un clic droit sur n’importe quelle ligne dans En direct, Rapports ou Agents IA et choisissez Focus sur…, ou utilisez la commande Focus au bas de la barre latérale pour piocher parmi les apps qui ont été actives et saisir des destinations.
  • ⇧⌘F active et désactive Focus, et la barre des menus aussi, qui montre également ce qui est ciblé.
  • Une destination emmène ses sous-domaines avec elle : example.com couvre api.example.com. Les adresses IP fonctionnent ; les plages comme 10.0.0.0/8 non.
  • Apps et destinations forment une union, pas une intersection : cibler Claude Code et github.com montre tout ce que fait Claude Code plus tout ce qui parle à GitHub.

Une app et une destination sont également des cibles, et l’une ou l’autre suffit. Ajoutez une app en tapant son nom ou son identifiant de bundle — toutes les applications du Mac sont cherchables, donc une app restée silencieuse toute la journée peut quand même être ciblée, comme un agent en ligne de commande sans bundle d’application — ou cochez-en une parmi celles qui ont été actives récemment. Ajoutez une destination de la même façon.

Une chose qu’une destination ne peut pas restreindre : les alertes consignent l’app qui les a déclenchées et rien sur la destination du trafic, donc un Focus fait uniquement de destinations laisse la liste des alertes intacte. L’éditeur le dit plutôt que de laisser un écran l’ignorer en silence.

Focus filtre ce que vous voyez, jamais ce qui est enregistré. Flowlight continue de tout capturer et de tout stocker pendant qu’il est actif, et les références d’anomalies continuent d’apprendre sur l’ensemble : désactiver Focus fait donc réapparaître le trafic qu’il cachait. Une conséquence : une alerte nomme l’app qui l’a déclenchée et non la destination du trafic, donc cibler uniquement des destinations laisse la liste des alertes telle quelle.

Fonctionner en arrière-plan

Flowlight continue d’enregistrer fenêtre fermée, et ne coûte presque rien au repos — il cesse de construire des graphiques que personne ne regarde. Réglages › Général › Exécuter en arrière-plan va plus loin et retire l’icône du Dock et l’entrée Cmd-Tab ; la barre des menus garde les débits en direct et gagne Afficher l’icône du Dock pour revenir en arrière. Lancer à l’ouverture de session est au même endroit.

La fenêtre s’ouvre là où vous l’avez laissée, à la taille où vous l’avez laissée. Un premier lancement remplit l’écran à la place, pour que rien ne soit caché derrière une petite fenêtre par défaut, et une fenêtre dont la position enregistrée est hors écran — un moniteur débranché — revient sur l’écran que vous avez. La configuration des noms d’hôte est proposée un peu après le lancement et seulement tant qu’une fenêtre est ouverte, plutôt que d’accueillir un premier lancement par une demande de mot de passe ; la proposition revient au lancement suivant jusqu’à ce que vous l’acceptiez ou l’écartiez.

Quitter Flowlight arrête l’échantillonneur. Cela n’arrête pas l’extension réseau : une extension système tourne pour son compte, donc le filtre continue d’inspecter les connexions jusqu’à ce que vous le désactiviez ou le désinstalliez dans Capture.

Exporter vers OpenTelemetry ou un SIEM

Désactivé tant que vous ne l’avez pas configuré, et il n’existe aucun service Flowlight vers lequel envoyer. C’est vous qui nommez le point de terminaison — votre propre collecteur, votre propre SIEM — et rien ne part avant cela. Réglages › Exportation.

  • OTLP sur HTTP avec un corps JSON : les agrégats vont vers /v1/metrics, les alertes vers /v1/logs, parce qu’une alerte est un événement accompagné d’une phrase et qu’une métrique perdrait la phrase. Le JSON délimité par retours à la ligne est là pour les collecteurs qui ne veulent que des lignes.
  • Ce qui part est listé exactement dans le panneau, champ par champ, et un aperçu montre une charge utile réelle construite à partir de vos propres données avant que rien ne soit envoyé.
  • Jamais rien qui vienne de l’inspection HTTPS. Pas d’en-têtes, pas de corps, pas d’appels d’outils — l’exportation ne peut transporter que des agrégats et des alertes, donc ces choses-là n’ont nulle part où aller, même par accident.
  • Les en-têtes d’authentification sont gardés dans le trousseau de votre session, pas dans les préférences. Seuls leurs noms sont affichés.
  • Ce que Flowlight envoie apparaît dans Flowlight, dans En direct et Rapports, comme le trafic de n’importe quelle autre app — y compris pour un collecteur sur 127.0.0.1.

Deux choses à prévoir : les agrégats sont consolidés avec environ deux minutes de retard, donc un intervalle inférieur à la minute interroge plus souvent sans que les données arrivent plus tôt ; et Tester la connexion prouve que le point de terminaison répond, pas qu’il a validé vos identifiants — la ligne « dernière exportation réussie » est le signal honnête.

Vos données

Tout vit dans ~/Library/Application Support/Flowlight/traffic.sqlite. Les lignes par seconde sont conservées 6 heures (réglable), les lignes à la minute 14 jours, les lignes horaires 400 jours, les lignes quotidiennes indéfiniment, et les alertes 90 jours. Capture › Effacer toutes les données les supprime.

Mises à jour

Quand une nouvelle version paraît, Flowlight vous le signale par une notification et un badge dans la barre latérale plutôt qu’en interrompant ce que vous faites ; cliquer sur l’un ou l’autre ouvre la fenêtre de mise à jour. Une recherche que vous lancez vous-même l’ouvre tout de suite.

Flowlight vérifie sur GitHub s’il existe une nouvelle version au lancement et une fois par jour, et Rechercher les mises à jour… est dans les menus de l’app et de la barre des menus. Télécharger récupère l’image disque dans Téléchargements et la vérifie avec le SHA-256 publié de la version. Rien n’est installé avant votre choix : Quitter & installer ferme Flowlight, le remplace par la nouvelle version et le rouvre, en gardant votre historique et vos réglages. Installer plus tard vous laisse travailler. Si Flowlight a été installé avec le .pkg, macOS demande un mot de passe d’administrateur pour le remplacer. Désactivez la recherche dans Réglages › Général.

Vous mettez à jour à la main ? Quittez d’abord Flowlight (icône de la barre des menus › Quitter), puis glissez la nouvelle version dans Applications. Le Finder ne peut pas remplacer une app encore en cours d’exécution et dit que l’élément est en cours d’utilisation.

Mode démo

open /Applications/Flowlight.app --args -FLDemo YES lance Flowlight avec 90 jours de trafic synthétique dans une base de données distincte, pour que vous puissiez regarder autour de vous sans enregistrer le vôtre. C’est ce que montrent les captures d’écran de ce site.

Désinstallation

  1. Dans Capture, choisissez Retirer l’accès à la capture de paquets (demande votre mot de passe) si vous l’aviez activé, désinstallez le filtre de contenu si vous l’aviez installé, et désactivez l’inspection HTTPS dans Inspecter pour que son certificat quitte votre trousseau. Flowlight seul peut retirer ces trois choses.
  2. Quittez Flowlight et déplacez-le d’Applications vers la Corbeille — ou, si vous l’avez installé avec Homebrew, brew uninstall --cask flowlight.
  3. Supprimez ~/Library/Application Support/Flowlight pour effacer l’historique enregistré, ou laissez Homebrew le faire avec brew uninstall --zap --cask flowlight.

Questions & réponses

Pourquoi macOS a-t-il demandé à Flowlight l’accès à mon Bureau ou à mes Documents ?
Uniquement parce que vous l’avez pointé vers un dossier de projet situé dans l’un des deux. Par défaut, Flowlight lit la configuration des agents dans les dossiers de votre dossier de départ et ne touche jamais à ces trois emplacements.
Flowlight voit-il tout mon trafic, ou en manque-t-il ?
Cela dépend du moteur de capture que vous utilisez, et la différence n’est pas subtile. L’échantillonneur par défaut lit les compteurs d’octets cumulés de macOS une fois par seconde et enregistre l’écart : un transfert long est donc compté exactement — mais une connexion qui s’ouvre et se ferme entre deux relevés n’apparaît pas du tout. L’extension réseau est appelée par macOS à chaque connexion établie, donc même une requête de cinq millisecondes est enregistrée. Si vous surveillez un agent IA qui déclenche beaucoup de requêtes brèves, installez l’extension depuis Capture. La comparaison complète est plus haut.
J’ai activé l’extension réseau et rien n’apparaît. L’échantillonneur fonctionne très bien.
Presque toujours parce qu’un autre filtre de contenu occupe déjà la place. macOS n’exécute qu’un filtre de contenu à la fois, et les logiciels de sécurité d’entreprise se l’accaparent d’ordinaire — Palo Alto Networks GlobalProtect, CrowdStrike Falcon et similaires. Le filtre de Flowlight s’installe, s’active et se connecte quand même, donc Capture affiche Connecté à l’extension de filtrage, mais macOS ne lui remet jamais une seule connexion et les écrans restent vides. Capture liste les filtres qu’il trouve et propose de vous ramener à l’échantillonneur, qui n’utilise pas de filtre et fonctionne à côté d’eux. Vous ne perdez que les connexions très brèves (la comparaison) ; tout le reste est enregistré de la même façon.
L’extension a cessé de fonctionner après une mise à jour de Flowlight.
Les versions antérieures à 0.2.5 avaient ce défaut : macOS continue d’exécuter la version de l’extension activée en dernier, donc après une mise à jour l’extension était l’ancienne version, et macOS refuse la connexion entre une paire dépareillée. À partir de 0.2.5, Flowlight vérifie au lancement et réactive le filtre lui-même. Sur une version plus ancienne, appuyez une fois sur Installer & activer le filtre dans Capture.
Autre chose ne va pas avec la capture et je ne sais pas quoi.
Lancez ceci et lisez ce qui s’affiche — cela ne rapporte que des états et des comptes, jamais rien de ce que Flowlight a enregistré sur votre trafic :

curl -fsSL https://raw.githubusercontent.com/xinbetween/flowlight/main/scripts/diagnose.sh | zsh

Cela montre quelles extensions sont installées, si macOS a réellement démarré le filtre de Flowlight, et à quand remonte le dernier enregistrement. Collez le résultat dans un ticket.
Flowlight envoie-t-il quoi que ce soit à mon sujet, où que ce soit ?
Non. Il n’y a ni compte, ni télémétrie, ni analytique. Les seules requêtes qu’il émet sont la recherche quotidienne de mise à jour, les recherches facultatives de propriétaire de réseau, et le DNS inverse — chacune listée, et chacune avec un interrupteur d’arrêt, sur la page Confidentialité.
Va-t-il ralentir mon Mac ou vider la batterie ?
Fenêtre fermée, Flowlight ne fait presque rien : il tient à jour les débits de la barre des menus et écrit une ligne par seconde. L’extension réseau coûte moins que l’échantillonneur de secours, qui lance un processus nettop éphémère chaque seconde.
Peut-il bloquer des connexions ?
Oui, avec l’extension réseau. La liste d’autorisation d’un agent peut refuser autant qu’avertir, une règle peut bloquer une app, une destination ou une URL aussi longtemps que vous le dites, et un garde-fou peut retirer un outil à un agent avant que son modèle ne le voie. Rien ne bloque avant que vous le demandiez, et chaque refus porte sa sortie de secours.
Ai-je besoin de l’extension réseau ?
Non. L’échantillonneur ne demande aucun droit particulier et couvre la majeure partie du trafic. L’extension ajoute les flux plus courts qu’une seconde, l’attribution par signature de code, les noms d’hôte sans la configuration de capture de paquets, et c’est le seul moteur capable de refuser une connexion.
Qu’advient-il de mes données si je désinstalle ?
Tout vit dans ~/Library/Application Support/Flowlight. Supprimez ce dossier et c’est parti ; voyez Désinstallation pour l’assistant de capture de paquets et le certificat d’inspection.

Limites

  • TCP et UDP seulement. ICMP (ping) et les autres protocoles sur IP brute ne sont pas attribués.
  • L’attribution se fait par processus, pas par thread.
  • Sauf si vous activez l’inspection HTTPS, Flowlight ne lit que des métadonnées et ne déchiffre jamais le trafic. Les noms de serveur QUIC viennent du DNS plutôt que de la poignée de main chiffrée.
  • L’inspection ne voit que les apps qui passent par le proxy, et jamais les apps qui épinglent leurs certificats.
  • La capture des noms d’hôte suit l’interface réseau principale.
