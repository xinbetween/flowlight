威胁模型

只做监控，不做防护

Flowlight 会告诉你，你 Mac 上的软件正在发送什么、发往哪里。它不是用来对付已经掌控这台机器的攻击者的， 而这个区别重要到值得单开一页来讲，而不是塞进脚注里。

它是做什么用的

Flowlight 回答一个 Mac 不回答的问题：是哪个应用发出去的，它去了哪里？它针对的是明面上就行为不端的 软件——一个去联系没人让它联系的地方的 AI 代理、一个上传得比它该上传的更多的工具、一个在跟没有名字的地址说话的进程。 这种行为在流量里是看得见的，而 Flowlight 的职责就是把它变得可读，并在做不到的时候老实说出来。

它不是杀毒软件，不是 EDR 代理，也不是那种站在你和攻击者之间的防火墙。在两者重叠的地方——Flowlight 可以拒绝连接—— 那种拒绝是一种便利，用来管住你本来就信任的软件，而不是一道拦住你不信任的软件的屏障。

它能防住什么

  • 没人留意的数据外流。某个应用或代理把东西发往一个你本来不会批准的地方，包括经由它自己运行的工具发出去。 Flowlight 会把这条连接归属到发起它的进程，以及启动那个进程的代理。
  • 行为上的悄然变化。某个应用突然联系新的目标、移动的数据远超它自己的基线，或在你离开时还在工作。 每条警报都会说明是哪个数字触发了它，所以你可以不同意它。
  • 超出你所允许范围的代理。每个代理各有一份允许列表，还有拒绝列表之外连接的规则；拒绝会被记录下来， 一键就能改为允许。
  • 被篡改的更新。每个版本都会公布校验和；更新程序会拒绝无法校验的下载，也会拒绝安装签名团队与 发起更新的那份运行中副本不一致的应用。

拥有 root 的软件可以把它关掉

Flowlight 以你的身份运行，并使用一个由 macOS 代它启动的系统扩展。任何以 root 运行的东西——或者任何你批准了安装程序的 东西——都可以卸载那个扩展、停掉这个应用，或者删掉它的数据库。设计上没有任何东西能阻止这一点，而 macOS 上的任何监控工具 都无法在保持为一个你自己也能关掉的工具的同时阻止它。

诚实的说法更窄，但依然有用：行为不端、却没有主动躲避监控的软件会被看见。主动躲避监控的软件可能不会被看见， 但它至少会留下一个缺口——一个停掉的扩展、一段没有数据的时间——而覆盖范围界面 就是为了把它显示出来。

捕获会漏掉什么

  • 捕获开始之前的流量。没有事后补录。在过滤器之前就已经建立的连接，从来没有交给过它。
  • 豁免于内容过滤器的系统服务。macOS 并不会把一切都给内容过滤器看；它自己的一部分流量永远到不了我们这里。
  • 位置被另一个内容过滤器占着。macOS 一次只运行一个。如果某个 VPN 或安全代理占着它，Flowlight 的过滤器 能安装、能连接，却永远不会被要求过滤任何东西——捕获界面会明说这一点，而不是给你一个空白界面。
  • 短连接，在采样器上。没有扩展时，Flowlight 每秒读取一次计数器：在两次读取之间开启又关闭的连接， 永远不会被记录。
  • 不是 TCP 也不是 UDP 的通道。蓝牙和 USB 是以设备的形式可见的，不是以字节的形式。代理的本地 MCP 服务器 通过管道通信，那根本不是网络流量，任何地方都不会出现。

检查会漏掉什么

HTTPS 检查只读得到经由 Flowlight 本地代理转发的东西，而这件事是由程序在启动的那一刻决定的。忽略代理设置的应用、 在检查打开之前就启动的应用，或者固定自己证书的应用，都会原封不动地直接通过——这是刻意的，因为破坏一条固定了证书的连接 就等于弄坏那个应用。QUIC 同样不会交给代理。

所以，检查界面是空的，意思是“没有东西被转发到这里”，而不是“什么都没发生”。到底是哪一种，覆盖范围会按应用逐个说明。

阻止是什么，不是什么

一条拒绝连接的规则由网络扩展执行，就在连接的路径上，在连接建立之前。一条指名 URL 的规则则由检查用的代理服务器执行， 它用应用能读到的状态来回答那个请求。这两处是 Flowlight 里唯一动手而不只是报告的部分——nettop 采样器什么都拒绝不了， 所以在用采样器的 Mac 上，没有任何规则会被强制执行，而 Flowlight 会把这一点说出来，而不是摆一个什么都不做的开关。

它仍然不是防护。一个能运行 shell 的代理，可以手动做到那个被拒绝的工具本来要做的事。一次你能一键撤销的拒绝， 也是代理下一次尝试就可能走过去的拒绝。本地流量、DNS、Apple 自家的服务以及 Flowlight 自己的连接永远不会被拒绝， 因为一台被封住的 Mac 比一个被封住的代理更糟。而且 Flowlight 停止运行几秒之后，强制执行就会失效： 没人能看见的拒绝比没有拒绝更糟。

检查与拒绝无法并存。经由 Flowlight 自己的代理服务器转发的流量，是以 Flowlight 的流量的身份离开这台 Mac 的， 而 Flowlight 从不拒绝自己——所以一个你正在读它请求的应用，也就是一个规则不再拦得住它连接的应用。为了看得更多而打开检查， 代价就是强制执行，而画面上此前并没有说这一点。

Flowlight 自己保存了什么

流量元数据，存在本地的 SQLite 数据库里，保留期限是公布的。打开 HTTPS 检查后，它还会保存请求和响应的正文三天—— 这是它所保存的东西里最敏感的。凭据标头会按名称、也按其中的词来遮蔽，那是一种启发式判断，不是保证； 一个把密钥放在没人认得的名字底下的标头，是可能被记录下来的。

流量数据库从不上传。不过确实有三样比较小的东西，会在你没有要求的情况下离开这台 Mac，它们都在隐私页面上 逐项列出：更新检查，它在启动时和每天一次向 GitHub 询问最新的发布；网络所有者查询，它就没有主机名的公网地址向 Team Cymru 询问；以及，当 Flowlight 在读计数器而不是在跑它的扩展时，对那些它没看到名字的地址做的一次反向 DNS 查询。前两样都有关闭 开关。第三样没有，因为在采样器上，一条连接能有名字，大半就靠它——这次查询会走这台 Mac 本来就在用的解析器，而一旦扩展 接手、从流量本身给连接命名，它就停了。用托管模型提问，送出去的东西比它们任何一个都多得多，而它也是唯一在你配置之前 一直关着的。

更新

版本以 Developer ID 签名并经过公证。更新程序要求有公布的校验和，没有就拒绝下载；随后会在安装之前核对下载到的应用 是否由与运行中副本相同的团队签名。由别人签名的更新会被拒绝，即使它在其他方面都有效。
