使用 Flowlight

从第一次启动到调整代理规则，需要的都在这里。Flowlight 0.7.7，macOS 15 或更高版本。

安装

  1. 用 Homebrew 安装——以后升级也是同一条命令：

    brew install --cask xinbetween/tap/flowlight

  2. 或者下载 Flowlight.dmg，打开它并把 Flowlight 拖进“应用程序”。
  3. 想用安装包？每个发布版本都另附一个 .pkg。
  4. 从源代码编译需要 Xcode 16 或更高版本，以及 xcodegen：
brew install xcodegen
git clone https://github.com/xinbetween/flowlight.git && cd flowlight
xcodegen generate && scripts/build-local.sh
open build/Build/Products/Release/Flowlight.app

首次启动

0.1.6 起的发布版本都用 Developer ID 证书签名，并经过 Apple 公证，所以第一次启动可以直接打开。你也可以自己验证：spctl -a -vvv /Applications/Flowlight.app 应当回答 Notarized Developer ID。 0.1.5 及更早的版本未签名，需要在系统设置 › 隐私与安全性 › 仍要打开里操作一次。

流量会在一秒内开始出现。菜单栏里的 ↓↑ 数字是实时的下载和上传速率。

主机名：一次性设置

默认情况下，macOS 只告诉 Flowlight 每个应用连接的 IP 地址。要显示真实的主机名，Flowlight 会从网络数据包里读两样东西：DNS 应答， 以及客户端建立 HTTPS 连接时请求的服务器名（TLS SNI）。内核里的过滤器会在 Flowlight 看到之前丢掉其他所有数据包，数据包内容从不保存。

macOS 只允许管理员读取数据包，所以给流量配上名字窗口会请你输入一次密码。它会安装 /Library/LaunchDaemons/com.flowlight.bpf-access.plist，在每次开机时让 access_bpf 组获得对 /dev/bpf* 的读取权限，和 Wireshark 的做法一样。你随时可以在捕获 › 移除数据包捕获访问权限里移除它。

识别网络所有者会用运营该地址的机构来标注没有主机名的流量 （Cloudflare, Inc. · AS13335）。它默认开启，只会把这些公网 IP 地址（绝不包括私有地址）发送到 Team Cymru 的 DNS 服务。在捕获里可以关掉。

语言

Flowlight 已翻译成 English、简体中文、繁體中文、日本語、한국어、Français、Deutsch、Italiano、Español 和 Português。默认跟随你的 Mac：如果你的偏好语言里有 Flowlight 支持的语言，用的就是它——中文还会按文字和地区区分简体与繁体， 所以设成 zh-TW 的 Mac 会得到繁体。尚未翻译的语言会回退为英文。

在设置 ⌘,的“通用”里可以明确指定语言。它会立即生效，不必等下次启动。当选择是跟随系统时， 该行下方会说明最终用的是哪种语言。

翻译正在逐屏推进：导航、设置和常用控件已经完成，较长的说明文字目前还是英文——没有翻译的键会显示正确的英文， 而不是空白或标识符。

AI 代理规则

一个应用被算作代理，要么是 Flowlight 按名字认得它（目前 16 个，包括 Claude Code、Codex、Cursor、GitHub Copilot、 Gemini CLI、Ollama 和 ZCode），要么是它调用了 27 家 LLM API 提供方之一。浏览器不计入。

规则代理出现以下情况时触发……默认值
敏感通道使用邮件、文件传输、SSH 或远程桌面、隧道或代理、点对点，或数据库连接开启。邮件、文件传输、隧道和 P2P 为严重级别
可能的数据外泄在一小时内向并非 AI 提供方的主机上传100 MB/小时
无名主机通过不常见的端口连接到没有主机名的裸 IP开启
你离开时仍在活动在你不再使用键盘和鼠标之后，一分钟内传输 1 MB 或更多15 分钟

代理有 1 小时学习期，之后才开始发新目标警报。这些都可以在设置 › 检测里更改。

工具与 MCP 服务器

代理的许多工作是通过其他进程完成的：shell 工具会运行 curl、git 或 npm，MCP 服务器则作为独立进程运行。Flowlight 会沿着每个进程的父进程追回启动它的代理，于是那些流量都算作该代理的。在AI 代理里， 代理详情会把它们列在工具与 MCP 服务器下，目标则显示为经由 curl 或经由 github MCP。在报告里，进程那一行显示经由 Claude Code。

MCP 服务器的名字来自把它们的命令行与各家 MCP 配置比对：Claude Code（~/.claude.json）、Claude Desktop、 Cursor（~/.cursor/mcp.json）、Windsurf、VS Code、Codex（~/.codex/config.toml）、Zed 和 Gemini CLI。远程 MCP 服务器 按其 URL 里的主机名匹配，未配置的服务器则按可识别的包名匹配，例如 @modelcontextprotocol/server-github。

归属是按进程的：Flowlight 无法分辨长期运行的 MCP 服务器里究竟是哪一次工具调用开了连接。

代理配置：Flowlight 在你的 Mac 上读取什么

代理的能力都写在文件里：它能加载的技能、它定义的子代理和斜杠命令、在事件发生时运行 shell 命令的 钩子、它获得的权限规则，以及它启动的 MCP 服务器。Flowlight 会读取这些文件，于是工具标签页在代理还没发出一个请求之前，就能显示它被配置成做什么。 一个向 webhook 投递内容的钩子，或者一条允许 Bash(curl:*) 的规则，能解释那些否则只能靠猜的流量。

  • 它默认看哪里：你个人文件夹里的代理文件夹——~/.claude、~/.codex、 ~/.cursor、~/.gemini、~/.agents 之类。它不会遍历你的整个个人文件夹，所以 macOS 不必为“桌面”、“文档”或“下载”请求访问权限。
  • 你的项目：用添加项目文件夹…把 Flowlight 指向你代码所在的位置。macOS 随后只授予 对那个文件夹的访问权限。如果这个文件夹位于“文档”或“桌面”里，macOS 会先询问，而这就是你会看到的唯一一次提示。
  • 只扫一次，不会一直扫：结果会被记住。只有你点重新扫描时 Flowlight 才会重扫；过一两周它会提议扫一次， 以防你新增了代理或项目。后台不会进行任何扫描。
  • 它保留什么：名称、说明、钩子运行的命令，以及 MCP 服务器的命令或 URL。它绝不拷贝你的 代码、你的提示词或你的文件，这些内容也都不会离开你的 Mac。忘记已发现的内容可以清除它们。

值得一看

报告里的第三种模式，与明细和图表并列。它把报告中的各个应用互相比较， 指出那些目标看起来和其他应用不太一样的：去的地方比同类多得多、从未解析出名称的地址、看起来是生成而不是人取的主机名、发出的远多于接收的， 以及那些属于副业而非该应用本职的协议。每条发现都带着背后的证据，点一下就把报告收窄到那个 应用。

它被叫作值得一看而不是可疑，这是有意的。数据能支持的说法是“和这份报告里的其他 应用相比不寻常”——备份工具去很多地方是有正当理由的，而一台安静的 Mac 根本不会产出任何发现。 对每个应用都有的那类流量，它什么也不说。

字节是从哪条出口离开的

并不是所有流量都通往互联网。AirDrop、接力、隔空播放、随航和通用控制都是经 Apple Wireless Direct Link 直接送到同一个房间里的 设备——不经路由器、不经互联网，也没有别人能访问的地址。这些流 Flowlight 一直都在统计；只是没有一个词来称呼它们， 于是一次 4 GB 文件夹的 AirDrop，看上去就像是发往一个没有名字的地址的几兆字节。

现在每条流都带着一条出口：网络、点对点 Wi-Fi、本机（回环， 从未离开这台机器）或隧道（在 VPN 内部；它之后去了哪里在这里看不到）。在报告工具栏里可以把报告限定到 其中之一，这个标记也会随 CSV 导出、以及发送给收集器的数据一起带走。

点对点的行以打开它们的功能命名——AirDrop and Handoff · nearby device、 Continuity · nearby device——因为链路本地地址什么都说明不了，而房间里那台设备没有这台 Mac 能学到的 名字。直接使用无线电的应用保留自己的名字，对它来说这才是真实的答案。

两个引擎的回答方式不同。采样器读取每个套接字绑定的网络接口 （awdl0、llw0），这是精确的。网络扩展拿到的是套接字而不是接口，所以它改为按地址 判断：链路本地地址正是点对点流量的寻址方式。这是两者中较粗的一种—— 通过以太网访问的打印机也可能这样寻址——Flowlight 宁愿把这一点说出来，也不愿含糊过去。

这里没有任何新记录的内容，也不涉及新的权限。还是同一份捕获，只是终于有了标签。

其他警报

  • 流量突增：某一小时比该应用的滚动基线高出至少 3σ（需有 24 小时历史，且高于 1 MB）。
  • 一天之内对比该应用的基线出现异常数量的目标。
  • 上传超过第 99 百分位：对比该应用 30 天内每小时的上传量。
  • 首次连接新域名，以及非标准端口，都在各应用 24 小时学习期之后开始。
  • 无界面操作时的流量：一个有窗口的应用，你已有 10 分钟没用它，却每分钟上传超过 5 MB。

默认忽略 Apple 自带应用。macOS 会不断与 Apple 通信——软件更新、iCloud、 推送、时间、地图瓦片——用的主机和端口在第一次出现时都是新的，把这些全列出来只会把唯一值得读的 那一行埋掉。想要它们的话，在设置 › 警报里关掉这一项。无论如何，这些流量仍然被 记录，仍然出现在实时、报告和提问里，也仍然受每一条规则、护栏和允许列表约束：这项设置 决定列出什么，绝不决定允许什么。

提问

用日常语言提问——Claude Code 昨天上传了什么？、这周哪个应用开始联系新地方了？、 总结最近一小时——然后从这台 Mac 上记录的历史里得到答案。

模型永远拿不到你的历史。它拿到的只是一份可调用的七个只读查询的清单，别无其他： 总量、排名靠前的应用、排名靠前的目标、新目标、警报、代理，以及随时间变化的序列。没有接受 SQL 的 查询，将来也不会有——能自己写查询的模型就能读到任何东西。模型指名哪一个，Flowlight 就在本地执行哪一个， 再把总数和名称交回去。真正离开这台 Mac 的（如果有的话）是你的问题和这些数字——绝不是数据库。

本地优先。只要 macOS 提供设备端模型，它就是默认选项：不花钱、离线可用， 而且一个字节都不往外发。否则，你已经在运行的模型服务器——Ollama、LM Studio、llama.cpp—— 也一样。两者都排在托管选项之上，因为一个以不需要账户、不上云为承诺的工具， 不该为了回答关于自己的问题而需要其中任何一样。

也可以自带密钥，用于 Anthropic、OpenAI、Gemini 或任何兼容 OpenAI 的端点。密钥保存在 你的登录钥匙串里，而不是 Flowlight 的偏好设置里。当某个提供方会把内容发出这台 Mac 时，界面会在你提问之前 就说明这一点，而且每个请求都会完整显示在答案下方。

它也回答关于 Flowlight 本身的问题。怎么开启 HTTPS 检查？、 怎么阻止代理使用它的 shell 工具？、为什么我看不到任何流量？——这些答案出自 应用自带的、逐个功能写下来的说明，以及这台 Mac 当前设置情况的快照。绝不出自 模型的记忆：菜单路径在不同版本间会变，编造一条比不回答更糟。当答案需要改动某个 开关时，它会说出开关在哪里，并提议打开那个界面——点不点由你。

形状要紧时就上图。随时间的变化以折线呈现，比较以柱状呈现，整体的 拆分以饼图呈现。Flowlight 用查询返回的同一批数据来绘制，所以图和文字不可能互相矛盾， 模型也可以要求换一种形状，或者干脆不要图。

每一条查询都列在答案下方，点一下就在报告里打开那些数据。无法核对的答案， 只是语法更好的猜测。

Flowlight 对自己也用同一把尺子。这个功能发出的任何流量都会像别的应用的流量一样 出现在实时和报告里——包括模型服务器就在这台 Mac 上的情况，而那恰恰是最容易被悄悄 省掉的一种。

HTTPS 检查（可选）

默认关闭。在检查里打开后，Flowlight 会在 127.0.0.1:8877 上运行一个本地代理，并使用在你 Mac 上创建的 专属证书颁发机构。对于你交给它转发的应用，它会解密 HTTPS 并显示每个请求和响应： 标头、正文、状态和耗时。它会从 AI 代理的模型响应里读出模型请求的每一次工具调用 （Anthropic、OpenAI 的 Chat 与 Responses、Gemini，以及 MCP 的 tools/call 请求）以及代理送回的结果，并 把工具发出的每个请求链接回引发它的那次调用：curl 向 paste.example 的请求会显示 ← Bash: curl -s https://paste.example/up。在AI 代理里，代理详情会多出工具调用 （每次调用及其命令、结果或错误，以及它发出的请求）、MCP 服务器（名称与版本，本地、 远程或经由提供方，它提供的工具、调用次数和失败次数）和工具（代理向 模型声明的每个工具，以及各自被用了多少次）。代理的标题行显示模型、调用次数和消耗的 token，包括 命中缓存的部分。正文以可折叠的 JSON 树按原始键序打开；事件流则逐个事件显示。

代理每一轮都会声明自己的工具，所以一个被检查的请求显示的不止是调用本身：还有代理提供的工具、 由提供方在自己服务器上运行的那些（网页搜索、代码执行），以及提供方替代理连接的 MCP 服务器 （Anthropic 的 mcp_servers、OpenAI 的 mcp 工具），连同它们的 URL、令牌、审批设置和允许的工具。最后 这一类永远不会出现在你的网络上，因为那些连接是提供方发起的，不是你的 Mac。

设置只需一个开关。在检查里开启 HTTPS 检查，Flowlight 就会创建它的证书、 请你输入一次密码、信任该证书，并把应用经由代理转发。把开关关掉会撤销全部这些。代理 配置文件在 Flowlight 未运行时会回退为直连，所以退出它绝不会切断你的 Mac。

命令行代理会忽略系统代理设置，所以对 Claude Code、Codex、Gemini CLI 或 Aider，请用打开受检查的终端 并在那里启动它们。在高级里，你可以只解密 AI 代理而不是所有应用、编辑从不解密列表、拷贝 某个 shell 的配置，或者移除证书和所有已记录的内容。

Flowlight 会把内置的 Apple 服务和密码管理器名单排除在解密之外（在“设置”里可以编辑这份列表）。固定证书的应用可能会拒绝 Flowlight 的证书；Flowlight 会发现并让它们以加密方式直接通过。API 密钥、cookie 以及其他凭据标头从不 保存，记录的请求保留 3 天，移除证书与记录的数据会删除证书、它的信任 设置以及所有已记录的内容。检查仅支持 HTTP/1.1（Flowlight 会向双方请求它），且在演示模式下不可用。

模拟响应

想看看某个 API 失败、卡住或返回奇怪内容时代理会怎么应对，那就自己来响应那个端点。在 检查 › 模拟响应里，一条规则指明主机、路径和方法，并给出用来回复的状态码、标头、正文和 可选的延迟。请求绝不会发出：由 Flowlight 来响应。

  • 主机是精确匹配的——api.example.com——或者用 *.example.com 覆盖某个域名及其 子域名。默认精确匹配，因为针对一个端点的模拟不该悄悄替整个域名作答。
  • 路径接受一个 * 通配符：/v1/*、/v1/*/items，或一个精确路径。 除非你的模式里含有查询字符串，否则查询字符串会被忽略。
  • 方法匹配一个动词，或任意方法。
  • 规则是有顺序的，第一条已启用且匹配的规则负责响应。每条都可以单独开关。

被模拟的交互会像其他交互一样被记录，并在列表里标为已模拟，详情面板会说明它是由 Flowlight 而不是该主机响应的，并指出是哪条规则。事后你总能分清哪些是真的。

有两点值得知道。只有 Flowlight 解密的流量才能被模拟，所以那个端点必须正经过 HTTPS 检查——针对某个主机的规则会让 Flowlight 解密该主机，即使你的范围只设为代理。另外，目标仍然会被 连接：模拟改变的是答案，而不是连接能否建立，所以“这个 API 返回 500”行得通，而“这个 API 完全不可达”不行。

规则

允许列表是某一个代理关于它可以去哪里的说法。规则是它的通用版本：它指明一个 对象——应用、代理、目标、URL，或其中两者的组合——并决定阻止 还是允许。在实时、报告、AI 代理或检查里右键任意一行，就能针对你正看着的东西写一条； 它们全都落在规则界面上的同一个编辑器里，因为一条在看不见的地方生效的规则， 会是一条你再也找不到的规则。

模板。共 22 个，分为五组——阻止代理访问软件包仓库或其他 模型提供方；封住数据外流的常见途径（粘贴站点、webhook 接收器、匿名文件投放、隧道、DNS over HTTPS）；产品分析与崩溃上报；工作时段策略；以及一次性的“先把这个拦一小时，我弄清它 是什么”。可以从规则工具栏浏览它们，也可以在实时、报告、AI 代理或检查的任意一行上右键， 把某个模板应用到你正看着的东西上。

每个模板在动手之前都会说明它要做什么。凡是会写入多条规则的，都会打开一张卡片，列出每个 主机和时段；凡是永久生效的，都会打开预填好的编辑器；而只有会自行撤销的规则——一 小时，或本次 Flowlight 运行期间——才会不经展示直接应用。每个模板也都带着自己的注意事项，包括它需要哪个 引擎：只在 HTTPS 检查下有效的模板会明说。

哪条规则胜出。由最具体的匹配决定；两条规则同样具体时，站得住的是阻止那一条。 所以写在一条宽泛阻止之下的例外是有效的——Cursor may reach api.github.com 能在 nothing reaches github.com 之下存活——而比它所要豁免的范围更宽的例外，则不会悄悄把范围放大。

持续多久。永久；到某个时间；到 Flowlight 退出；或在选定日期的选定时段内。时段按 本地时间，并在连接建立的那一刻判定，所以一台睡过了时段结束的 Mac 醒来时会发现它已关闭， 而时钟或时区变化会让时段随之移动。时段关闭只会阻止新连接——它不会拆掉已经 建立的连接。此外还有一个全局的暂停阻止，因为正是这个应急出口让严格的规则 用得下去。

解除阻止是阻止的一部分。每次拒绝都带着它的出口：在警报里允许一次、允许一小时， 或允许到 Flowlight 退出。这几种本身也都是带有效期的规则，所以列表总能回答这个为什么 放行了？——包括两周前你顺手点过的那次放宽。

规则在哪里起作用，在哪里不行。网络扩展拒绝的是整条连接：它知道主机、 地址和端口，对路径一无所知，而且只在扩展模式下有效。HTTPS 检查拒绝的是单个请求，所以它能匹配 URL，并用代理读得懂的状态码作答，而不是一个不声不响就断掉的套接字。nettop 采样器 完全无法拒绝任何东西。当前配置无法执行的规则会在列表里明说，而不是摆在那里装作已经生效。

第二个标签页是违规流水：每一条由规则判定的连接，带上应用、它要去哪里、是哪条 规则判定的，以及那究竟是一次拒绝，还是一次放它通过的例外。

允许列表

在AI 代理里选中一个代理，用它详情里的允许列表指定它可以连接哪里。输入域名 （含子域名）、IP 地址或 CIDR 地址段，或者选一个预设：GitHub、npm、PyPI、Homebrew、Docker Hub、Rust crates、Go modules 或 Apple。该代理的 AI 提供方（除非你关掉这一项）和你的本地网络始终被允许。

从此以后，代理或它的工具联系任何未列出的目标，都会触发一条严重级别的违反允许列表警报 （每个域名每 6 小时一次），并被标为不允许，旁边有一个允许按钮可以把它加进去。允许列表默认只警告， 不拒绝连接；阻止需要网络扩展引擎，已列入路线图。

拒绝连接

允许列表默认只警告。为某个代理打开拒绝列表之外的连接，它就会真的 拒绝：连接被丢弃，并有一条警报记录下被拒绝的内容，带从现在起允许……一键把它加入 列表。代理的下一次尝试就会通过。

它需要网络扩展。拒绝一条连接意味着站在它的路径上，而 nettop 采样器 做不到——捕获界面会明说这一点，而不是给你一个什么都不做的开关。

有些东西无论列表怎么写都绝不会被拒绝：你的本地网络、DNS、Apple 自家的服务，以及 Flowlight 自己的 流量。一台被封住的 Mac 比一个被封住的代理更糟，所以有疑问时，连接会被允许并记录下来。 Flowlight 停止运行几秒之后，强制执行也会失效——没人能看见的拒绝比没有拒绝更糟，而撤销它的 办法就在应用里。

HTTPS 检查和阻止不能并用：经由 Flowlight 代理转发的流量是以 Flowlight 自己的名义发出的，而它 永远不会被拒绝。

代理护栏：阻止一个工具、一个服务器或一个资源

这个代理可以用哪些工具和它可以访问哪些主机是两个不同的问题，所以它有自己的 区域：AI 代理里每个代理旁边的护栏标签页，对它声明的每个工具和它访问的每个 MCP 服务器都有一个开关，还有几个值得一用的预设（只读、禁用 shell、禁止写入），以及一份被拿掉了什么的 记录。

最有力的杠杆是声明本身。代理在每一轮都会重新发送完整的工具列表。Flowlight 会在请求 离开之前，把被拒绝的工具从那个列表里移除，于是模型根本看不到它：没有需要争辩的拒绝，也没有重试 循环。对代理自己运行的工具和藏在远程 MCP 服务器后面的工具，做法是一样的；它读取的也正是 Flowlight 已经会解析的 Anthropic、OpenAI 和 Gemini 的那些结构。

被拒绝的调用会得到体面的答复。对于通过 HTTP 访问的 MCP 服务器，被阻止的 tools/call 会作为一个 result 返回，其中带着 isError: true 和一句平实的说明，因为协议规定失败的工具 就是这个样子——模型读到它就会绕开，而传输层错误在它看来会像是服务器坏了。 resources/read 和 prompts/get 没有这样的结构，所以它们得到的是一个 JSON-RPC 错误。

连接器是被收窄，而不是被拦截。当提供方代表代理去访问某个 MCP 服务器时，那段 流量根本不会碰到这台 Mac。唯一的杠杆是设置它的那个请求，所以 Flowlight 会收窄这个连接器 允许调用的工具，或者干脆把连接器整个去掉。

本地 stdio 服务器通过管道通信，任何代理都看不到这一点。Flowlight 在那里能做的，是观察 服务器进程自身的网络流量（它本来就已归属于启动它的代理），并把拒绝清单交给你，让你 粘贴到代理自己的设置里——Claude Code 在 permissions.deny 里接受 mcp__server__tool，它的 同类们也有对应写法。那要等代理重启后才生效。

护栏需要 HTTPS 检查，因为工具列表在请求正文里。检查关闭时，这个 标签页会明说，而不是看起来像在工作。

这不是沙盒。被拒绝的工具不再提供给模型，也不再被响应。而仍然拥有 shell 的代理，可以手动做到那个工具本来要做的事。Flowlight 会把它记录下来；它不会假装能阻止。

捕获：引擎与来源

Flowlight 用两种方式之一记录流量，在捕获里选择。它们会漏掉的东西不同，在依赖任何 一种之前，值得先了解清楚。

nettop 采样器（默认）网络扩展
需要什么都不需要安装一个系统扩展，以及你的批准
它如何看到流量每秒读取一次累计总数，并记录差值每建立一条连接，macOS 就调用它一次
长时间传输精确计数，无论多么突发会计入
短连接可能被整条漏掉无论多短都会记录
能耗每秒启动一个进程更低——无需轮询

采样器漏掉的是整条连接，而不是字节。因为它比较的是累计总数，所以任何跨越两次 读取的传输都不会丢，中间来了多少都一样。永远不会出现的，是那些在两次读取之间开始并且 结束的东西——一次很快的 DNS 查询、一次迅速的 API 调用、一个运行 curl 然后退出的脚本。要盯住一个 发出大量短请求的代理，这个差别很要紧。

扩展则处在数据路径上，所以一个只持续五毫秒的请求也会像其他请求一样被记录。它也不是万能的： 你启用它之前的流量并不在其中，部分系统流量豁免于内容过滤器，而它的字节计数 来自过滤器自己的统计，而不是逐包计数。它只在你写下的规则或 允许列表要求时才拒绝连接。

当扩展不再响应时。macOS 运行的是最后一次被激活的那个扩展构建版本，所以 应用更新之后，两者可能互相不一致——一旦不一致，macOS 就会拒绝它们之间的连接。系统设置说 过滤器已启用，Flowlight 说连接已失效，而双方都不改主意。Flowlight 现在会自己爬出 这个坑：它会重试几次，然后询问 macOS 正在运行哪个构建版本，如果不是本应用的就重新安装扩展； 如果这些都不行，它就用 nettop 采样器捕获，好让数据不至于中断——同时把情况直说， 并且不改动你选择的来源。网络扩展下的重试网络扩展会重新来一遍。

它在某些 Mac 上也完全跑不起来。macOS 一次只允许一个内容过滤器，而企业安全软件 通常占着它——Palo Alto Networks GlobalProtect、CrowdStrike Falcon 之类。Flowlight 的过滤器在那些 机器上能安装、也能连接，然后永远不会被交给任何一条连接。捕获会列出它找到的这类软件，并提议把你切回采样器，后者 不需要过滤器，可以和它们并存。 关于它是如何构建的，见开发者指南。

设备：蓝牙、USB 与外置存储

一台 Mac 收发数据的途径不止 TCP 和 UDP。设备界面负责其余部分，而且在你打开之前 它一直关闭——不是因为它需要 Flowlight 尚未拥有的权限，而是因为监视你 Mac 的更多部分 应当由你决定，而不是某次更新替你决定。

蓝牙显示哪些设备已配对、哪些已连接，以及这些什么时候变的，每半分钟从系统 读取一次。旁边是为使用蓝牙而构建的应用列表，取自各应用自己的 Info.plist。

它给不出什么，也会直说。这里没有字节计数。macOS 不为蓝牙记录按应用的 用量，而能给出字节级数据的 HCI 追踪需要 Apple 的 PacketLogger 配置文件，普通应用 读不到它。同样，应用列表说的是谁申请了蓝牙，而不是谁获得了授权：macOS 把授权放在 应用打不开的数据库里，而 Flowlight 宁愿把这个区别讲清楚，也不愿把它糊过去。

USB 与外置存储列出接入了什么——它是什么、谁制造的、驱动器的容量——并 记录每一台什么时候接入、什么时候离开。两半是有意用不同方式工作的：USB 设备是定期从系统 读取的，而卷则在挂载或弹出的那一刻来自工作区，因为驱动器出现才是人们真正在意的 事件。这里同样没有吞吐量，原因和蓝牙那边一样。

聚焦模式

挑几个应用和目标，所有界面就只显示它们——实时、报告、警报、AI 代理和检查，以及菜单栏里的 速率。它适合在不受这台 Mac 其余部分干扰的情况下，看一个代理干活。

  • 在实时、报告或 AI 代理里右键任意一行并选择聚焦于…，或者用边栏底部的聚焦控件， 从活动过的应用里挑选，并手动输入目标。
  • ⇧⌘F 可以开关聚焦，菜单栏也可以，它还会显示当前聚焦的内容。
  • 目标会连带它的子域名：example.com 覆盖 api.example.com。IP 地址可以用； 10.0.0.0/8 这样的地址段不行。
  • 应用和目标是并集，不是交集：同时聚焦 Claude Code 和 github.com，会显示 Claude Code 做的一切，外加所有与 GitHub 通信的流量。

一个应用和一个目标同样都算一个聚焦，单独任一个就够了。输入名称或 Bundle ID 来添加应用—— 这台 Mac 上的每个应用都能搜到，所以一个一整天都很安静的应用也可以被聚焦，没有应用包的命令行代理 也一样——或者从最近繁忙的列表里勾选一个。添加目标也是同样的方式。

有一件事目标收窄不了：警报记录的是触发它的应用，对流量去了哪里一无所知，所以只由 目标构成的聚焦不会影响警报列表。编辑器会明说这一点，而不是让某个界面悄悄忽略它。

聚焦筛选的是你看到的内容，从不影响记录下来的内容。开启期间 Flowlight 会继续捕获并存储一切， 异常基线也会继续从全部数据中学习，所以关掉聚焦就会显示它藏起来的流量。一个后果是：警报 指明的是触发它的应用，而不是流量去了哪里，所以只聚焦目标会让警报列表保持原样。

在后台运行

Flowlight 关着窗口也继续记录，而且空闲时几乎不耗资源——它不会去画没人在看的 图表。设置 › 通用 › 在后台运行更进一步，去掉程序坞图标和 Cmd-Tab 条目； 菜单栏保留实时速率，并多出显示程序坞图标来撤销它。登录时启动也在 同一处。

窗口会在你上次离开的位置、以上次的尺寸打开。首次运行则铺满屏幕，这样就不会有内容被藏在 一个小小的默认窗口后面；而保存的位置落在屏幕之外的窗口——比如拔掉的外接显示器——会回到你 现有的屏幕上。主机名设置会在启动后稍晚、且只在有窗口打开时才提出，而不是一上来就向首次运行的你 索要密码；在你接受或忽略它之前，这个提议下次启动还会出现。

退出 Flowlight 会停止采样器，但不会停止网络扩展：系统扩展独立运行，所以过滤器 会继续检查连接，直到你在捕获里停用或卸载它。

导出到 OpenTelemetry 或 SIEM

在你配置之前一直关闭，而且没有什么 Flowlight 服务可供发送。端点由你指定——你自己的 收集器、你自己的 SIEM——在那之前什么都不会发出。设置 › 导出。

  • 基于 HTTP 的 OTLP，正文为 JSON：汇总数据发往 /v1/metrics，警报发往 /v1/logs， 因为一条警报是带着一句话的事件，而指标会把那句话丢掉。对只想要按行读取的收集器，也提供换行分隔的 JSON。
  • 究竟有什么发出去，面板里逐字段列出，而预览会在发送任何东西之前，用你自己的数据 构建一份真实的载荷给你看。
  • 绝不包含来自 HTTPS 检查的任何内容。没有标头、没有正文、没有工具调用——导出只能携带 汇总数据和警报，所以它们连误发的去处都没有。
  • 认证标头保存在你的登录钥匙串里，而不是偏好设置里。显示出来的永远只有它们的名称。
  • Flowlight 发出的内容会出现在 Flowlight 里，在实时和报告中，和别的应用的流量一样——包括 位于 127.0.0.1 的收集器。

有两件事要预料到：汇总数据大约滞后两分钟才折叠，所以把间隔设成小于一分钟只会更频繁地轮询，而数据 并不会更早到达；还有测试连接只能证明端点有响应，不能证明它校验通过了你的凭据—— “上次成功导出”那一行才是诚实的信号。

你的数据

所有内容都放在 ~/Library/Application Support/Flowlight/traffic.sqlite。每秒数据保留 6 小时 （可调），分钟数据 14 天，小时数据 400 天，每日数据无限期保留，警报 90 天。 捕获 › 清除所有数据会删除它们。

更新

有新版本时，Flowlight 会用一条通知和边栏里的标记告诉你，而不是打断你正在做的 事；点击其中任一个都会打开更新窗口。你自己发起的检查会直接打开它。

Flowlight 在启动时以及每天一次向 GitHub 检查新版本，检查更新…在应用菜单 和菜单栏菜单里都有。下载会把磁盘映像取到“下载”文件夹，并用该版本公布的 SHA-256 校验它。在你作出选择之前， 不会安装任何东西：退出并安装会关闭 Flowlight、用新版本替换它并重新打开，保留你的历史和 设置。以后安装让你继续手上的事。如果 Flowlight 是用 .pkg 安装的，macOS 会要求输入管理员 密码来替换它。可以在设置 › 通用里关掉这项检查。

想手动更新？先退出 Flowlight（菜单栏图标 › 退出），然后把新版本拖进“应用程序”。Finder 无法替换 仍在运行的应用，会提示该项目正在使用中。

演示模式

open /Applications/Flowlight.app --args -FLDemo YES 会在一个独立的数据库里，以 90 天的合成流量 启动 Flowlight，这样你可以随意逛逛而不必记录自己的数据。本站的截图就是这么来的。

卸载

  1. 在捕获里，如果你启用过，就选择移除数据包捕获访问权限（会要求输入密码）； 如果你安装过内容过滤器，就把它卸载；并在检查里关闭 HTTPS 检查，让它的证书 离开你的钥匙串。只有 Flowlight 自己能撤销这三样。
  2. 退出 Flowlight，并把它从“应用程序”移到废纸篓——或者，如果你是用 Homebrew 安装的，执行 brew uninstall --cask flowlight。
  3. 删除 ~/Library/Application Support/Flowlight 以移除记录下来的历史，或者让 Homebrew 用 brew uninstall --zap --cask flowlight 来做。

问题与解答

macOS 为什么向 Flowlight 请求访问我的“桌面”或“文档”？
只因为你把它指向了其中某个里面的项目文件夹。默认情况下，Flowlight 从你个人文件夹里的代理文件夹读取代理配置， 绝不碰这三个位置。
Flowlight 会看到我所有的流量，还是会漏掉一些？
这取决于你用哪个捕获引擎，而差别并不细微。默认的采样器每秒读取一次 macOS 的累计 字节计数器并记录变化量，所以一次长传输会被精确计数——但在两次读取之间打开又 关闭的连接根本不会出现。网络扩展在每条连接建立时由 macOS 调用，所以 哪怕是五毫秒的请求也会被记录。如果你要盯的是一个发出大量短请求的 AI 代理，请在捕获里 安装扩展。上文有完整对比。
我打开了网络扩展，却什么都没出现。采样器倒是正常。
几乎总是因为另一个内容过滤器已经占了那个位置。macOS 一次只运行一个内容过滤器，而 企业安全软件通常会占用它——Palo Alto Networks GlobalProtect、CrowdStrike Falcon 之类。Flowlight 的 过滤器仍然会安装、激活并连接，所以捕获界面会说已连接到过滤器扩展，但 macOS 从不交给它 任何一条连接，界面也就一直空着。捕获会列出它找到的过滤器，并提议把你切回 采样器，后者不使用过滤器，可以和它们并存。你只会失去那些极短的连接 （见对比），其余一切照旧记录。
Flowlight 更新之后，扩展就不工作了。
0.2.5 之前的版本有这个问题：macOS 会一直运行最后一次被激活的那个扩展构建版本，所以更新之后 扩展还是旧版本，而 macOS 会拒绝这对不匹配的组件之间的连接。从 0.2.5 起，Flowlight 会在启动时检查， 并自行重新激活过滤器。如果用的是更旧的版本，在捕获里按一次安装并启用过滤器。
捕获还有别的问题，我不知道是什么。
运行下面这条命令，读一读它打印的内容——它只报告状态和计数，绝不包含 Flowlight 记录的任何流量内容：

curl -fsSL https://raw.githubusercontent.com/xinbetween/flowlight/main/scripts/diagnose.sh | zsh

它会显示安装了哪些扩展、macOS 是否真的启动了 Flowlight 的过滤器，以及最近一次记录是什么时候。 把它粘贴到一个 issue 里。
Flowlight 会把关于我的任何信息发到什么地方吗？
不会。没有账号，没有遥测，也没有分析。它发出的请求只有每日更新检查、可选的网络所有者 查询，以及反向 DNS——每一项都列在隐私页面上，并且每一项都有开关可以关掉。
它会让我的 Mac 变慢，或者更耗电吗？
窗口关闭时 Flowlight 几乎什么都不做：它保留菜单栏速率，每秒写入一行。网络扩展 比作为后备的采样器更省，后者每秒都要启动一个短命的 nettop 进程。
它能阻止连接吗？
能，配合网络扩展。代理的允许列表除了警告也可以拒绝，一条规则可以按你指定的时长阻止一个应用、 一个目标或一个 URL，而一条护栏可以在模型看到某个工具之前，把它从代理手里 拿走。在你要求之前不会阻止任何东西，而且每次拒绝都带着它的出口。
我需要网络扩展吗？
不需要。采样器不需要任何授权，覆盖大多数流量。扩展额外带来短于一秒的流、按代码 签名的归属、无需数据包捕获设置的主机名，而且它是唯一能拒绝连接的引擎。
如果我卸载了，我的数据会怎样？
所有内容都在 ~/Library/Application Support/Flowlight 里。删掉那个文件夹就没了；数据包捕获助手和检查证书 见卸载。

限制

  • 只支持 TCP 和 UDP。ICMP（ping）和其他裸 IP 协议不作归属。
  • 归属是按进程的，不是按线程。
  • 除非你打开 HTTPS 检查，Flowlight 只读取元数据，绝不解密流量。QUIC 的服务器名来自 DNS， 而不是加密的握手。
  • 检查只能看到使用代理的应用，永远看不到固定证书的应用。
  • 主机名捕获跟随主网络接口。
