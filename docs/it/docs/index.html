Installazione

  1. Con Homebrew: lo stesso comando lo aggiorna anche in seguito.

    brew install --cask xinbetween/tap/flowlight

  2. Oppure scarica Flowlight.dmg, aprilo e trascina Flowlight in Applicazioni.
  3. Preferisci un installer? Ogni versione include anche un .pkg.
  4. Per compilare dal codice sorgente servono Xcode 16 o successivo e xcodegen:
brew install xcodegen
git clone https://github.com/xinbetween/flowlight.git && cd flowlight
xcodegen generate && scripts/build-local.sh
open build/Build/Products/Release/Flowlight.app

Primo avvio

Le versioni dalla 0.1.6 sono firmate con un certificato Developer ID e autenticate da Apple, quindi il primo avvio funziona subito. Puoi verificarlo da te: spctl -a -vvv /Applications/Flowlight.app deve rispondere Notarized Developer ID. Le versioni fino alla 0.1.5 non erano firmate: per quelle serve una volta Impostazioni di Sistema › Privacy e sicurezza › Apri comunque.

Il traffico inizia a comparire entro un secondo. I valori ↓↑ nella barra dei menu sono le velocità di download e upload in diretta.

Nomi host: la configurazione iniziale

Per impostazione predefinita macOS comunica a Flowlight solo l'indirizzo IP con cui parla ogni app. Per mostrare i nomi host reali, Flowlight legge due cose dai pacchetti di rete: le risposte DNS e il nome del server che un client richiede quando apre una connessione HTTPS (SNI di TLS). Un filtro nel kernel scarta ogni altro pacchetto prima che Flowlight lo veda, e il contenuto dei pacchetti non viene mai memorizzato.

macOS permette di leggere i pacchetti solo agli amministratori, quindi la finestra Dai un nome al traffico chiede una volta la tua password. Installa /Library/LaunchDaemons/com.flowlight.bpf-access.plist, che a ogni avvio dà al gruppo access_bpf l'accesso in lettura a /dev/bpf*, lo stesso approccio usato da Wireshark. Puoi rimuoverlo quando vuoi da Acquisizione › Revoca l'accesso all'acquisizione dei pacchetti.

Identifica i proprietari della rete etichetta il traffico senza nome host con chi gestisce l'indirizzo (Cloudflare, Inc. · AS13335). È attivo per impostazione predefinita e invia quegli indirizzi IP pubblici (mai quelli privati) al servizio DNS di Team Cymru. Disattivalo in Acquisizione.

Lingua

Flowlight è tradotto in English, 简体中文, 繁體中文, 日本語, 한국어, Français, Deutsch, Italiano, Español e Português. Per impostazione predefinita segue il Mac: se tra le tue lingue preferite c'è una di quelle che Flowlight parla, userà quella — e per il cinese distingue il semplificato dal tradizionale in base a scrittura e regione, così un Mac impostato su zh-TW ottiene il tradizionale. Tutto ciò in cui non è stato tradotto torna all'inglese.

Scegli una lingua esplicitamente in Impostazioni ⌘, alla voce Generali. Cambia immediatamente, non al prossimo avvio. Quando la scelta è Sistema, sotto la riga compare quale lingua ne è risultata.

La traduzione arriva schermata per schermata: navigazione, impostazioni e i controlli comuni sono pronti, mentre i passaggi esplicativi più lunghi per ora sono ancora in inglese — una chiave senza traduzione mostra l'inglese corretto invece di uno spazio vuoto o di un identificatore.

Regole per gli agenti IA

Un'app conta come agente se Flowlight la conosce per nome (oggi 16, tra cui Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Ollama e ZCode) o se chiama uno dei 27 provider di API LLM. I browser sono esclusi.

Gli agenti hanno un periodo di apprendimento di 1 ora prima che scattino gli avvisi sulle nuove destinazioni. Puoi cambiare tutto questo in Impostazioni › Rilevamento.

Strumenti e server MCP

Gli agenti svolgono molto del loro lavoro tramite altri processi: uno strumento shell esegue curl, git o npm, e i server MCP girano come processi a sé. Flowlight risale la catena dei processi padre fino all'agente che li ha avviati, così quel traffico conta come traffico dell'agente. In Agenti IA, il dettaglio dell'agente li elenca sotto Strumenti e server MCP, e le destinazioni riportano via curl o via github MCP. In Rapporti, la riga del processo riporta via Claude Code.

I server MCP prendono il nome confrontando la loro riga di comando con la configurazione MCP di Claude Code (~/.claude.json), Claude Desktop, Cursor (~/.cursor/mcp.json), Windsurf, VS Code, Codex (~/.codex/config.toml), Zed e Gemini CLI. I server MCP remoti vengono riconosciuti dal nome host nel loro URL, e quelli non configurati da nomi di pacchetto riconoscibili come @modelcontextprotocol/server-github.

L'attribuzione è per processo: Flowlight non può sapere quale singola chiamata a uno strumento, dentro un server MCP di lunga durata, abbia aperto una connessione.

Configurazione degli agenti: cosa legge Flowlight sul tuo Mac

Le capacità di un agente sono scritte in file: le skill che può caricare, i subagent e i comandi slash che definisce, gli hook che eseguono comandi shell in risposta agli eventi, le regole di permesso che ha ricevuto e i server MCP che avvia. Flowlight legge quei file perché il pannello Strumenti possa mostrare cosa è configurato a fare ogni agente, ancora prima che faccia una sola richiesta. Un hook che invia dati a un webhook, o una regola che consente Bash(curl:*), spiega traffico che altrimenti dovresti indovinare.

  • Dove guarda per impostazione predefinita: le cartelle degli agenti nella tua cartella Inizio — ~/.claude, ~/.codex, ~/.cursor, ~/.gemini, ~/.agents e simili. Non percorre tutta la cartella Inizio, così macOS non deve chiedere l'accesso a Scrivania, Documenti o Download.
  • I tuoi progetti: usa Aggiungi cartella di progetto… per indicare a Flowlight dove si trova il tuo codice. macOS concede l'accesso solo a quella cartella. Se la cartella è dentro Documenti o Scrivania, macOS chiede prima il permesso, e quella è l'unica richiesta che vedrai.
  • Una volta, non continuamente: il risultato viene ricordato. Flowlight riesamina solo quando fai clic su Riesamina, e lo propone dopo un paio di settimane, nel caso in cui tu abbia aggiunto agenti o progetti. Nulla viene esaminato in background.
  • Cosa conserva: nomi, descrizioni, il comando che esegue un hook e i comandi o gli URL dei server MCP. Non copia mai il tuo codice, i tuoi prompt o i tuoi file, e nulla di tutto questo lascia il Mac. Dimentica ciò che è stato trovato lo cancella.

Vale un'occhiata

Una terza modalità in Rapporti, accanto alla ripartizione e ai grafici. Confronta tra loro le app presenti nel rapporto e indica quelle le cui destinazioni non assomigliano alle altre: molti più posti dei loro pari, indirizzi che non sono mai stati risolti in un nome, nomi host che sembrano generati anziché scelti, molto più inviato che ricevuto, e protocolli che sono un'attività collaterale anziché lo scopo dell'app. Ogni rilievo porta con sé le prove che lo sostengono, e facendo clic su uno il rapporto si limita a quell'app.

Si chiama Vale un'occhiata e non Sospetto, di proposito. Ciò che i dati sostengono è «insolito rispetto alle altre app di questo rapporto»: uno strumento di backup parla con molti posti per buone ragioni, e un Mac tranquillo non produce alcun rilievo. Non dice nulla sul traffico comune a tutte le app.

Da dove sono usciti i byte

Non tutto il traffico va su internet. AirDrop, Handoff, AirPlay, Sidecar e Controllo universale vanno direttamente a un dispositivo nella stanza tramite Apple Wireless Direct Link: nessun router, nessuna internet e nessun indirizzo raggiungibile da altri. Flowlight contava già quei flussi; non aveva una parola per definirli, così un AirDrop di una cartella da 4 GB sembrava qualche megabyte verso un indirizzo senza nome.

Ogni flusso ora porta un canale: Rete, Wi-Fi peer-to-peer, Questo Mac (loopback, che non ha mai lasciato la macchina) o Tunnel (dentro una VPN; dove sia andato dopo non è visibile qui). Limita un rapporto a uno di essi dalla barra strumenti di Rapporti; il canale viaggia con le esportazioni CSV e con tutto ciò che viene inviato a un collector.

Le righe peer-to-peer prendono il nome dalla funzione che le ha aperte — AirDrop and Handoff · nearby device, Continuity · nearby device — perché un indirizzo link-local non dice nulla e il dispositivo nella stanza non ha un nome che questo Mac possa apprendere. Un'app che usa la radio direttamente mantiene il proprio nome, che per lei è la risposta veritiera.

I due motori rispondono in modo diverso. Il campionatore legge l'interfaccia a cui è associato ogni socket (awdl0, llw0), ed è esatto. All'estensione di rete vengono passati i socket, non le interfacce, quindi giudica dall'indirizzo: un indirizzo link-local è il modo in cui viene indirizzato il traffico peer-to-peer. È il più approssimativo dei due — una stampante raggiunta via Ethernet può essere indirizzata allo stesso modo — e Flowlight preferisce dirlo piuttosto che arrotondare.

Nulla di tutto questo viene registrato ex novo, e non è coinvolto alcun nuovo permesso. È la stessa acquisizione, finalmente etichettata.

Altri avvisi

  • Picco di traffico: un'ora almeno 3σ sopra la linea di base mobile dell'app (dopo 24 ore di cronologia, sopra 1 MB).
  • Numero insolito di destinazioni in un giorno, rispetto alla linea di base dell'app.
  • Caricamento sopra il 99° percentile dei caricamenti orari dell'app negli ultimi 30 giorni.
  • Primo contatto con un nuovo dominio e porte non standard, dopo un periodo di apprendimento di 24 ore per app.
  • Traffico senza attività a schermo: un'app con finestra che non usi da 10 minuti carica più di 5 MB al minuto.

Le app di Apple sono escluse per impostazione predefinita. macOS comunica costantemente con Apple — Aggiornamento Software, iCloud, notifiche push, ora, riquadri di Mappe — su host e porte che la prima volta risultano nuovi, e segnalare tutto questo seppellisce l'unica riga che vale la pena leggere. Disattivalo in Impostazioni › Avvisi se li vuoi. In ogni caso il traffico viene comunque registrato, compare in In diretta, Rapporti e Chiedi, e resta soggetto a ogni regola, protezione ed elenco consentiti: l'impostazione decide cosa viene elencato, mai cosa viene consentito.

Chiedi

Chiedi in linguaggio naturale — cosa ha caricato Claude Code ieri?, quale app ha iniziato a parlare con un posto nuovo questa settimana?, riassumi l'ultima ora — e ottieni una risposta dalla cronologia registrata su questo Mac.

Il modello non riceve mai la tua cronologia. Gli viene consegnato un elenco di sette query di sola lettura che può richiamare e nient'altro: totali, app principali, destinazioni principali, nuove destinazioni, avvisi, agenti e una serie nel tempo. Non esiste una query che accetti SQL, e non ci sarà: un modello che può scrivere la propria query può leggere qualsiasi cosa. Flowlight esegue in locale quella che il modello indica e restituisce totali e nomi. Ciò che lascia il Mac, se qualcosa lo lascia, è la tua domanda e quei numeri — mai il database.

Prima il locale. Dove macOS mette a disposizione un modello sul dispositivo, quella è la scelta predefinita: non costa nulla, funziona offline e non invia un solo byte da nessuna parte. Altrimenti fa lo stesso un server di modelli che già gestisci — Ollama, LM Studio, llama.cpp. Entrambi sono elencati sopra le opzioni ospitate, perché uno strumento che promette nessun account e nessun cloud non dovrebbe aver bisogno né dell'uno né dell'altro per rispondere a una domanda su di sé.

Oppure porta la tua chiave per Anthropic, OpenAI, Gemini o qualsiasi endpoint compatibile con OpenAI. La chiave finisce nel portachiavi di accesso, non nelle preferenze di Flowlight. Quando un provider invia qualcosa fuori dal Mac, la schermata lo dice prima che tu chieda, e ogni richiesta è mostrata per intero sotto la risposta.

Risponde anche a domande su Flowlight stesso. Come attivo l'ispezione HTTPS?, come impedisco a un agente di usare il suo strumento shell?, perché non vedo traffico? — a queste risponde attingendo alla guida scritta dell'app su ogni funzione e a un'istantanea di come è configurato ora questo Mac. Mai dalla memoria del modello: i percorsi dei menu cambiano tra le versioni, e uno inventato è peggio di nessuna risposta. Quando la risposta richiede di cambiare un'impostazione, dice dov'è e propone di aprire quella schermata, che è un clic che fai tu.

Grafici quando conta la forma. Un andamento nel tempo torna come linea, un confronto come barre, la ripartizione di un intero come torta. Flowlight li disegna dalle stesse righe restituite dalla query, così immagine e frase non possono contraddirsi, e il modello può chiedere una forma diversa o nessuna.

Ogni query è elencata sotto la risposta, e facendo clic su una si aprono quelle righe in Rapporti. Una risposta che non puoi verificare è un'ipotesi con una grammatica migliore.

Flowlight applica a sé stesso il proprio standard. Tutto ciò che questa funzione invia compare in In diretta e Rapporti come il traffico di qualsiasi altra app — anche quando il server del modello è su questo stesso Mac, che è il caso che sarebbe stato più facile lasciar fuori in silenzio.

Ispezione HTTPS (opzionale)

Disattivata per impostazione predefinita. Quando la attivi in Ispeziona, Flowlight avvia un proxy locale su 127.0.0.1:8877 con una propria autorità di certificazione, creata sul tuo Mac. Per le app che instradi attraverso di esso decifra HTTPS e mostra ogni richiesta e risposta: intestazioni, corpi, stato e tempi. Dalle risposte del modello di un agente IA legge ogni chiamata a uno strumento richiesta dal modello (Anthropic, OpenAI Chat e Responses, Gemini e le richieste MCP tools/call) e il risultato che l'agente ha restituito, e collega ogni richiesta fatta da uno strumento alla chiamata che l'ha causata: la richiesta di curl a paste.example mostra ← Bash: curl -s https://paste.example/up. In Agenti IA, il dettaglio di un agente acquisisce Chiamate agli strumenti (ogni chiamata con il suo comando, il risultato o l'errore e le richieste che ha fatto), Server MCP (nome e versione, locale o remoto o via provider, gli strumenti che offre, chiamate ed errori) e Strumenti (ogni strumento che l'agente dichiara al modello, con la frequenza d'uso). La riga di intestazione dell'agente mostra il modello, il numero di chiamate e i token spesi, compresi quelli dalla cache. I corpi si aprono come albero JSON espandibile nell'ordine originale delle chiavi; i flussi di eventi mostrano un evento alla volta.

Gli agenti dichiarano i loro strumenti a ogni turno, quindi una richiesta ispezionata mostra più delle sole chiamate: gli strumenti che l'agente offre, quelli che il provider esegue sui propri server (ricerca web, esecuzione di codice) e i server MCP a cui il provider si collega per l'agente (mcp_servers di Anthropic, lo strumento mcp di OpenAI) con il loro URL, token, impostazione di approvazione e strumenti consentiti. Quest'ultimo gruppo non compare mai sulla tua rete, perché quelle connessioni le fa il provider, non il tuo Mac.

Configurarla è un solo interruttore. Attiva l'ispezione HTTPS in Ispeziona e Flowlight crea il suo certificato, chiede una volta la password, lo considera affidabile e instrada le app attraverso il proxy. Disattivando l'interruttore tutto torna come prima. Il file di configurazione del proxy ripiega su una connessione diretta ogni volta che Flowlight non è in esecuzione, così chiuderlo non taglia mai fuori il Mac.

Gli agenti a riga di comando ignorano le impostazioni proxy di sistema, quindi per Claude Code, Codex, Gemini CLI o Aider usa Apri Terminale ispezionato e avviali da lì. In Avanzate puoi decifrare solo gli agenti IA invece di tutte le app, modificare l'elenco di quelli mai decifrati, copiare la configurazione shell per una shell, oppure rimuovere il certificato e tutto ciò che è stato registrato.

Flowlight esclude dalla decifrazione il proprio elenco integrato di servizi Apple e gestori di password (modifica l'elenco in Configura). Le app che applicano il pinning dei certificati possono rifiutare il certificato di Flowlight; Flowlight lo rileva e le inoltra cifrate. Chiavi API, cookie e altre intestazioni con credenziali non vengono mai memorizzate, le richieste registrate vengono conservate 3 giorni e Rimuovi certificato e dati registrati elimina il certificato, la sua impostazione di attendibilità e tutto ciò che è stato registrato. L'ispezione è solo HTTP/1.1 (Flowlight lo richiede a entrambe le parti) e non è disponibile in modalità demo.

Risposte simulate

Per vedere come reagisce un agente quando un'API fallisce, si blocca o restituisce qualcosa di strano, rispondi tu a quell'endpoint. In Ispeziona › Risposte simulate, una regola indica un host, un percorso e un metodo, e fornisce lo stato, le intestazioni, il corpo e un ritardo facoltativo con cui rispondere. La richiesta non viene mai inviata: risponde Flowlight.

  • Host è esatto — api.example.com — oppure *.example.com per un dominio e i suoi sottodomini. Esatto per impostazione predefinita, perché una simulazione rivolta a un endpoint non deve rispondere in silenzio per un intero dominio.
  • Percorso accetta un carattere jolly *: /v1/*, /v1/*/items o un percorso esatto. La query string viene ignorata a meno che il tuo pattern non ne contenga una.
  • Metodo corrisponde a un solo verbo, o a qualsiasi.
  • Le regole sono ordinate e risponde la prima corrispondenza attiva. Ognuna si attiva e si disattiva per conto proprio.

Uno scambio simulato viene registrato come qualsiasi altro e contrassegnato come Simulato nell'elenco, con il pannello dei dettagli che dice che ha risposto Flowlight e non l'host, e con il nome della regola. Puoi sempre capire, più tardi, cosa era reale.

Due cose da sapere. Si possono simulare solo le richieste che Flowlight decifra, quindi l'endpoint deve passare dall'ispezione HTTPS — una regola per un host fa sì che Flowlight decifri quell'host anche se il tuo ambito è «solo agenti». E la destinazione viene comunque contattata: una simulazione cambia la risposta, non la possibilità di connettersi, quindi «l'API restituisce 500» funziona mentre «l'API è del tutto irraggiungibile» no.

Regole

Un elenco consentiti è l'idea che un singolo agente ha di dove può andare. Una regola è la versione generale: indica un soggetto — un'app, un agente, una destinazione, un URL o una coppia di due di questi — e dice blocca o consenti. Fai clic con il tasto destro su una riga in In diretta, Rapporti, Agenti IA o Ispeziona per scriverne una su ciò che stai guardando; tutte finiscono nello stesso editor della schermata Regole, perché una regola che entra in vigore fuori dalla vista sarebbe una regola che non potresti più ritrovare.

Modelli. Ventidue, in cinque gruppi: impedire a un agente di raggiungere i registri di pacchetti o altri provider di modelli, chiudere le vie più comuni per cui i dati escono (siti di paste, raccoglitori di webhook, servizi anonimi per caricare file, tunnel, DNS over HTTPS), analisi di prodotto e segnalazione degli arresti anomali, politiche sull'orario di lavoro, e il classico «blocca questo per un'ora mentre capisco cos'è». Sfogliali dalla barra strumenti di Regole, oppure fai clic con il tasto destro su una riga in In diretta, Rapporti, Agenti IA o Ispeziona e applicane uno a ciò che stai guardando.

Ogni modello dice cosa farà prima di farlo. Tutto ciò che scrive più di una regola apre una scheda con l'elenco di ogni host e orario; tutto ciò che è permanente apre l'editor già compilato; e solo le regole che si annullano da sole — un'ora, o questa esecuzione di Flowlight — vengono applicate senza essere mostrate prima. Ognuno porta con sé anche i suoi limiti, compreso il motore che richiede: un modello che funziona solo con l'ispezione HTTPS lo dice.

Quale regola vince. Decide la corrispondenza più specifica e, dove due regole sono ugualmente strette, resta valido il blocco. Così un'eccezione scritta sotto un blocco ampio funziona — Cursor may reach api.github.com sopravvive a nothing reaches github.com — mentre un'eccezione più ampia di ciò che eccettua non lo allarga in silenzio.

Per quanto tempo. Per sempre; fino a un orario; fino alla chiusura di Flowlight; o in fasce orarie scelte in giorni scelti. Le ore sono locali e valutate nel momento in cui viene stabilita una connessione, così un Mac che ha dormito oltre la fine di una fascia la trova chiusa al risveglio, e un cambio di orologio o di fuso sposta la fascia con sé. La chiusura di una fascia blocca le nuove connessioni, non smonta quelle già aperte. C'è anche un unico Sospendi il blocco globale, perché è la via di fuga a rendere vivibili le regole severe.

Sbloccare fa parte del bloccare. Ogni rifiuto porta con sé la sua via d'uscita: dall'avviso, consentilo una volta, per un'ora o fino alla chiusura di Flowlight. Ognuna di queste è a sua volta una regola con una scadenza, così l'elenco può sempre rispondere a perché questo sta passando? — anche per quella concessione su cui hai fatto clic due settimane fa.

Dove una regola morde, e dove non può. L'estensione di rete rifiuta connessioni intere: conosce l'host, l'indirizzo e la porta, nulla dei percorsi, e solo in modalità estensione. L'ispezione HTTPS rifiuta una singola richiesta, quindi può corrispondere a un URL e rispondere con uno stato che l'agente può leggere, invece di un socket morto senza spiegazioni. Il campionatore nettop non può rifiutare nulla. Una regola che la configurazione attuale non può applicare lo dice nell'elenco, invece di starsene lì con l'aria di essere in vigore.

Il secondo pannello è il flusso delle violazioni: ogni connessione decisa da una regola, con l'app, dove era diretta, quale regola ha deciso e se si è trattato di un rifiuto o di un'eccezione che l'ha lasciata passare.

Elenchi consentiti

Seleziona un agente in Agenti IA e usa Elenco consentiti nel suo dettaglio per dire dove può connettersi. Inserisci domini (sottodomini compresi), indirizzi IP o intervalli CIDR, oppure scegli una preimpostazione: GitHub, npm, PyPI, Homebrew, Docker Hub, Rust crates, Go modules o Apple. I provider IA dell'agente (a meno che non lo disattivi) e la tua rete locale sono sempre consentiti.

Da quel momento, tutto ciò che l'agente o i suoi strumenti contattano e che non è elencato genera un avviso critico di Violazione dell'elenco consentiti (una volta per dominio ogni 6 ore) e viene contrassegnato come Non consentito, con un pulsante Consenti che lo aggiunge. Per impostazione predefinita un elenco consentiti avvisa anziché rifiutare le connessioni; il blocco richiede il motore dell'estensione di rete ed è in programma.

Rifiutare le connessioni

Per impostazione predefinita un elenco consentiti avvisa. Attiva Rifiuta le connessioni fuori dall'elenco per un agente e le rifiuterà anche: la connessione viene interrotta e un avviso registra cosa è stato rifiutato, con Consenti … da ora in poi per aggiungerlo all'elenco con un clic. Il tentativo successivo dell'agente passa.

Richiede l'estensione di rete. Rifiutare una connessione significa stare sul suo percorso, cosa che il campionatore nettop non può fare: Acquisizione lo dice, invece di offrire un interruttore che non fa nulla.

Alcune cose non vengono mai rifiutate, qualunque cosa dica un elenco: la tua rete locale, il DNS, i servizi di Apple e il traffico di Flowlight stesso. Un Mac bloccato è un esito peggiore di un agente bloccato, quindi nel dubbio la connessione viene consentita e registrata. L'applicazione decade anche pochi secondi dopo che Flowlight smette di funzionare: un rifiuto che nessuno può vedere è peggio di nessun rifiuto, e il modo per annullarne uno sta nell'app.

Ispezione HTTPS e blocco non si combinano: il traffico instradato attraverso il proxy di Flowlight esce come traffico di Flowlight, che non viene mai rifiutato.

Protezioni per gli agenti: bloccare uno strumento, un server o una risorsa

Quali strumenti può usare questo agente è una domanda diversa da quali host può raggiungere, quindi ha una sezione a sé: un pannello Protezioni accanto a ogni agente in Agenti IA, con un interruttore su ogni strumento che dichiara e su ogni server MCP che raggiunge, preimpostazioni utili (sola lettura, niente shell, niente scritture) e un registro di ciò che è stato tolto.

La leva più forte è la dichiarazione. Gli agenti reinviano l'intero elenco di strumenti a ogni turno. Flowlight rimuove uno strumento rifiutato da quell'elenco prima che la richiesta parta, così al modello non viene mai offerto: nessun rifiuto su cui discutere, nessun ciclo di tentativi. Funziona allo stesso modo per uno strumento che l'agente esegue da sé e per uno dietro un server MCP remoto, e legge le stesse strutture che Flowlight già analizza per Anthropic, OpenAI e Gemini.

A una chiamata rifiutata si risponde a dovere. Per i server MCP raggiunti via HTTP, un tools/call bloccato torna come result con isError: true e una frase in chiaro, perché è così che il protocollo descrive uno strumento che fallisce: il modello la legge e si organizza diversamente, mentre un errore di trasporto sembrerebbe un server guasto. resources/read e prompts/get non hanno una struttura simile, quindi ricevono invece un errore JSON-RPC.

I connettori vengono ristretti, non intercettati. Quando è il provider a raggiungere un server MCP per conto dell'agente, quel traffico non tocca mai questo Mac. L'unica leva è la richiesta che lo predispone, quindi Flowlight restringe gli strumenti che il connettore può chiamare, oppure lo elimina del tutto.

I server stdio locali comunicano tramite pipe, e nessun proxy può vederlo. Lì Flowlight può osservare il traffico di rete del processo server, che è già attribuito all'agente che lo ha avviato, e consegnarti l'elenco dei divieti da incollare nelle impostazioni dell'agente: Claude Code accetta mcp__server__tool in permissions.deny, e i suoi vicini hanno equivalenti. Ha effetto al riavvio dell'agente.

Le protezioni richiedono l'ispezione HTTPS, perché l'elenco degli strumenti sta dentro il corpo di una richiesta. Con l'ispezione disattivata il pannello lo dice, invece di dare l'impressione di funzionare.

Questa non è una sandbox. Uno strumento rifiutato non viene più offerto e non riceve più risposta. Un agente che ha ancora una shell può fare a mano ciò che avrebbe fatto lo strumento. Flowlight lo registra; non pretende di impedirlo.

Acquisizione: motori e origini

Flowlight registra il traffico in uno di due modi, da scegliere in Acquisizione. Differiscono per ciò che possono perdere, e vale la pena capirlo prima di affidarsi all'uno o all'altro.

Ciò che il campionatore perde sono connessioni intere, non byte. Poiché confronta i totali correnti, nulla che duri attraverso due letture va perso, per quanti dati arrivino nel frattempo. Ciò che non compare mai è tutto quello che inizia e finisce tra le due — una rapida richiesta DNS, una chiamata API veloce, uno script che esegue curl ed esce. Per osservare un agente che fa molte richieste brevi, quella differenza conta.

L'estensione, invece, sta nel percorso dei dati, quindi una richiesta che dura cinque millisecondi viene registrata come qualsiasi altra. Nemmeno lei è magia: il traffico precedente alla sua attivazione non c'è, una parte del traffico di sistema è esente dai filtri di contenuto, e i suoi conteggi di byte vengono dalle statistiche del filtro stesso anziché dal conteggio dei pacchetti. Rifiuta una connessione solo dove una regola o un elenco consentiti scritto da te lo richiede.

Quando l'estensione non risponde più. macOS esegue la build dell'estensione attivata per ultima, quindi dopo un aggiornamento dell'app le due possono non concordare — e quando succede, macOS rifiuta la connessione tra loro. Impostazioni di Sistema dice che il filtro è attivo, Flowlight dice che la connessione è stata invalidata, e nessuno dei due cambia idea. Ora Flowlight se ne tira fuori da solo: riprova un paio di volte, poi chiede a macOS quale build sta eseguendo e reinstalla l'estensione se non è quella di questa app; se nulla di tutto questo funziona, acquisisce con il campionatore nettop così che ci siano comunque dati — dicendolo chiaramente e lasciando invariata l'origine che hai scelto. Riprova con l'estensione, sotto Estensione di rete, ricomincia da capo.

Su alcuni Mac non può proprio funzionare. macOS consente un solo filtro di contenuto alla volta, e normalmente lo occupa il software di sicurezza aziendale — Palo Alto Networks GlobalProtect, CrowdStrike Falcon e simili. Su quelle macchine il filtro di Flowlight si installa e si connette, e poi non riceve mai una connessione. Acquisizione elenca quelli che trova e propone di riportarti al campionatore, che non richiede alcun filtro e convive con loro. Vedi la guida per sviluppatori per come è costruito.

Dispositivi: Bluetooth, USB e archiviazione esterna

Un Mac invia e riceve oltre TCP e UDP. La schermata Dispositivi copre il resto, ed è disattivata finché non la attivi — non perché serva un permesso che Flowlight non ha già, ma perché monitorare una parte più ampia del tuo Mac deve essere una tua decisione e non qualcosa fatto da un aggiornamento.

Bluetooth mostra quali dispositivi sono abbinati, quali sono connessi e quando è cambiato, letto dal sistema ogni mezzo minuto. Accanto c'è l'elenco delle applicazioni predisposte per usare il Bluetooth, preso dall'Info.plist di ciascuna app.

Cosa non può dirti, e lo dice. Qui non ci sono conteggi di byte. macOS non tiene una contabilità per app del Bluetooth, e le tracce HCI a livello di byte che la fornirebbero richiedono il profilo PacketLogger di Apple, che un'app comune non può leggere. Allo stesso modo l'elenco delle app dice chi ha chiesto il Bluetooth, non a chi è stato concesso: macOS conserva le autorizzazioni in un database che un'app non può aprire, e Flowlight preferisce nominare quella differenza piuttosto che confonderla.

USB e archiviazione esterna elenca ciò che è collegato — di cosa si tratta, chi lo produce e la capacità di un disco — e registra quando ciascuno è arrivato e andato via. Le due metà funzionano in modo diverso di proposito: i dispositivi USB vengono letti dal sistema periodicamente, mentre i volumi arrivano dallo spazio di lavoro nel momento in cui uno viene montato o espulso, perché la comparsa di un disco è l'evento che interessa davvero. Nemmeno qui c'è il throughput, per la stessa ragione per cui non c'è sotto Bluetooth.

Modalità Focus

Scegli qualche app e qualche destinazione e ogni schermata mostra solo quelle — In diretta, Rapporti, Avvisi, Agenti IA e Ispeziona, e le velocità nella barra dei menu. Serve a osservare un agente all'opera senza il resto del Mac di mezzo.

  • Fai clic con il tasto destro su una riga in In diretta, Rapporti o Agenti IA e scegli Focus su…, oppure usa il controllo Focus in fondo alla barra laterale per scegliere tra le app che sono state attive e per digitare destinazioni.
  • ⇧⌘F attiva e disattiva Focus, come fa anche la barra dei menu, che mostra anche cosa è sotto focus.
  • Una destinazione porta con sé i suoi sottodomini: example.com copre api.example.com. Gli indirizzi IP funzionano; gli intervalli come 10.0.0.0/8 no.
  • App e destinazioni sono un'unione, non un'intersezione: mettere sotto focus Claude Code e github.com mostra tutto ciò che fa Claude Code più tutto ciò che parla con GitHub.

Un'app e una destinazione sono allo stesso modo un focus, e ciascuna da sola basta. Aggiungi un'app digitandone il nome o l'ID bundle — ogni applicazione sul Mac è ricercabile, così si può mettere a fuoco anche una che è rimasta zitta tutto il giorno, come un agente a riga di comando senza bundle applicativo — oppure spunta una tra quelle attive di recente. Aggiungi una destinazione allo stesso modo.

Una cosa che una destinazione non può restringere: gli avvisi registrano l'app che li ha generati e nulla su dove è andato il traffico, quindi un focus fatto solo di destinazioni non modifica l'elenco degli avvisi. L'editor lo dice, invece di lasciare che una schermata lo ignori in silenzio.

Focus filtra ciò che vedi, mai ciò che viene registrato. Flowlight continua ad acquisire e archiviare tutto mentre è attivo, e le linee di base delle anomalie continuano ad apprendere da tutto, così disattivando Focus ricompare il traffico che nascondeva. Una conseguenza: un avviso indica l'app che lo ha generato e non dove è andato il traffico, quindi un focus fatto solo di destinazioni lascia l'elenco degli avvisi come era.

Esecuzione in background

Flowlight continua a registrare con la finestra chiusa e costa quasi nulla mentre è inattivo: smette di costruire grafici che nessuno guarda. Impostazioni › Generali › Esegui in background va oltre e toglie l'icona nel Dock e la voce in Cmd-Tab; la barra dei menu mantiene le velocità in diretta e acquisisce Mostra l'icona nel Dock per annullare. Avvia all'accesso è nello stesso punto.

La finestra si apre dove l'hai lasciata, della dimensione che le hai dato. Al primo avvio riempie invece lo schermo, così nulla resta nascosto dietro una finestra piccola, e una finestra la cui posizione salvata è fuori schermo — un display scollegato — torna sullo schermo che hai. La configurazione dei nomi host viene proposta un po' dopo l'avvio e solo mentre una finestra è aperta, invece di accogliere il primo avvio con una richiesta della password; la proposta ritorna al lancio successivo finché non l'accetti o non la rifiuti.

Chiudere Flowlight ferma il campionatore. Non ferma l'estensione di rete: un'estensione di sistema funziona per conto proprio, quindi il filtro continua a ispezionare le connessioni finché non lo disattivi o lo disinstalli in Acquisizione.

Esportazione verso OpenTelemetry o un SIEM

Disattivata finché non la configuri, e non esiste alcun servizio Flowlight a cui inviare. Indichi tu l'endpoint — il tuo collector, il tuo SIEM — e nulla parte finché non lo fai. Impostazioni › Esportazione.

  • OTLP su HTTP con corpo JSON: le aggregazioni vanno a /v1/metrics, gli avvisi a /v1/logs, perché un avviso è un evento con una frase attaccata e una metrica perderebbe la frase. Per i collector che vogliono solo righe c'è il JSON delimitato da righe.
  • Ciò che esce è elencato per intero nel pannello, campo per campo, e un'anteprima mostra un payload reale costruito dai tuoi dati prima che venga inviato qualcosa.
  • Mai nulla dall'ispezione HTTPS. Nessuna intestazione, nessun corpo, nessuna chiamata agli strumenti: l'esportazione può trasportare solo aggregazioni e avvisi, quindi non c'è nessun posto dove possano finire, nemmeno per sbaglio.
  • Le intestazioni di autenticazione sono conservate nel portachiavi di accesso, non nelle preferenze. Di esse vengono mostrati solo i nomi.
  • Ciò che Flowlight invia compare in Flowlight, in In diretta e Rapporti, come il traffico di qualsiasi altra app — compreso un collector su 127.0.0.1.

Due cose da aspettarsi: le aggregazioni vengono consolidate con circa due minuti di ritardo, quindi un intervallo inferiore al minuto interroga più spesso senza che i dati arrivino prima; e Prova connessione dimostra che l'endpoint risponde, non che ha convalidato le tue credenziali: la riga «ultima esportazione riuscita» è il segnale onesto.

I tuoi dati

Tutto si trova in ~/Library/Application Support/Flowlight/traffic.sqlite. Le righe al secondo vengono conservate 6 ore (regolabile), quelle al minuto 14 giorni, quelle orarie 400 giorni, quelle giornaliere a tempo indeterminato e gli avvisi 90 giorni. Acquisizione › Cancella tutti i dati le elimina.

Aggiornamenti

Quando compare una nuova versione, Flowlight te lo dice con una notifica e un contrassegno nella barra laterale, invece di interrompere quello che stai facendo; facendo clic su uno dei due si apre la finestra di aggiornamento. Un controllo che avvii tu la apre subito.

Flowlight controlla su GitHub se c'è una nuova versione all'avvio e una volta al giorno, e Cerca aggiornamenti… è nei menu dell'app e della barra dei menu. Download scarica l'immagine disco in Download e la verifica con lo SHA-256 pubblicato della versione. Nulla viene installato finché non scegli tu: Esci e installa chiude Flowlight, lo sostituisce con la nuova versione e lo riapre, conservando cronologia e impostazioni. Installa più tardi ti lascia lavorare. Se Flowlight è stato installato con il .pkg, macOS chiede una password di amministratore per sostituirlo. Disattiva il controllo in Impostazioni › Generali.

Aggiorni a mano? Chiudi prima Flowlight (icona nella barra dei menu › Esci), poi trascina la nuova versione in Applicazioni. Il Finder non può sostituire un'app ancora in esecuzione e dice che l'elemento è in uso.

Modalità demo

open /Applications/Flowlight.app --args -FLDemo YES avvia Flowlight con 90 giorni di traffico sintetico in un database separato, così puoi dare un'occhiata senza registrare il tuo. È quello che mostrano le schermate di questo sito.

Disinstallazione

  1. In Acquisizione, scegli Revoca l'accesso all'acquisizione dei pacchetti (chiede la password) se l'avevi attivato, disinstalla il filtro di contenuto se l'avevi installato e disattiva l'ispezione HTTPS in Ispeziona così il suo certificato esce dal portachiavi. Solo Flowlight stesso può ritirare queste tre cose.
  2. Chiudi Flowlight e spostalo da Applicazioni al Cestino — oppure, se l'hai installato con Homebrew, brew uninstall --cask flowlight.
  3. Elimina ~/Library/Application Support/Flowlight per rimuovere la cronologia registrata, oppure lascia fare a Homebrew con brew uninstall --zap --cask flowlight.

Domande e risposte

Perché macOS ha chiesto a Flowlight l'accesso alla Scrivania o ai Documenti?
Solo perché gli hai indicato una cartella di progetto dentro una delle due. Per impostazione predefinita Flowlight legge la configurazione degli agenti dalle cartelle nella tua cartella Inizio e non tocca mai quelle tre.
Flowlight vede tutto il mio traffico o qualcosa gli sfugge?
Dipende da quale motore di acquisizione usi, e la differenza non è sottile. Il campionatore predefinito legge i contatori di byte di macOS una volta al secondo e registra la variazione, quindi un trasferimento lungo è conteggiato con esattezza — ma una connessione che si apre e si chiude tra due letture non compare affatto. L'estensione di rete viene chiamata da macOS a ogni connessione stabilita, quindi anche una richiesta di cinque millisecondi viene registrata. Se stai osservando un agente IA che scatena molte richieste brevi, installa l'estensione da Acquisizione. Il confronto completo è qui sopra.
Ho attivato l'estensione di rete e non compare nulla. Il campionatore funziona bene.
Quasi sempre perché un altro filtro di contenuto occupa già il posto. macOS esegue un solo filtro di contenuto alla volta, e di solito lo rivendica il software di sicurezza aziendale — Palo Alto Networks GlobalProtect, CrowdStrike Falcon e simili. Il filtro di Flowlight si installa, si attiva e si connette comunque, quindi Acquisizione dice Connesso all'estensione filtro, ma macOS non gli consegna mai una sola connessione e le schermate restano vuote. Acquisizione elenca i filtri che trova e propone di riportarti al campionatore, che non usa un filtro e convive con loro. Perdi solo le connessioni molto brevi (il confronto); tutto il resto viene registrato allo stesso modo.
L'estensione ha smesso di funzionare dopo l'aggiornamento di Flowlight.
Le versioni prima della 0.2.5 avevano questo problema: macOS continua a eseguire la build dell'estensione attivata per ultima, quindi dopo un aggiornamento l'estensione era la versione vecchia e macOS rifiuta la connessione tra una coppia non corrispondente. Dalla 0.2.5 Flowlight controlla all'avvio e riattiva il filtro da sé. Su una versione più vecchia, premi una volta Installa e attiva il filtro in Acquisizione.
C'è qualcos'altro che non va nell'acquisizione e non so cosa.
Esegui questo e leggi cosa stampa — riporta solo stato e conteggi, mai nulla di ciò che Flowlight ha registrato sul tuo traffico:

curl -fsSL https://raw.githubusercontent.com/xinbetween/flowlight/main/scripts/diagnose.sh | zsh

Mostra quali estensioni sono installate, se macOS ha davvero avviato il filtro di Flowlight e quanto di recente è stato registrato qualcosa. Incollalo in una segnalazione.
Flowlight invia da qualche parte informazioni su di me?
No. Non c'è account, non c'è telemetria, non ci sono analisi. Le sole richieste che fa sono il controllo giornaliero degli aggiornamenti, le ricerche facoltative sul proprietario della rete e il DNS inverso — ognuna elencata e ognuna con un interruttore per disattivarla, nella pagina sulla privacy.
Rallenta il Mac o consuma la batteria?
Con la finestra chiusa Flowlight fa quasi nulla: mantiene le velocità nella barra dei menu e scrive una riga al secondo. L'estensione di rete costa meno del campionatore di riserva, che avvia un breve processo nettop ogni secondo.
Può bloccare le connessioni?
Sì, con l'estensione di rete. L'elenco consentiti di un agente può rifiutare oltre che avvisare, una regola può bloccare un'app, una destinazione o un URL per il tempo che dici tu, e una protezione può togliere uno strumento a un agente prima che venga offerto al suo modello. Nulla blocca finché non glielo chiedi, e ogni rifiuto porta con sé la sua via d'uscita.
Mi serve l'estensione di rete?
No. Il campionatore non richiede alcun entitlement e copre la maggior parte del traffico. L'estensione aggiunge i flussi più brevi di un secondo, l'attribuzione tramite firma del codice, i nomi host senza la configurazione per l'acquisizione dei pacchetti, ed è il solo motore che può rifiutare una connessione.
Cosa succede ai miei dati se disinstallo?
Tutto si trova in ~/Library/Application Support/Flowlight. Elimina quella cartella e non c'è più; vedi Disinstallazione per l'helper di acquisizione dei pacchetti e il certificato dell'ispezione.

Limitazioni

  • Solo TCP e UDP. ICMP (ping) e gli altri protocolli su IP grezzo non vengono attribuiti.
  • L'attribuzione è per processo, non per thread.
  • Se non attivi l'ispezione HTTPS, Flowlight legge solo i metadati e non decifra mai il traffico. I nomi server di QUIC arrivano dal DNS anziché dall'handshake cifrato.
  • L'ispezione vede solo le app che usano il proxy, e mai quelle che applicano il pinning dei certificati.
  • L'acquisizione dei nomi host segue l'interfaccia di rete principale.
