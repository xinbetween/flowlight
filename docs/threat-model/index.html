Threat model

Monitoring, not prevention

Flowlight tells you what software on your Mac is sending and where. It is not a defence against an attacker who already controls the machine, and the difference matters enough to state on its own page rather than in footnotes.

What it is for

Flowlight answers a question the Mac does not: which app sent this, and where did it go? It is built for software that behaves badly in the open — an AI agent contacting something nobody asked it to, a tool uploading more than it should, a process talking to an address that has no name. That behaviour is visible in the traffic, and Flowlight's job is to make it legible and to say honestly when it cannot.

It is not antivirus, not an EDR agent, and not a firewall in the sense of something that stands between you and an attacker. Where the two overlap — Flowlight can refuse connections — the refusal is a convenience for controlling software you already trust, not a barrier against software you don't.

What it defends against

  • Unnoticed egress. An app or an agent sending somewhere you would not have approved, including through a tool it ran itself. Flowlight attributes the connection to the process that made it and to the agent that started that process.
  • Quiet changes in behaviour. An app that suddenly contacts new destinations, moves far more than its baseline, or works while you are away. Every alert names the number that tripped it, so you can disagree with it.
  • An agent exceeding what you allowed. An allowlist per agent, and rules that refuse connections outside it, with the refusal recorded and one click to allow it.
  • A tampered update. Every release publishes a checksum; the updater refuses a download it cannot verify and refuses to install an app not signed by the same team as the copy asking for the update.

Software with root can switch it off

Flowlight runs as you, with a system extension macOS starts on its behalf. Anything running as root — or anything you approve an installer for — can unload that extension, stop the app, or delete its database. Nothing in the design prevents that, and no monitoring tool on macOS can prevent it while remaining a tool you can also turn off yourself.

The honest claim is narrower and still useful: software that is misbehaving but not actively evading a monitor will be seen. Software that is actively evading one may not be, and will at least leave a gap — an extension that stopped, a period with no data — which the Coverage screen is there to show.

What capture misses

  • Traffic from before capture started. There is no backfill. A connection that opened before the filter did was never offered to it.
  • System services exempt from content filters. macOS does not show a content filter everything; some of its own traffic never reaches ours.
  • Another content filter holding the slot. macOS runs one at a time. If a VPN or a security agent has it, Flowlight's filter installs, connects, and is never asked to filter anything — Capture says so rather than showing an empty screen.
  • Short connections, on the sampler. Without the extension, Flowlight reads counters once a second: a connection that opens and closes between two readings is never recorded.
  • Channels that are not TCP or UDP. Bluetooth and USB are visible as devices, not as bytes. An agent's local MCP server talking over a pipe is not network traffic at all and appears nowhere.

What inspection misses

HTTPS inspection reads only what is routed through Flowlight's local proxy, and a program decides that when it starts. An app that ignores proxy settings, one started before inspection was switched on, or one that pins its certificates is passed through untouched — deliberately, because breaking a pinned connection would break the app. QUIC is not offered to the proxy either.

So an empty Inspect screen means "nothing was routed here", not "nothing happened". Coverage says which of the two applies, per app.

What blocking is, and isn't

A rule that refuses a connection is carried out by the Network Extension, in the path, before the connection is made. A rule that names a URL is carried out by the inspection proxy instead, which answers the request with a status the app can read. Those are the only two parts of Flowlight that act rather than report — the nettop sampler can refuse nothing at all, so on a Mac running the sampler no rule is enforced, and Flowlight says so rather than offering a switch that does nothing.

It is still not prevention. An agent that can run a shell can do by hand what a refused tool would have done. A refusal you can undo in one click is a refusal an agent's next attempt may walk through. Local traffic, DNS, Apple's own services and Flowlight's own connections are never refused, because a blocked Mac is a worse outcome than a blocked agent. And enforcement lapses a few seconds after Flowlight stops running: a refusal nobody can see is worse than none.

Inspection and refusal do not combine. Traffic routed through Flowlight's own proxy leaves the Mac as Flowlight's traffic, and Flowlight never refuses itself — so an app whose requests you are reading is an app whose connections rules no longer stop. Turning inspection on to see more costs you enforcement, and nothing on screen previously said so.

What Flowlight itself holds

Traffic metadata in a local SQLite database, with published retention. With HTTPS inspection on it also holds request and response bodies for three days — the most sensitive thing it ever keeps. Credential headers are redacted by name and by word, which is a heuristic and not a guarantee; a header carrying a secret under a name nothing recognises can be recorded.

The traffic database is never uploaded. Three smaller things do leave the Mac without being asked for, all of them named on the privacy page: the update check, which asks GitHub for the latest release on launch and daily; the network-owner lookup, which asks Team Cymru about public addresses that have no hostname; and, while Flowlight is reading counters instead of running its extension, a reverse-DNS lookup of addresses it saw no name for. The first two have off switches. The third does not, because on the sampler it is most of how a connection gets a name at all — it goes to the resolver the Mac already uses, and it stops once the extension takes over and names connections from the traffic itself. Ask with a hosted model sends far more than any of them, and is the one thing that stays off until you configure it.

Updates

Releases are signed with a Developer ID and notarized. The updater requires a published checksum and refuses a download without one, then verifies that the downloaded app is signed by the same team as the running copy before installing it. An update signed by somebody else is refused even if it is otherwise valid.

Reporting a vulnerability

Use GitHub's private vulnerability reporting, or email security@xinbetween.com if you would rather not use GitHub. SECURITY.md says what is in scope and what to expect. An ordinary bug — a crash, a wrong number, a misleading screen — belongs in the issue tracker instead.
