Flowlight の使い方

初回起動からエージェントのルールの調整まで、すべてここに。Flowlight 0.7.7、macOS 15 以降。

インストール

  1. Homebrew で。あとからのアップグレードも同じコマンドです。

    brew install --cask xinbetween/tap/flowlight

  2. または Flowlight.dmg をダウンロードし、開いて Flowlight を「アプリケーション」にドラッグします。
  3. インストーラがよいですか？どのリリースにも .pkg が付いています。
  4. ソースからビルドするには Xcode 16 以降と xcodegen が必要です。
brew install xcodegen
git clone https://github.com/xinbetween/flowlight.git && cd flowlight
xcodegen generate && scripts/build-local.sh
open build/Build/Products/Release/Flowlight.app

初回起動

0.1.6 以降のリリースは Developer ID 証明書で署名され、Apple の公証を受けているので、初回起動もそのまま通ります。自分で確かめることもできます。 spctl -a -vvv /Applications/Flowlight.app と実行すると Notarized Developer ID と返るはずです。 0.1.5 までのバージョンは未署名なので、システム設定 › プライバシーとセキュリティ › このまま開くを 1 回行う必要があります。

トラフィックは 1 秒以内に表示され始めます。メニューバーの ↓↑ の数値は、現在のダウンロードとアップロードの速度です。

ホスト名：初回だけのセットアップ

標準では、macOS が Flowlight に伝えるのは、各アプリが通信する IP アドレスだけです。実際のホスト名を表示するために、Flowlight は ネットワークパケットから 2 つのものを読み取ります。DNS の応答と、クライアントが HTTPS 接続を開くときに求めるサーバ名（TLS SNI）です。 カーネルのフィルタが、それ以外のパケットを Flowlight が見る前にすべて捨てるので、パケットの中身が保存されることはありません。

macOS では管理者だけがパケットを読めるため、トラフィックに名前を付けるウインドウでパスワードを 1 回尋ねます。これにより /Library/LaunchDaemons/com.flowlight.bpf-access.plist がインストールされ、起動のたびに access_bpf グループに /dev/bpf* への読み取り権限が与えられます。Wireshark と同じやり方です。キャプチャ › パケットキャプチャのアクセスを削除から、いつでも取り消せます。

ネットワーク所有者を特定をオンにすると、ホスト名のないトラフィックにアドレスの運用者名が付きます （Cloudflare, Inc. · AS13335）。デフォルトでオンで、そうしたパブリックな IP アドレス（プライベートなものは決して送りません）を Team Cymru の DNS サービスに送信します。キャプチャでオフにできます。

言語

Flowlight は English、简体中文、繁體中文、日本語、한국어、Français、Deutsch、Italiano、Español、Português に翻訳されています。 デフォルトでは Mac に従います。優先する言語に Flowlight が話せるものが含まれていれば、それを使います。中国語については、文字体系と地域から 簡体字と繁体字を見分けるので、zh-TW に設定した Mac では繁体字になります。未翻訳の言語の場合は英語に戻ります。

言語を明示的に選ぶには、設定 ⌘, の「一般」を開きます。次回起動を待たず、すぐに切り替わります。 システムに合わせるを選んでいるときは、その行の下に、実際にどの言語になったかが表示されます。

翻訳は画面ごとに進んでいます。ナビゲーション、設定、共通のコントロールは完了済みで、長い説明文は今のところまだ英語です。 翻訳のないキーは、空欄や識別子ではなく、正しい英語を表示します。

AI エージェントのルール

Flowlight が名前で知っているアプリ（現在 16 種類。Claude Code、Codex、Cursor、GitHub Copilot、Gemini CLI、Ollama、ZCode を含みます）か、 27 社の LLM API プロバイダのいずれかを呼ぶアプリは、エージェントとして扱われます。ブラウザは対象外です。

ルール発動する条件：エージェントが…デフォルト
機密性の高い経路メール、ファイル転送、SSH やリモートデスクトップ、トンネルやプロキシ、ピアツーピア、データベース接続を使ったときオン。メール・ファイル転送・トンネル・P2P は重大
情報流出の疑い1 時間のあいだに、AI プロバイダ以外のホストへ送信したとき100 MB/時
名前のないホストホスト名のない生の IP に、異常なポートで接続したときオン
離席中に動作キーボードとマウスの操作をやめたあと、1 分間に 1 MB 以上を転送したとき15 分

エージェントには 1 時間の学習期間があり、その後に新しい接続先のアラートが出始めます。これらはすべて設定 › 検出で変更できます。

ツールと MCP サーバ

エージェントは仕事の多くをほかのプロセスに任せます。シェルツールが curl や git、npm を実行し、MCP サーバはそれ自身のプロセスとして動きます。Flowlight は各プロセスの親をたどって起動元のエージェントまで戻るので、その通信はエージェントのものとして 数えられます。AI エージェントでは、エージェントの詳細のツールと MCP サーバにそれらが並び、接続先には curl 経由や github MCP 経由と表示されます。レポートでは、プロセスの行が Claude Code 経由と読めます。

MCP サーバの名前は、コマンドラインを Claude Code（~/.claude.json）、Claude Desktop、Cursor（~/.cursor/mcp.json）、 Windsurf、VS Code、Codex（~/.codex/config.toml）、Zed、Gemini CLI の MCP 設定と照合して決まります。リモートの MCP サーバは URL のホスト名で照合し、設定のないサーバは @modelcontextprotocol/server-github のような見覚えのあるパッケージ名で照合します。

結び付けはプロセス単位です。動き続けている MCP サーバの中で、どの個別のツール呼び出しが接続を開いたのかは、Flowlight にはわかりません。

エージェントの設定：Flowlight がこの Mac で読み取るもの

エージェントにできることは、ファイルに書かれています。読み込めるスキル、定義されたサブエージェントとスラッシュコマンド、イベントでシェルコマンドを実行する フック、与えられた権限ルール、そして起動する MCP サーバです。Flowlight はそれらのファイルを読むので、まだ 1 件もリクエストが出ていなくても、 ツールタブで各エージェントが何をする設定になっているかを確認できます。Webhook に投稿するフックや Bash(curl:*) を許可するルールは、 そうでなければ推測するしかなかったトラフィックの理由を説明してくれます。

  • デフォルトで見る場所：ホームフォルダにあるエージェントのフォルダ（~/.claude、~/.codex、 ~/.cursor、~/.gemini、~/.agents など）です。ホームフォルダ全体をたどることはないので、macOS が 「デスクトップ」「書類」「ダウンロード」へのアクセスを尋ねる必要もありません。
  • プロジェクト：プロジェクトフォルダを追加…で、コードのある場所を Flowlight に教えます。macOS が許可するのは、そのフォルダだけです。 フォルダが「書類」や「デスクトップ」の中にある場合は macOS が先に尋ねますが、目にする確認はそれ 1 回だけです。
  • 1 回だけ、常時ではなく：結果は記憶されます。Flowlight が再スキャンするのは再スキャンをクリックしたときだけで、 エージェントやプロジェクトが増えているかもしれない頃を見て、数週間後に再スキャンを提案します。バックグラウンドでのスキャンは行いません。
  • 保持するもの：名前、説明、フックが実行するコマンド、MCP サーバのコマンドまたは URL です。コードやプロンプト、ファイルをコピーすることは決してなく、 そのどれも Mac の外には出ません。見つけたものを破棄で消去できます。

気になるもの

レポートにある 3 つめのモードで、内訳とグラフの隣にあります。レポート内のアプリを互いに比べ、接続先の様子がほかと違うものを指し示します。 同種のアプリよりずっと多くの場所へつないでいる、名前に解決されたことのないアドレス、選んだというより生成されたように見えるホスト名、受信よりはるかに多い送信、 そのアプリの本業とは言えない傍流のプロトコルなどです。どの指摘にも根拠が添えられ、クリックするとそのアプリだけにレポートが絞り込まれます。

これを疑わしいものではなく気になるものと呼んでいるのは意図的です。データが裏付けられるのは「このレポートのほかのアプリと比べて、いつもと違う」 という事実までです。バックアップツールが多くの場所とつながるのには正当な理由がありますし、静かな Mac では指摘が 1 件も出ません。どのアプリにも共通するトラフィックについては、 何も述べていません。

バイトが出ていった経路

トラフィックのすべてがインターネットへ向かうわけではありません。AirDrop、Handoff、AirPlay、Sidecar、ユニバーサルコントロールは、Apple Wireless Direct Link で 同じ部屋にあるデバイスへ直接届きます。ルータもインターネットもなく、ほかの誰かが到達できるアドレスもありません。Flowlight はそうしたフローをずっと数えていましたが、 それを呼ぶ言葉を持っていませんでした。そのため、4 GB のフォルダの AirDrop が、名前のないアドレスへの数メガバイトのように見えていたのです。

いまはどのフローにもチャンネルが付きます。ネットワーク、ピアツーピア Wi-Fi、この Mac 内（ループバック。マシンの外へ出ていません）、 トンネル（VPN の中。その先どこへ行ったかはここでは見えません）です。レポートのツールバーからどれか 1 つに絞り込めますし、CSV の書き出しや コレクターへ送るデータにも一緒に付いていきます。

ピアツーピアの行には、それを開いた機能の名前が付きます。AirDrop and Handoff · nearby device、 Continuity · nearby device のように。リンクローカルアドレスからは何もわからず、同じ部屋のデバイスには、この Mac が知りうる名前がないからです。 無線を直接使うアプリはそのアプリ自身の名前を保ちます。それがそのアプリについての正直な答えです。

2 つのエンジンは答え方が違います。サンプラーは各ソケットが結び付いているインターフェイス（awdl0、llw0）を読むので、 正確です。ネットワーク機能拡張に渡されるのはインターフェイスではなくソケットなので、代わりにアドレスで判断します。リンクローカルアドレスは、ピアツーピアの通信が 宛先に使う形式です。こちらは 2 つのうち粗いほうで、Ethernet 経由で届くプリンタが同じように宛先指定されることもあります。Flowlight はそこを丸めるより、 そのまま述べるほうを選びます。

ここに新しく記録されたものはなく、新しい権限も関わりません。同じキャプチャに、ようやくラベルが付いただけです。

そのほかのアラート

  • トラフィックの急増：そのアプリの移動基準値より 3σ 以上高い 1 時間（24 時間分の履歴がたまった後、1 MB 超のもの）。
  • 1 日の接続先の数がふだんと違うとき。アプリごとの基準値と比較します。
  • 30 日間のそのアプリの 1 時間あたり送信量の99 パーセンタイルを超える送信。
  • アプリごとに 24 時間の学習期間を経た後の、新しいドメインへの初回接続と非標準ポート。
  • 操作のないトラフィック：10 分間使っていないウインドウ付きのアプリが、1 分間に 5 MB を超えて送信したとき。

Apple 純正アプリはデフォルトで除外されます。macOS は絶えず Apple と通信します。ソフトウェアアップデート、iCloud、 プッシュ、時刻、マップのタイルなど、初めて現れたときは新しく見えるホストとポートが使われ、それを全部並べると、読む価値のある 1 行が埋もれてしまいます。 表示したい場合は設定 › アラートでオフにしてください。いずれにしてもトラフィックは記録され続け、ライブ、レポート、質問にも現れ、 すべてのルール、ガードレール、許可リストの対象であり続けます。この設定が決めるのは何が一覧に載るかで、何が許されるかではありません。

質問

ふつうの言葉で尋ねれば、この Mac に記録された履歴から答えが返ります。Claude Code は昨日何を送信した？、 今週、新しい場所と通信し始めたアプリはどれ？、直近 1 時間を要約してのように。

モデルが履歴を受け取ることはありません。モデルに渡されるのは、呼び出せる読み取り専用の問い合わせ 7 種類の一覧だけです。 合計、上位のアプリ、上位の接続先、新しい接続先、アラート、エージェント、そして時系列の推移です。SQL を受け取る問い合わせは存在せず、今後も作りません。 自分で問い合わせを書けるモデルは、何でも読めてしまいます。Flowlight は、モデルが名前を挙げたものをローカルで実行し、合計と名前を返します。 Mac の外に出るものがあるとすれば、それはあなたの質問とその数値だけで、データベースが出ることはありません。

まずローカルで。macOS がオンデバイスのモデルを提供している場合は、それがデフォルトです。費用がかからず、オフラインでも動き、 どこにも 1 バイトも送りません。それがなければ、すでに動かしているモデルサーバ（Ollama、LM Studio、llama.cpp）が同じ役割を果たします。 どちらもホスト型の選択肢より上に並べています。アカウント不要・クラウド不要をうたうツールが、自分自身についての質問に答えるためにそのどちらかを 必要とするべきではないからです。

あるいは自分の API キーで。Anthropic、OpenAI、Gemini、または OpenAI 互換のエンドポイントが使えます。キーは Flowlight の環境設定ではなく、 ログインキーチェーンに保存されます。プロバイダが何かを Mac の外に送る場合は、尋ねる前に画面がそう伝えますし、すべてのリクエストは回答の下に全文が表示されます。

Flowlight 自身についての質問にも答えます。HTTPS インスペクションはどうやってオンにする？、 エージェントにシェルツールを使わせないようにするには？、トラフィックがまったく表示されないのはなぜ？といった質問には、 アプリ自身が全機能について書き下したガイドと、この Mac の現在の設定のスナップショットから答えます。モデルの記憶からは決して答えません。 メニューの場所はバージョンによって違い、でっち上げられた道順は、答えがないより悪いからです。スイッチの変更が必要な答えのときは、そのスイッチの場所を示し、 その画面を開くことを申し出ます。クリックするのはあなたです。

形が意味を持つときはグラフで。時間による変化は折れ線、比較は棒、全体の内訳は円グラフで返ります。Flowlight は問い合わせが返した同じ行から 描くので、図と文が食い違うことはありません。モデルは別の形を頼むことも、グラフなしを選ぶこともできます。

実行した問い合わせはすべて回答の下に並び、クリックするとその行がレポートで開きます。確かめられない答えは、 文法が上手なだけの当て推量です。

Flowlight は自分自身にも同じ基準を課します。この機能が送るものは、ほかのアプリのトラフィックと同じようにライブとレポートに現れます。 モデルサーバがこの Mac 上にある場合も含めてです。そこは、黙って省いてしまうのがいちばん簡単だった場面でした。

HTTPS インスペクション（任意）

デフォルトではオフです。インスペクトでオンにすると、Flowlight は 127.0.0.1:8877 でローカルプロキシを動かします。 証明書認証局は Mac 上で作られた独自のものです。経由させたアプリについては HTTPS を復号し、リクエストとレスポンスのそれぞれを表示します。 ヘッダ、本文、ステータス、そして時間です。AI エージェントのモデル応答からは、モデルが要求したツール呼び出し （Anthropic、OpenAI の Chat と Responses、Gemini、そして MCP の tools/call リクエスト）と、エージェントが返した結果をすべて読み取り、 ツールが出した各リクエストを、その原因となった呼び出しに結び付けます。paste.example への curl のリクエストには ← Bash: curl -s https://paste.example/up と表示されます。AI エージェントでは、エージェントの詳細に ツール呼び出し（呼び出しごとに、コマンド、結果またはエラー、出したリクエスト）、MCP サーバ（名前とバージョン、ローカルか リモートかプロバイダ経由か、提供するツール、呼び出し回数と失敗）、ツール（エージェントがモデルに宣言するすべてのツールと、 それぞれの使用頻度）が加わります。エージェントのヘッダ行には、モデル、呼び出し回数、消費したトークン数（キャッシュされたものも含む）が表示されます。 本文は元のキー順のまま、折りたためる JSON ツリーとして開きます。イベントストリームは 1 イベントずつ表示されます。

エージェントは毎ターン、ツールを宣言し直します。そのため、インスペクトしたリクエストからは呼び出しそのもの以上のことがわかります。エージェントが提供するツール、 プロバイダが自社サーバで実行するもの（Web 検索、コード実行）、そしてプロバイダがエージェントのために接続する MCP サーバ（Anthropic の mcp_servers、OpenAI の mcp ツール）が、その URL、トークン、承認の設定、許可されたツールとともに見えます。 最後のものは、あなたのネットワークには決して現れません。その接続を行うのは、あなたの Mac ではなくプロバイダだからです。

設定はスイッチ 1 つです。インスペクトで HTTPS インスペクションをオンにすると、Flowlight は証明書を作成し、 パスワードを 1 回尋ね、その証明書を信頼して、アプリの通信をプロキシ経由にします。スイッチをオフにすると、そのすべてが元に戻ります。プロキシの設定ファイルは Flowlight が動いていないときには直接接続に戻るので、終了しても Mac が通信できなくなることはありません。

コマンドラインのエージェントはシステムのプロキシ設定を無視します。Claude Code、Codex、Gemini CLI、Aider では インスペクト用のターミナルを開くを使い、そこから起動してください。詳細では、すべてのアプリではなく AI エージェントだけを復号する、 復号しないホストのリストを編集する、1 つのシェル用の設定をコピーする、証明書と記録したすべてを削除するといった操作ができます。

Flowlight は内蔵の一覧にある Apple のサービスとパスワード管理アプリを復号の対象から除外します（リストは「設定」で編集できます）。証明書をピン留めしているアプリは Flowlight の証明書を拒否することがあります。Flowlight はそれを検知し、暗号化されたまま通過させます。API キー、Cookie、その他の認証情報ヘッダは保存されません。 記録したリクエストの保持期間は 3 日で、証明書と記録データを削除すると、証明書、その信頼設定、記録したすべてが削除されます。 インスペクションは HTTP/1.1 のみ（Flowlight が両側にそれを要求します）で、デモモードでは利用できません。

モック応答

API が失敗したり、止まったり、おかしなものを返したときにエージェントがどう振る舞うかを見るには、そのエンドポイントに自分で応答します。 インスペクト › モック応答では、1 つのルールがホスト、パス、メソッドを指定し、返すステータス、ヘッダ、本文、そして任意の遅延を決めます。 リクエストは送信されません。Flowlight が代わりに応答します。

  • ホストは完全一致です（api.example.com）。ドメインとそのサブドメインを含めるには *.example.com と書きます。 デフォルトが完全一致なのは、1 つのエンドポイントに向けたモックが、黙ってドメイン全体に応答すべきではないからです。
  • パスには * ワイルドカードを 1 つ使えます。/v1/*、/v1/*/items、または完全なパスです。 パターンにクエリ文字列を書かない限り、クエリ文字列は無視されます。
  • メソッドは 1 つのメソッド、またはすべてに一致します。
  • ルールには順序があり、有効なもののうち最初に一致したものが応答します。オン・オフはルールごとに切り替えられます。

モックされたやり取りもほかと同じように記録され、一覧ではモック済みと表示されます。詳細ペインには、ホストではなく Flowlight が応答したことと、 どのルールによるものかが示されます。後から見ても、何が本物だったかは必ずわかります。

知っておく価値のあることが 2 つあります。モックできるのは Flowlight が復号したトラフィックだけなので、そのエンドポイントは HTTPS インスペクションを 通っている必要があります。あるホストについてのルールがあれば、対象をエージェントのみに絞っていても、Flowlight はそのホストを復号します。もう 1 つは、 接続先への接続そのものは行われるということです。モックが変えるのは答えであって、接続できるかどうかではありません。つまり「API が 500 を返す」は再現できますが、 「API にまったく到達できない」は再現できません。

ルール

許可リストは、1 つのエージェントについて「どこへ行ってよいか」を定めたものです。ルールはその一般版で、 対象（アプリ、エージェント、接続先、URL、またはそのうち 2 つの組み合わせ）を指定し、ブロックか 許可を決めます。ライブ、レポート、AI エージェント、インスペクトのどの行でも右クリックすれば、いま見ているものについてルールを書けます。 そのどれもがルール画面の同じエディタに集まります。見えないところで効き始めるルールは、二度と見つけられないルールになってしまうからです。

テンプレート。22 種類あり、5 つのグループに分かれています。エージェントがパッケージレジストリやほかのモデルプロバイダへ届かないようにするもの、 データが出ていきやすい経路をふさぐもの（ペーストサイト、Webhook の受け口、匿名のファイル置き場、トンネル、DNS over HTTPS）、プロダクト分析とクラッシュレポート、 勤務時間のポリシー、そして「作業のあいだ 1 時間だけこれをブロックして、何なのか調べる」という単発のものです。ルールのツールバーから一覧を見るか、 ライブ、レポート、AI エージェント、インスペクトのどこかで行を右クリックして、いま見ているものに当てはめてください。

どのテンプレートも、実行する前に何をするかを述べます。2 つ以上のルールを書くものは、すべてのホストとスケジュールを並べたカードを開きます。恒久的なものは あらかじめ入力されたエディタを開きます。そして自分で元に戻るルールだけ（1 時間、またはこの回の Flowlight の実行中だけ）が、先に示されることなく 適用されます。どれも注意点も添えており、必要なエンジンも示します。HTTPS インスペクションがなければ動かないテンプレートは、そう書いてあります。

どのルールが勝つか。いちばん具体的に一致したものが決め、同じくらい狭いルールが 2 つあればブロックが残ります。つまり、広いブロックの下に書いた 例外は効きます。Cursor may reach api.github.com は nothing reaches github.com を生き延びます。一方、例外の対象より広い例外が、 黙って範囲を広げることはありません。

どのくらいの期間か。ずっと、指定の時刻まで、Flowlight を終了するまで、または選んだ曜日の選んだ時間帯のあいだ。時刻はローカルタイムで、接続が 行われた瞬間に判定されます。そのため、時間帯の終わりをまたいでスリープしていた Mac は、目覚めたときにその窓が閉じていると判断します。時計やタイムゾーンを変えれば、 窓もそれに合わせて動きます。窓が閉じると新しい接続は止まりますが、すでに開いている接続を切ることはありません。全体をまとめて止めるブロックを一時停止も あります。厳しいルールと付き合っていけるのは、この非常口があるからです。

ブロックを解くこともブロックの一部です。どの拒否にも抜け道が添えてあります。アラートから、1 回だけ、1 時間、または Flowlight を終了するまで 許可できます。そのどれも期限付きのルールそのものなので、一覧はいつでもこれはなぜ通っているのかに答えられます。2 週間前にクリックして通した緩和についても、です。

ルールが効く場所と、効かない場所。ネットワーク機能拡張は接続を丸ごと拒否します。ホスト、アドレス、ポートは知っていますが、パスについては何も知らず、 しかも機能拡張モードのときだけです。HTTPS インスペクションは 1 つのリクエストを拒否するので、URL に一致させられますし、理由も告げずに死んだソケットの代わりに、 エージェントが読めるステータスで応答できます。nettop サンプラーは何も拒否できません。現在の構成では実行できないルールは、効いているように見せかけて並ぶのではなく、 一覧にそう表示されます。

2 つめのタブは違反の履歴です。ルールが判断したすべての接続について、アプリ、向かおうとしていた先、どのルールが判断したか、 そしてそれが拒否だったのか、通過を許した例外だったのかが並びます。

許可リスト

AI エージェントでエージェントを選び、その詳細の許可リストで、どこへ接続してよいかを指定します。ドメイン（サブドメインを含みます）、 IP アドレス、CIDR 範囲を入力するか、プリセットを選びます。GitHub、npm、PyPI、Homebrew、Docker Hub、Rust crates、Go modules、Apple があります。 そのエージェントの AI プロバイダ（オフにしない限り）とローカルネットワークは、常に許可されます。

それ以降、エージェントやそのツールがリストにないものに接続すると、重大な許可リスト違反アラートが上がり（同じドメインについては 6 時間に 1 回）、 許可されていませんと印が付き、それを追加する許可ボタンが表示されます。許可リストはデフォルトでは接続を拒否するのではなく警告します。 ブロックにはネットワーク機能拡張エンジンが必要で、ロードマップに載っています。

接続を拒否する

許可リストはデフォルトでは警告します。エージェントに対してリスト外の接続を拒否をオンにすると、実際に拒否もするようになります。接続は切られ、 何が拒否されたかをアラートが記録し、以後 … を許可でワンクリックでリストに追加できます。エージェントの次の試行は通ります。

ネットワーク機能拡張が必要です。接続を拒否するとは、その経路に入ることであり、nettop サンプラーにはできません。キャプチャは、 何もしないスイッチを見せるのではなく、そう伝えます。

リストが何と言っていても決して拒否されないものがあります。ローカルネットワーク、DNS、Apple 純正のサービス、そして Flowlight 自身のトラフィックです。 ブロックされたエージェントより、ブロックされた Mac のほうが悪い結果なので、迷いがある場合は接続を許可して記録します。強制は Flowlight が動作を止めた数秒後に 失効もします。誰にも見えない拒否は、拒否がないより悪く、それを取り消す手段はアプリの中にあるからです。

HTTPS インスペクションとブロックは組み合わせられません。Flowlight のプロキシを通るトラフィックは Flowlight 自身のものとして出ていき、それは決して拒否されないからです。

エージェントのガードレール：ツール、サーバ、リソースをブロックする

このエージェントはどのツールを使ってよいかは、どのホストへ届いてよいかとは別の問いなので、独立した場所があります。AI エージェントの 各エージェントの隣にあるガードレールタブです。そこには、エージェントが宣言するすべてのツールと届くすべての MCP サーバのスイッチ、 用意しておく価値のあるプリセット（読み取り専用、シェルなし、書き込みなし）、そして何を取り上げたかの記録があります。

いちばん強いてこは宣言です。エージェントは毎ターン、ツールのリスト全体を送り直します。Flowlight は拒否したツールを、リクエストが出ていく前に そのリストから外すので、モデルにはそもそも提示されません。拒否をめぐるやり取りも、再試行の繰り返しもありません。エージェント自身が実行するツールでも、 リモートの MCP サーバの向こうにあるツールでも同じように働き、Anthropic、OpenAI、Gemini について Flowlight がすでに解析している形をそのまま読みます。

拒否した呼び出しには、きちんと応答します。HTTP で接続する MCP サーバについては、ブロックした tools/call は、 結果として isError: true と平易な一文を載せて返ります。プロトコルが定める「失敗したツール」の形がそれだからです。モデルはそれを読んで 回り道を考えますが、トランスポートのエラーだと、サーバが壊れているように見えてしまいます。resources/read と prompts/get には そうした形がないので、代わりに JSON-RPC のエラーを返します。

コネクタは範囲を狭めるもので、割り込むものではありません。プロバイダがエージェントの代わりに MCP サーバへ接続する場合、その通信はこの Mac を まったく通りません。使えるてこは、それを設定するリクエストだけです。そこで Flowlight は、そのコネクタが呼び出してよいツールを狭めるか、コネクタそのものを落とします。

ローカルの stdio サーバはパイプで話すので、どのプロキシからも見えません。そこで Flowlight ができるのは、サーバプロセス自身のネットワーク通信を 監視すること（それはすでに起動元のエージェントに結び付いています）、そしてエージェント自身の設定に貼り付ける拒否リストを渡すことです。Claude Code は permissions.deny に mcp__server__tool を書けますし、ほかのエージェントにも同等のものがあります。これはエージェントを再起動したときに効きます。

ガードレールには HTTPS インスペクションが必要です。ツールのリストはリクエストの本文の中にあるからです。インスペクションがオフのときは、 動いているように見せかけるのではなく、タブがそう伝えます。

これはサンドボックスではありません。拒否したツールは提示されなくなり、呼び出しにも応答しなくなります。しかしシェルを使えるエージェントは、 そのツールがしていたことを手作業で行えます。Flowlight はそれを記録しますが、防げるふりはしません。

キャプチャ：エンジンとソース

Flowlight がトラフィックを記録する方法は 2 つあり、キャプチャで選びます。何を取りこぼしうるかが違うので、どちらかに頼る前に 知っておく価値があります。

nettop サンプラー（デフォルト）ネットワーク機能拡張
必要なものなしシステム機能拡張のインストールと、あなたの承認
トラフィックの見え方1 秒ごとに累計値を読み、その差分を記録します接続が行われるたびに macOS が呼び出します
長い転送どれだけ波があっても正確に計上計上されます
短い接続まるごと取りこぼすことがありますどれだけ短くても記録されます
電力1 秒ごとにプロセスを起動しますより少ない。ポーリングがありません

サンプラーが取りこぼすのはバイトではなく、接続そのものです。累計値を比べる方式なので、2 回の読み取りをまたいで続くものは、 そのあいだにどれだけ届いても失われません。現れないのは、2 回の読み取りのあいだに始まり、かつ終わるものです。素早い DNS の照会、速い API 呼び出し、 curl を実行して終わるスクリプトなどです。短いリクエストを何度も出すエージェントを見張る場合、この違いは重要です。

機能拡張はデータの経路の中にいるので、5 ミリ秒しか続かないリクエストもほかと同じように記録されます。とはいえ魔法ではありません。有効にする前のトラフィックは そこにありませんし、一部のシステムトラフィックはコンテンツフィルタの対象外で、バイト数はパケットを数えた値ではなくフィルタ自身の統計から来ています。 接続を拒否するのは、あなたが書いたルールか許可リストがそう指示した場合だけです。

機能拡張が応答しなくなったとき。macOS は最後に有効化されたビルドの機能拡張を動かし続けるので、アプリのアップデート後に両者が食い違うことがあります。 そうなると macOS は両者のあいだの接続を拒否します。システム設定はフィルタが有効だと言い、Flowlight は接続が無効化されたと言い、どちらも考えを変えません。 Flowlight はいま、自力でそこから抜け出します。何度か再接続を試み、次に macOS にどのビルドを動かしているか尋ね、それがこのアプリのものでなければ機能拡張を 再インストールします。それでもだめなら、データが途切れないように nettop サンプラーでキャプチャします。そのことははっきり伝え、あなたが選んだソースは変えません。 ネットワーク機能拡張の下にある機能拡張を再試行で、やり直せます。

そもそも動かない Mac もあります。macOS が許すコンテンツフィルタは同時に 1 つだけで、ふつうは企業のセキュリティソフトがそれを握っています。 Palo Alto Networks GlobalProtect や CrowdStrike Falcon などです。そうしたマシンでも Flowlight のフィルタはインストールされ、接続もしますが、 接続を 1 件も渡されません。キャプチャは見つけたものを一覧にし、フィルタを必要とせずそれらと並んで動くサンプラーへ戻すことを申し出ます。 どう作られているかは開発者向けガイドをご覧ください。

デバイス：Bluetooth、USB、外部ストレージ

Mac が送受信する経路は TCP と UDP だけではありません。デバイス画面が残りを扱います。この画面は、自分でオンにするまではオフです。 Flowlight がまだ持っていない権限を必要とするからではなく、Mac をより広く監視するかどうかは、アップデートが勝手に決めることではなく、あなたが決めることだからです。

Bluetoothでは、どのデバイスがペアリングされ、どれが接続され、それがいつ変わったかを、30 秒ごとにシステムから読み取って表示します。 その隣には、Bluetooth を使うように作られたアプリの一覧があり、各アプリ自身の Info.plist から取っています。

わからないことは、わからないと言います。ここにバイト数はありません。macOS は Bluetooth についてアプリごとの集計を行わず、それを得られる バイト単位の HCI トレースには Apple の PacketLogger プロファイルが必要で、ふつうのアプリはそれを読めません。アプリの一覧も同じで、Bluetooth を 求めたアプリであって、許可されたアプリではありません。macOS は許可の記録をアプリが開けないデータベースに保持しており、Flowlight は その違いをぼかすより、はっきり名指しするほうを選びます。

USB と外部ストレージでは、接続されているもの（何であるか、製造元、ドライブの容量）を一覧にし、それぞれがいつ来ていつ去ったかを記録します。 2 つの半分は意図的に違う仕組みです。USB デバイスは定期的にシステムから読み取り、ボリュームはマウントや取り出しの瞬間にワークスペースから受け取ります。 ドライブが現れることこそ、人が実際に気にする出来事だからです。スループットもここにはありません。Bluetooth にない理由と同じです。

フォーカスモード

アプリと接続先をいくつか選ぶと、どの画面もそれだけを表示します。ライブ、レポート、アラート、AI エージェント、インスペクト、そしてメニューバーの速度もです。 1 つのエージェントの仕事を、Mac のほかの部分に邪魔されずに見守るための機能です。

  • ライブ、レポート、AI エージェントのどの行でも右クリックしてフォーカス…を選ぶか、サイドバー下部のフォーカスのコントロールから、 動きのあったアプリを選び、接続先を入力します。
  • ⇧⌘F でフォーカスをオン・オフできます。メニューバーからも同じことができ、何にフォーカスしているかも表示されます。
  • 接続先はサブドメインも連れていきます。example.com は api.example.com を含みます。IP アドレスは使えますが、 10.0.0.0/8 のような範囲は使えません。
  • アプリと接続先は積集合ではなく和集合です。Claude Code と github.com にフォーカスすると、Claude Code のすべてに加えて、 GitHub と通信するすべてが表示されます。

アプリと接続先はどちらも同じくフォーカスになり、どちらか一方だけでも十分です。アプリは名前かバンドル識別子を入力して追加します。Mac 上のすべてのアプリケーションが 検索できるので、1 日中静かだったアプリもフォーカスできますし、アプリケーションバンドルを持たないコマンドラインのエージェントもフォーカスできます。 最近動きのあったものからチェックを入れてもかまいません。接続先も同じように追加します。

接続先で絞り込めないものが 1 つあります。アラートはそれを上げたアプリを記録し、トラフィックの行き先については何も記録しないので、接続先だけで作ったフォーカスは アラートのリストに影響しません。画面が黙って無視するのではなく、エディタがそう伝えます。

フォーカスが絞るのは見えるものだけで、記録されるものではありません。オンのあいだも Flowlight はすべてをキャプチャして保存し続け、 異常検出の基準値もすべてから学習し続けます。フォーカスをオフにすれば、隠れていたトラフィックが現れます。ひとつ結果として、アラートはそれを上げたアプリを記録し、 トラフィックの行き先は記録しないので、接続先だけにフォーカスしてもアラートのリストは変わりません。

バックグラウンドでの動作

Flowlight はウインドウを閉じても記録を続け、待機中の負荷はほぼゼロです。誰も見ていないグラフを作るのはやめます。設定 › 一般 › バックグラウンドで実行は さらに進んで、Dock アイコンと Cmd-Tab の項目をなくします。メニューバーには現在の速度が残り、それを取り消すDock アイコンを表示が加わります。 ログイン時に起動も同じ場所にあります。

ウインドウは、閉じたときの場所と大きさで開きます。初回だけは画面いっぱいに広がるので、小さなデフォルトのウインドウの裏に何かが隠れることはありません。 保存された位置が画面の外にあるウインドウ（ディスプレイを外した場合など）は、いま手元にある画面に戻ってきます。ホスト名のセットアップは、起動の少し後、 ウインドウが開いているときにだけ案内されます。初回起動のあいさつがパスワードの要求になるのを避けるためです。この案内は、実行するか閉じるまで、 次回の起動時にも出ます。

Flowlight を終了するとサンプラーは止まります。ネットワーク機能拡張は止まりません。システム機能拡張はそれ自身で動くので、キャプチャで 無効化するかアンインストールするまで、フィルタは接続を検査し続けます。

OpenTelemetry や SIEM への書き出し

設定するまではオフで、送信先となる Flowlight のサービスは存在しません。エンドポイント（あなた自身のコレクター、あなた自身の SIEM）を 指定するのはあなたで、それまで何も出ていきません。設定 › 書き出し。

  • OTLP over HTTP で、本文は JSON です。集計は /v1/metrics へ、アラートは /v1/logs へ送ります。 アラートは文が付いた出来事であり、メトリックにするとその文が失われるからです。行単位で受け取りたいコレクター向けに、改行区切り JSON も用意しています。
  • 何が出ていくかはパネルに項目ごとに一覧表示され、プレビューでは、送信する前にあなた自身のデータから組み立てた実際のペイロードを 確認できます。
  • HTTPS インスペクションのものは一切含みません。ヘッダも本文もツール呼び出しもありません。書き出しが運べるのは集計とアラートだけなので、 間違って混じる余地すらありません。
  • 認証ヘッダは環境設定ではなく、ログインキーチェーンに保存されます。表示されるのは名前だけです。
  • Flowlight が送るものは Flowlight に現れます。ほかのアプリのトラフィックと同じように、ライブとレポートに。 127.0.0.1 のコレクターも含めてです。

知っておくとよいことが 2 つあります。集計はおよそ 2 分遅れでまとめられるので、間隔を 1 分未満にしても、問い合わせが増えるだけでデータが早く届くわけでは ありません。もう 1 つ、接続をテストが証明するのはエンドポイントが応答することであって、認証情報が通ったことではありません。 「最後に書き出しに成功した時刻」の行が、正直な手がかりです。

データの保存先

すべては ~/Library/Application Support/Flowlight/traffic.sqlite にあります。秒単位の行は 6 時間（変更可能）、分単位は 14 日、 時間単位は 400 日、日単位は無期限、アラートは 90 日保持されます。 キャプチャ › すべてのデータを消去で削除できます。

アップデート

新しいバージョンが出ると、Flowlight は作業を中断させるのではなく、通知とサイドバーのバッジで知らせます。どちらをクリックしてもアップデートのウインドウが 開きます。自分で始めた確認では、すぐにそのウインドウが開きます。

Flowlight は起動時と 1 日 1 回 GitHub で新しいリリースを確認し、アップデートを確認…はアプリとメニューバーのメニューにあります。 ダウンロードはディスクイメージを「ダウンロード」フォルダに取得し、リリースが公開している SHA-256 と照合します。あなたが選ぶまで何も インストールされません。終了してインストールは Flowlight を閉じ、新しいバージョンに置き換えて開き直します。履歴と設定はそのままです。 あとでインストールなら作業を続けられます。.pkg でインストールしていた場合は、置き換えのために macOS が管理者パスワードを 尋ねます。この確認は設定 › 一般でオフにできます。

手作業でアップデートしますか？まず Flowlight を終了し（メニューバーのアイコン › 終了）、それから新しいバージョンを「アプリケーション」にドラッグしてください。 Finder は動作中のアプリを置き換えられず、項目は使用中だと言います。

デモモード

open /Applications/Flowlight.app --args -FLDemo YES で起動すると、90 日分の合成トラフィックが入った別のデータベースで Flowlight が 動きます。自分のトラフィックを記録せずに中を見られます。このサイトのスクリーンショットもこれです。

アンインストール

  1. キャプチャで、有効にしていた場合はパケットキャプチャのアクセスを削除を選び（パスワードを尋ねられます）、 インストールしていた場合はコンテンツフィルタをアンインストールし、インスペクトで HTTPS インスペクションをオフにして、証明書を キーチェーンから取り除きます。この 3 つを取り下げられるのは Flowlight 自身だけです。
  2. Flowlight を終了し、「アプリケーション」からゴミ箱に移します。Homebrew でインストールした場合は brew uninstall --cask flowlight でもかまいません。
  3. 記録した履歴を消すには ~/Library/Application Support/Flowlight を削除するか、Homebrew に任せて brew uninstall --zap --cask flowlight を実行します。

質問と回答

macOS が Flowlight に「デスクトップ」や「書類」へのアクセスを求めたのはなぜですか？
そのどちらかの中にあるプロジェクトフォルダを指定した場合だけです。デフォルトでは、Flowlight はホームフォルダにあるフォルダからエージェントの設定を読み、 その 3 つには触れません。
Flowlight は私のトラフィックをすべて見るのですか、それとも取りこぼしがありますか？
どのキャプチャエンジンを使うかによりますし、その差はささいなものではありません。デフォルトのサンプラーは macOS の累計バイトカウンタを 1 秒ごとに読み、 その変化を記録するので、長い転送は正確に計上されます。しかし、2 回の読み取りのあいだに開いて閉じた接続は、まったく現れません。ネットワーク機能拡張は 接続が行われるたびに macOS から呼ばれるので、5 ミリ秒のリクエストでも記録されます。短いリクエストを何度も出す AI エージェントを見張るなら、 キャプチャから機能拡張をインストールしてください。詳しい比較は上にあります。
ネットワーク機能拡張をオンにしたのに何も表示されません。サンプラーは問題なく動きます。
ほとんどの場合、別のコンテンツフィルタがすでにその枠を取っているからです。macOS が許すコンテンツフィルタは同時に 1 つだけで、 企業のセキュリティソフトがふつうそれを取っています。Palo Alto Networks GlobalProtect、CrowdStrike Falcon などです。Flowlight のフィルタは インストールも有効化も接続もされるので、キャプチャはフィルタ機能拡張に接続しましたと表示しますが、macOS は接続を 1 件も渡さず、画面は空のままです。 キャプチャは見つけたフィルタを一覧にし、フィルタを使わずそれらと並んで動くサンプラーへ戻すことを申し出ます。失われるのはごく短い接続だけで （比較）、ほかはすべて同じように記録されます。
Flowlight をアップデートしたら機能拡張が動かなくなりました。
0.2.5 より前のバージョンにはこの問題がありました。macOS は最後に有効化されたビルドの機能拡張を動かし続けるため、アップデート後は機能拡張が古いバージョンのままで、 macOS は食い違った両者のあいだの接続を拒否します。0.2.5 以降は、Flowlight が起動時に確認して、自分でフィルタを再有効化します。それより古いバージョンでは、 キャプチャでフィルタをインストールして有効にするを 1 回押してください。
キャプチャがほかの理由でおかしいのですが、原因がわかりません。
これを実行して、出力を読んでください。報告するのは状態と件数だけで、Flowlight が記録したトラフィックの内容は決して含みません。

curl -fsSL https://raw.githubusercontent.com/xinbetween/flowlight/main/scripts/diagnose.sh | zsh

どの機能拡張がインストールされているか、macOS が本当に Flowlight のフィルタを起動したか、最後に何かが記録されたのはいつかがわかります。 issue に貼り付けてください。
Flowlight は私に関する情報をどこかに送りますか？
いいえ。アカウントもテレメトリも分析もありません。行うリクエストは、1 日 1 回のアップデート確認、任意のネットワーク所有者の照会、そして逆引き DNS だけです。 それぞれプライバシーのページに一覧があり、どれにもオフのスイッチがあります。
Mac が遅くなったり、バッテリーが減ったりしませんか？
ウインドウを閉じているあいだ、Flowlight はほとんど何もしません。メニューバーの速度を保ち、1 秒に 1 行書き込むだけです。ネットワーク機能拡張のほうが、 1 秒ごとに短命な nettop プロセスを起動する代替のサンプラーよりも負荷が低いです。
接続をブロックできますか？
はい、ネットワーク機能拡張があれば。エージェントの許可リストは警告だけでなく拒否もでき、ルールはアプリ、接続先、URL を 好きな期間ブロックでき、ガードレールはモデルに提示される前にエージェントからツールを取り上げられます。 あなたが指示するまで何もブロックされず、どの拒否にも抜け道が添えてあります。
ネットワーク機能拡張は必要ですか？
いいえ。サンプラーは特別な権限を必要とせず、たいていのトラフィックを押さえます。機能拡張が加えるのは、1 秒より短いフロー、コード署名による判別、 パケットキャプチャのセットアップなしでのホスト名で、接続を拒否できる唯一のエンジンでもあります。
アンインストールしたら、データはどうなりますか？
すべては ~/Library/Application Support/Flowlight にあります。そのフォルダを削除すれば消えます。パケットキャプチャのヘルパーと インスペクションの証明書についてはアンインストールをご覧ください。

制限事項

  • TCP と UDP のみです。ICMP（ping）やその他の生 IP プロトコルは、アプリに結び付けられません。
  • 結び付けはプロセス単位で、スレッド単位ではありません。
  • HTTPS インスペクションをオンにしない限り、Flowlight はメタデータだけを読み、トラフィックを復号することはありません。QUIC のサーバ名は、 暗号化されたハンドシェイクではなく DNS から取ります。
  • インスペクションが見られるのはプロキシを使うアプリだけで、証明書をピン留めするアプリは決して見られません。
  • ホスト名のキャプチャは、主要なネットワークインターフェイスに従います。
