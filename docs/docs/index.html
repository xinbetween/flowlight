Using Flowlight

Everything from the first launch to tuning the agent rules. Flowlight 0.1.5, macOS 15 or later.

Install

  1. Download Flowlight.dmg, open it and drag Flowlight into Applications.
  2. Prefer an installer? Every release also has a .pkg.
  3. Building from source needs Xcode 16 or later and xcodegen:
brew install xcodegen
git clone https://github.com/xinbetween/flowlight.git && cd flowlight
xcodegen generate && scripts/build-local.sh
open build/Build/Products/Release/Flowlight.app

First launch

This preview isn't notarized yet, so macOS says it can't verify the developer. Right-click Flowlight in Applications, choose Open, then Open again. You only do this once. On macOS 15 and later you can also allow it in System Settings › Privacy & Security › Open Anyway.

Traffic starts appearing within a second. The ↓↑ figures in your menu bar are live download and upload rates.

Hostnames: the one-time setup

By default macOS only tells Flowlight the IP address each app talks to. To show real hostnames, Flowlight reads two things from network packets: DNS answers, and the server name a client asks for when it opens an HTTPS connection (TLS SNI). A filter in the kernel drops every other packet before Flowlight sees it, and packet contents are never stored.

macOS only lets administrators read packets, so the Name Your Traffic window asks for your password once. It installs /Library/LaunchDaemons/com.flowlight.bpf-access.plist, which gives the access_bpf group read access to /dev/bpf* at each boot, the same approach Wireshark uses. Remove it any time from Capture › Remove Packet Capture Access.

Identify network owners labels traffic with no hostname by who operates the address (Cloudflare, Inc. · AS13335). It's on by default and sends those public IP addresses (never private ones) to Team Cymru's DNS service. Turn it off in Capture.

AI agent rules

An app counts as an agent if Flowlight knows it by name (16 today, including Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Ollama and ZCode) or if it calls one of 25 LLM API providers. Browsers are excluded.

RuleFires when an agent…Default
Sensitive channeluses email, file transfer, SSH or remote desktop, a tunnel or proxy, peer-to-peer, or a database connectionOn. Critical for email, file transfer, tunnels and P2P

Agents get a 1-hour learning period before new-destination alerts start. Change any of this in Settings › Detection.

Tools & MCP servers

Agents do much of their work through other processes: a shell tool runs curl, git or npm, and MCP servers run as their own processes. Flowlight follows each process's parents back to the agent that started it, so that traffic is counted as the agent's. In AI Agents, the agent's detail lists these under Tools & MCP servers, and destinations read via curl or via github MCP. In Reports, the process row reads via Claude Code.

MCP servers are named by matching their command line to the MCP configuration of Claude Code (~/.claude.json), Claude Desktop, Cursor (~/.cursor/mcp.json), Windsurf, VS Code, Codex (~/.codex/config.toml), Zed and Gemini CLI. Remote MCP servers are matched by the hostname in their URL, and unconfigured servers by recognizable package names such as @modelcontextprotocol/server-github.

Attribution is per process: Flowlight can't tell which individual tool call inside a long-running MCP server opened a connection.

Allowlists

Select an agent in AI Agents and use Allowlist in its detail to say where it may connect. Enter domains (subdomains included), IP addresses or CIDR ranges, or pick a preset: GitHub, npm, PyPI, Homebrew, Docker Hub, Rust crates, Go modules or Apple. The agent's AI providers (unless you turn that off) and your local network are always allowed.

From then on, anything the agent or its tools contact that isn't listed raises a critical Allowlist violation alert (once per domain every 6 hours) and is marked Not allowed, with an Allow button that adds it. Flowlight doesn't block connections; blocking needs the Network Extension engine and is on the roadmap.

HTTPS inspection (optional)

Off by default. When you turn it on in Inspect, Flowlight runs a local proxy on 127.0.0.1:8877 with its own certificate authority, created on your Mac. For apps you route through it, it decrypts HTTPS and shows each request and response: headers, bodies, status and timing. From an AI agent's model responses it reads every tool call the model asked for (Anthropic, OpenAI Chat and Responses, Gemini, and MCP tools/call requests) and the result the agent sent back, and it links each request a tool makes back to the call that caused it: curl's request to paste.example shows ← Bash: curl -s https://paste.example/up. In AI Agents, an agent's detail gets Tool calls (each call with its command, result or error, and the requests it made) and MCP servers (name and version, local or remote, the tools it offers, calls and failures). Bodies open as a collapsible JSON tree in their original key order; event streams show one event at a time.

  1. Turn it on in Inspect › Setup. By default only AI agents and the tools they start are decrypted; other apps sent through the proxy pass through encrypted and aren't recorded.
  2. Route an agent. Click Open Inspected Terminal and start Claude Code, Codex, Gemini CLI or Aider there, or paste Copy Shell Setup into any shell. It sets the proxy variables and points Node, Python, curl and Git at the Flowlight certificate, for that shell only.
  3. Optional: trust the certificate (macOS asks for your password) and turn on the system proxy, so desktop apps that follow proxy settings (Cursor, VS Code, Claude) are inspected too. The proxy file falls back to a direct connection whenever Flowlight isn't running.

Apple services and password managers are never decrypted (edit the list in Setup). Apps that pin their certificates refuse the Flowlight certificate; Flowlight notices and passes them through encrypted. API keys, cookies and other credential headers are never stored, recorded requests are kept 3 days, and Remove Certificate & Recorded Data deletes the certificate, its trust setting and everything recorded. Inspection is HTTP/1.1 only (Flowlight asks both sides for it) and not available in demo mode.

Other alerts

  • Traffic spike: an hour at least 3σ above the app's rolling baseline (after 24 hours of history, above 1 MB).
  • Unusual number of destinations in a day, against the app's baseline.
  • Upload above 99th percentile of the app's hourly uploads over 30 days.
  • First contact with a new domain, and non-standard ports, after a 24-hour learning period per app.
  • Traffic without UI activity: a windowed app you haven't used for 10 minutes uploads more than 5 MB a minute.

Capture engines

The default engine samples macOS's nettop once a second, which needs no special permission. Connections shorter than about a second can be missed. A Network Extension engine (a content filter that sees every flow) is included in the source for builds signed with Apple's content-filter entitlement; see the developer guide.

Your data

Everything lives in ~/Library/Application Support/Flowlight/traffic.sqlite. Per-second rows are kept 6 hours (adjustable), minute rows 14 days, hourly rows 400 days, daily rows indefinitely, and alerts 90 days. Capture › Clear all data deletes it.

Updates

Flowlight checks GitHub for a new release on launch and once a day, and Check for Updates… is in the app and menu bar menus. Download fetches the disk image to Downloads and checks it against the release's published SHA-256. Nothing is installed until you choose: Quit & Install closes Flowlight, replaces it with the new version and reopens it, keeping your history and settings. Install Later keeps you working. If Flowlight was installed with the .pkg, macOS asks for an administrator password to replace it. Turn the check off in Settings › General.

Updating by hand? Quit Flowlight first (menu bar icon › Quit), then drag the new version into Applications. Finder can't replace an app that's still running and says the item is in use.

Demo mode

open /Applications/Flowlight.app --args -FLDemo YES starts Flowlight with 90 days of synthetic traffic in a separate database, so you can look around without recording your own. It's what the screenshots on this site show.

Uninstall

  1. In Capture, choose Remove Packet Capture Access (asks for your password) if you enabled it.
  2. Quit Flowlight and move it from Applications to the Trash.
  3. Delete ~/Library/Application Support/Flowlight to remove the recorded history.

Limitations

  • TCP and UDP only. ICMP (ping) and other raw-IP protocols aren't attributed.
  • Attribution is per process, not per thread.
  • Unless you turn on HTTPS inspection, Flowlight reads metadata only and never decrypts traffic. QUIC server names come from DNS rather than the encrypted handshake.
  • Inspection only sees apps that use the proxy, and never apps that pin their certificates.
  • Hostname capture follows the primary network interface.
