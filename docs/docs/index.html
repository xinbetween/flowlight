Using Flowlight

Everything from the first launch to tuning the agent rules. Flowlight 0.2.6, macOS 15 or later.

Install

  1. With Homebrew — the same command upgrades it later:

    brew install --cask xinbetween/tap/flowlight

  2. Or download Flowlight.dmg, open it and drag Flowlight into Applications.
  3. Prefer an installer? Every release also has a .pkg.
  4. Building from source needs Xcode 16 or later and xcodegen:
brew install xcodegen
git clone https://github.com/xinbetween/flowlight.git && cd flowlight
xcodegen generate && scripts/build-local.sh
open build/Build/Products/Release/Flowlight.app

First launch

Releases from 0.1.6 are signed with a Developer ID certificate and notarized by Apple, so the first launch just works. You can check it yourself: spctl -a -vvv /Applications/Flowlight.app should answer Notarized Developer ID. Versions up to 0.1.5 were unsigned; those need System Settings › Privacy & Security › Open Anyway once.

Traffic starts appearing within a second. The ↓↑ figures in your menu bar are live download and upload rates.

Hostnames: the one-time setup

By default macOS only tells Flowlight the IP address each app talks to. To show real hostnames, Flowlight reads two things from network packets: DNS answers, and the server name a client asks for when it opens an HTTPS connection (TLS SNI). A filter in the kernel drops every other packet before Flowlight sees it, and packet contents are never stored.

macOS only lets administrators read packets, so the Name Your Traffic window asks for your password once. It installs /Library/LaunchDaemons/com.flowlight.bpf-access.plist, which gives the access_bpf group read access to /dev/bpf* at each boot, the same approach Wireshark uses. Remove it any time from Capture › Remove Packet Capture Access.

Identify network owners labels traffic with no hostname by who operates the address (Cloudflare, Inc. · AS13335). It's on by default and sends those public IP addresses (never private ones) to Team Cymru's DNS service. Turn it off in Capture.

In Reports, hover a bar to see which apps drove it, click it to zoom in, and double-click any row to narrow the report to it.

Focus mode

Pick a few apps and destinations and every screen shows only those — Live, Reports, Alerts, AI Agents and Inspect, and the rates in the menu bar. It's for watching one agent work without the rest of the Mac in the way.

  • Right-click any row in Live, Reports or AI Agents and choose Focus on…, or use the Focus control at the bottom of the sidebar to pick from the apps that have been active and to type destinations.
  • ⇧⌘F turns Focus on and off, and so does the menu bar, which also shows what's focused.
  • A destination takes its subdomains with it: example.com covers api.example.com. IP addresses work; ranges like 10.0.0.0/8 don't.
  • Apps and destinations are a union, not an intersection: focusing on Claude Code and github.com shows everything Claude Code does plus everything that talks to GitHub.

Focus filters what you see, never what's recorded. Flowlight keeps capturing and storing everything while it's on, and the anomaly baselines keep learning from all of it, so turning Focus off shows the traffic it was hiding. One consequence: an alert names the app that raised it and not where the traffic went, so focusing only on destinations leaves the alert list as it was.

AI agent rules

An app counts as an agent if Flowlight knows it by name (16 today, including Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Ollama and ZCode) or if it calls one of 25 LLM API providers. Browsers are excluded.

RuleFires when an agent…Default
Sensitive channeluses email, file transfer, SSH or remote desktop, a tunnel or proxy, peer-to-peer, or a database connectionOn. Critical for email, file transfer, tunnels and P2P
Possible exfiltrationuploads to hosts that aren't AI providers, over an hour100 MB/h
Unnamed hostconnects to a raw IP with no hostname on an unusual portOn
Active while you're awaymoves 1 MB or more in a minute after you stop using the keyboard and mouse15 minutes

Agents get a 1-hour learning period before new-destination alerts start. Change any of this in Settings › Detection.

Tools & MCP servers

Agents do much of their work through other processes: a shell tool runs curl, git or npm, and MCP servers run as their own processes. Flowlight follows each process's parents back to the agent that started it, so that traffic is counted as the agent's. In AI Agents, the agent's detail lists these under Tools & MCP servers, and destinations read via curl or via github MCP. In Reports, the process row reads via Claude Code.

MCP servers are named by matching their command line to the MCP configuration of Claude Code (~/.claude.json), Claude Desktop, Cursor (~/.cursor/mcp.json), Windsurf, VS Code, Codex (~/.codex/config.toml), Zed and Gemini CLI. Remote MCP servers are matched by the hostname in their URL, and unconfigured servers by recognizable package names such as @modelcontextprotocol/server-github.

Attribution is per process: Flowlight can't tell which individual tool call inside a long-running MCP server opened a connection.

Allowlists

Select an agent in AI Agents and use Allowlist in its detail to say where it may connect. Enter domains (subdomains included), IP addresses or CIDR ranges, or pick a preset: GitHub, npm, PyPI, Homebrew, Docker Hub, Rust crates, Go modules or Apple. The agent's AI providers (unless you turn that off) and your local network are always allowed.

From then on, anything the agent or its tools contact that isn't listed raises a critical Allowlist violation alert (once per domain every 6 hours) and is marked Not allowed, with an Allow button that adds it. Flowlight doesn't block connections; blocking needs the Network Extension engine and is on the roadmap.

Agent configuration: what Flowlight reads on your Mac

An agent's abilities are written down in files: the skills it can load, the subagents and slash commands it defines, the hooks that run shell commands on events, the permission rules it was given, and the MCP servers it starts. Flowlight reads those files so the Tools tab can show what each agent is set up to do, even before it makes a single request. A hook that posts to a webhook, or a rule that allows Bash(curl:*), explains traffic you'd otherwise have to guess at.

  • Where it looks by default: the agent folders in your home folder — ~/.claude, ~/.codex, ~/.cursor, ~/.gemini, ~/.agents and the like. It does not walk your whole home folder, so macOS doesn't have to ask for access to Desktop, Documents or Downloads.
  • Your projects: use Add project folder… to point Flowlight at where your code lives. macOS then grants access to that folder only. If the folder sits inside Documents or Desktop, macOS asks first, and that's the one prompt you'll see.
  • Once, not constantly: the result is remembered. Flowlight rescans only when you click Rescan, and offers one after a couple of weeks in case you've added agents or projects. Nothing is scanned in the background.
  • What it keeps: names, descriptions, the command a hook runs, and MCP server commands or URLs. It never copies your code, your prompts or your files, and none of it leaves your Mac. Forget what was found clears it.

HTTPS inspection (optional)

Off by default. When you turn it on in Inspect, Flowlight runs a local proxy on 127.0.0.1:8877 with its own certificate authority, created on your Mac. For apps you route through it, it decrypts HTTPS and shows each request and response: headers, bodies, status and timing. From an AI agent's model responses it reads every tool call the model asked for (Anthropic, OpenAI Chat and Responses, Gemini, and MCP tools/call requests) and the result the agent sent back, and it links each request a tool makes back to the call that caused it: curl's request to paste.example shows ← Bash: curl -s https://paste.example/up. In AI Agents, an agent's detail gets Tool calls (each call with its command, result or error, and the requests it made) and MCP servers (name and version, local or remote or via provider, the tools it offers, calls and failures) and Tools (every tool the agent declares to the model, with how often each was used). The agent's header line shows the model, the number of calls and the tokens spent, including cached ones. Bodies open as a collapsible JSON tree in their original key order; event streams show one event at a time.

Agents declare their tools on every turn, so an inspected request shows more than the calls themselves: the tools the agent offers, the ones the provider runs on its own servers (web search, code execution), and the MCP servers the provider connects to for the agent (Anthropic's mcp_servers, OpenAI's mcp tool) with their URL, token, approval setting and allowed tools. That last group never appears on your network, because the provider makes those connections, not your Mac.

Setting it up is one switch. Turn on HTTPS inspection in Inspect and Flowlight creates its certificate, asks for your password once, trusts the certificate and routes apps through the proxy. Turning the switch off undoes all of it. The proxy file falls back to a direct connection whenever Flowlight isn't running, so quitting it never cuts your Mac off.

Command-line agents ignore system proxy settings, so for Claude Code, Codex, Gemini CLI or Aider use Open Inspected Terminal and start them there. Under Advanced you can decrypt AI agents only instead of every app, edit the never-decrypt list, copy the shell setup for one shell, or remove the certificate and everything recorded.

Apple services and password managers are never decrypted (edit the list in Setup). Apps that pin their certificates refuse the Flowlight certificate; Flowlight notices and passes them through encrypted. API keys, cookies and other credential headers are never stored, recorded requests are kept 3 days, and Remove Certificate & Recorded Data deletes the certificate, its trust setting and everything recorded. Inspection is HTTP/1.1 only (Flowlight asks both sides for it) and not available in demo mode.

Other alerts

  • Traffic spike: an hour at least 3σ above the app's rolling baseline (after 24 hours of history, above 1 MB).
  • Unusual number of destinations in a day, against the app's baseline.
  • Upload above 99th percentile of the app's hourly uploads over 30 days.
  • First contact with a new domain, and non-standard ports, after a 24-hour learning period per app.
  • Traffic without UI activity: a windowed app you haven't used for 10 minutes uploads more than 5 MB a minute.

Capture engines

Flowlight records traffic one of two ways, chosen in Capture. They differ in what they can miss, which is worth understanding before you rely on either.

nettop sampler (default)Network Extension
NeedsNothingInstalling a system extension, and your approval
How it sees trafficReads running totals once a second and records the differencemacOS calls it as each connection is made
Long transfersCounted exactly, however burstyCounted
Short connectionsCan be missed entirelyRecorded, however brief
EnergyStarts a process every secondLower — no polling

What the sampler misses is whole connections, not bytes. Because it compares running totals, nothing that lasts across two readings is lost, no matter how much arrives in between. What never appears is anything that starts and finishes between them — a quick DNS lookup, a fast API call, a script that runs curl and exits. For watching an agent that makes many short requests, that difference matters.

The extension is in the data path instead, so a request lasting five milliseconds is recorded like any other. It isn't magic either: traffic from before you enabled it isn't there, some system traffic is exempt from content filters, and its byte counts come from the filter's own statistics rather than from counting packets. It never blocks anything.

It also can't run at all on some Macs. macOS allows one content filter at a time, and corporate security software normally holds it — Palo Alto Networks GlobalProtect, CrowdStrike Falcon and the like. Flowlight's filter will install and connect on those machines and then never be handed a connection. Capture lists any it finds and offers to switch you back to the sampler, which needs no filter and works alongside them. See the developer guide for how it's built.

Your data

Everything lives in ~/Library/Application Support/Flowlight/traffic.sqlite. Per-second rows are kept 6 hours (adjustable), minute rows 14 days, hourly rows 400 days, daily rows indefinitely, and alerts 90 days. Capture › Clear all data deletes it.

Updates

When a new version appears, Flowlight tells you with a notification and a badge in the sidebar rather than interrupting what you're doing; clicking either opens the update window. A check you start yourself opens it straight away.

Flowlight checks GitHub for a new release on launch and once a day, and Check for Updates… is in the app and menu bar menus. Download fetches the disk image to Downloads and checks it against the release's published SHA-256. Nothing is installed until you choose: Quit & Install closes Flowlight, replaces it with the new version and reopens it, keeping your history and settings. Install Later keeps you working. If Flowlight was installed with the .pkg, macOS asks for an administrator password to replace it. Turn the check off in Settings › General.

Updating by hand? Quit Flowlight first (menu bar icon › Quit), then drag the new version into Applications. Finder can't replace an app that's still running and says the item is in use.

Demo mode

open /Applications/Flowlight.app --args -FLDemo YES starts Flowlight with 90 days of synthetic traffic in a separate database, so you can look around without recording your own. It's what the screenshots on this site show.

Uninstall

  1. In Capture, choose Remove Packet Capture Access (asks for your password) if you enabled it, uninstall the content filter if you installed it, and turn HTTPS inspection off in Inspect so its certificate leaves your keychain. Only Flowlight itself can withdraw those three.
  2. Quit Flowlight and move it from Applications to the Trash — or, if you installed it with Homebrew, brew uninstall --cask flowlight.
  3. Delete ~/Library/Application Support/Flowlight to remove the recorded history, or let Homebrew do it with brew uninstall --zap --cask flowlight.

Questions & answers

Why did macOS ask Flowlight for access to my Desktop or Documents?
Only because you pointed it at a project folder inside one of them. By default Flowlight reads agent configuration from the folders in your home folder and never touches those three.
Does Flowlight see all my traffic, or does it miss some?
It depends which capture engine you use, and the difference is not subtle. The default sampler reads macOS's running byte counters once a second and records the change, so a long transfer is counted exactly — but a connection that opens and closes between two readings never appears at all. The Network Extension is called by macOS as each connection is made, so even a five-millisecond request is recorded. If you're watching an AI agent that fires many short requests, install the extension from Capture. The full comparison is above.
I turned on the Network Extension and nothing appears. The sampler works fine.
Almost always because another content filter already has the slot. macOS runs one content filter at a time, and corporate security software usually claims it — Palo Alto Networks GlobalProtect, CrowdStrike Falcon and similar. Flowlight's filter still installs, activates and connects, so Capture says Connected to filter extension, but macOS never hands it a single connection and the screens stay empty. Capture lists the filters it finds and offers to switch you back to the sampler, which doesn't use a filter and works alongside them. You lose only the very short connections (the comparison); everything else is recorded the same way.
The extension stopped working after Flowlight updated.
Versions before 0.2.5 had this: macOS keeps running whichever build of the extension was last activated, so after an update the extension was the old version and macOS refuses the connection between a mismatched pair. From 0.2.5 Flowlight checks at launch and re-activates the filter itself. On an older version, press Install & enable filter in Capture once.
Something else is wrong with capture and I don't know what.
Run this and read what it prints — it reports state and counts only, never anything Flowlight recorded about your traffic:

curl -fsSL https://raw.githubusercontent.com/xinbetween/flowlight/main/scripts/diagnose.sh | zsh

It shows which extensions are installed, whether macOS actually started Flowlight's filter, and how recently anything was recorded. Paste it into an issue.
Does Flowlight send anything about me anywhere?
No. There's no account, no telemetry and no analytics. The only requests it makes are the daily update check, optional network-owner lookups, and reverse DNS — each listed, and each with an off switch, on the privacy page.
Will it slow my Mac down or drain the battery?
With the window closed Flowlight does almost nothing: it keeps the menu bar rates and writes one row a second. The Network Extension costs less than the fallback sampler, which starts a short-lived nettop process every second.
Can it block connections?
Not yet. It observes and explains, and allowlists raise alerts. Blocking needs the Network Extension engine and is on the roadmap.
Do I need the Network Extension?
No. The sampler needs no entitlement and covers most traffic. The extension adds flows shorter than a second, attribution by code signature, hostnames without the packet-capture setup, and is the path to blocking.
What happens to my data if I uninstall?
Everything lives in ~/Library/Application Support/Flowlight. Delete that folder and it's gone; see Uninstall for the packet-capture helper and the inspection certificate.

Limitations

  • TCP and UDP only. ICMP (ping) and other raw-IP protocols aren't attributed.
  • Attribution is per process, not per thread.
  • Unless you turn on HTTPS inspection, Flowlight reads metadata only and never decrypts traffic. QUIC server names come from DNS rather than the encrypted handshake.
  • Inspection only sees apps that use the proxy, and never apps that pin their certificates.
  • Hostname capture follows the primary network interface.
