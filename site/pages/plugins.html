Write inspection plugins

Plugins turn inspected exchanges into local advisory findings. Official Flowlight plugins cover common traffic and LLM/MCP guardrail patterns; community plugins use reviewable manifests with provenance, permissions and privacy disclosures.

The trust boundary

Flowlight plugins are scoped to HTTPS inspection. They run after a request and response have already been captured, redacted, clipped, attributed to an app or agent, and written to the local database. A plugin can add findings and suggest reviewed Flowlight actions that open existing editors, but it does not block, rewrite, mock, transform, or save settings by itself.

Flowlight reviews a plugin package before installation. The review shows provenance, signature status, permissions, privacy categories, the full package and script digests, and the exact embedded JavaScript in a read-only source view. Package import fails closed when a signed package is malformed or tampered with; runtime JavaScript still fails open so capture remains complete.

Manifest

A manifest tells Flowlight what the plugin is, who publishes it, what sanitized metadata it uses, whether it can suggest reviewed actions, and optionally the JavaScript evaluate(context) script to run.

{
  "id": "thirdparty.example-guardrails",
  "name": "Example Guardrails",
  "version": "0.1.0",
  "kind": "llmMCP",
  "source": "installed",
  "publisher": "thirdParty",
  "guardrailProvider": "custom",
  "description": "Example advisory findings for inspected LLM and MCP activity.",
  "ruleVersion": 1,
  "schemaVersion": 1,
  "privacySummary": "Uses provider names, tool names, MCP server names, request sizes and redacted evidence only.",
  "privacy": {
    "categories": ["metadataOnly", "toolNames", "mcpMetadata", "guardrailSuggestions"],
    "summary": "Uses sanitized metadata only."
  },
  "permissions": ["trafficMetadata", "appIdentity", "llmMetadata", "mcpMetadata", "suggestAction"],
  "capabilities": ["annotate", "suggestAction"],
  "script": "function evaluate(context) { return []; }"
}
FieldValuesMeaning
kindtraffic, llmMCPWhether the plugin describes ordinary inspected HTTP or model/tool/MCP activity.
publisherofficial, thirdPartyOfficial status is trusted only when package provenance verifies; unsigned packages are treated as third-party.
permissionstrafficMetadata, headerNames, appIdentity, llmMetadata, mcpMetadata, suggestActionWhich sanitized metadata families the plugin expects. These are not mutation powers.
capabilitiesannotate, suggestActionCapabilities are advisory; enforcement still uses Flowlight rules, guardrails, mock, rewrite and transform editors.

Provenance and package review

Installed packages may include a detached P-256 signature envelope next to the manifest. Flowlight binds the plugin ID, version, rule version, publisher identity, permissions, privacy categories and script digest to the reviewed package. If those values change, the package needs review again.

Unsigned local packages are allowed for development and internal sharing, but the review sheet labels them as unsigned local packages and they cannot claim official provenance. Local settings such as enabled and configuration are not part of the signed payload, so package-supplied configuration is discarded during review and local changes do not invalidate package identity.

Findings

A JavaScript plugin defines a synchronous evaluate(context) function. Flowlight passes context.manifest and a sanitized context.exchange containing only the metadata families declared in permissions. Scripts run out of process with an empty environment, a 128 KB script limit and a short timeout; failures produce no findings.

A finding is a bounded record attached to one inspected exchange. Evidence should name facts, not leak content: method, host, redacted path shape, byte counts, header names, model provider, tool names, MCP server names, approval mode and policy labels. Do not store header values, raw bodies, credentials, full tool inputs, prompts, completions or unredacted query strings.

When a manifest declares the suggestAction capability and permission, a finding can also include suggestedActions. Flowlight stores those as inert suggestions; Inspect opens the matching editor and saves only when the user reviews and clicks Save.

{
  "severity": "medium",
  "title": "High-risk tool available",
  "summary": "Claude Code declared Bash. Add a guardrail if this tool should be refused.",
  "evidence": [
    { "label": "Tool", "value": "Bash" },
    { "label": "Provider", "value": "Flowlight" }
  ],
  "suggestedActions": [
    {
      "kind": "guardrail",
      "title": "Review guardrail",
      "reason": "Refuse this tool only after reviewing the normal Flowlight guardrail.",
      "guardrail": { "agent": "claude", "server": "", "tool": "Bash" }
    },
    {
      "kind": "networkRule",
      "title": "Review Claude API traffic",
      "reason": "Create a normal Flowlight rule if this endpoint should be refused.",
      "networkRule": {
        "action": "block",
        "app": "claude",
        "destination": "api.example.com",
        "path": "/v1/messages",
        "method": "POST",
        "status": 403,
        "name": "Review Claude API traffic"
      }
    }
  ]
}

Supported guardrail providers

Official and third-party plugins can declare the guardrail provider they model. Declaring a provider does not send traffic to that provider or enable enforcement on its own; it is a label for the policy semantics and review path.

Template package

The starter package lives at templates/inspection-plugin. It includes a manifest, plugin.js, sample findings and a validator for ordinary traffic and LLM/MCP guardrail plugins. Import the manifest JSON from Settings › Plugins and Flowlight will show the review sheet before installation.

cp -R templates/inspection-plugin my-flowlight-plugin
cd my-flowlight-plugin
node validate.js

The JavaScript validator is deliberately local and boring: it checks manifest fields, provider names, capability names, permissions, privacy categories, evidence size limits and the absence of common secret-looking values in sample findings.

Review checklist

  • The plugin is advisory unless it creates a normal Flowlight rule or guardrail for the user to review.
  • For an unsigned local package, inspect the exact embedded JavaScript and compare its full digest before installing. Flowlight rejects invisible Unicode formatting controls that could misrepresent the source view; a visible preview still does not prove the code is safe.
  • Evidence is bounded and redacted; no raw bodies, prompts, completions, header values or tool inputs.
  • Permissions match the sanitized metadata the script actually reads.
  • Provider-side MCP connector findings say local network rules cannot reach provider-run calls.
  • Failures are fail-open: capture remains complete and no finding is better than blocking capture.
  • The privacy summary and categories are specific enough that a user can tell what data the plugin needs.
