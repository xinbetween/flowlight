Install

  1. With Homebrew — the same command upgrades it later:

    brew install --cask xinbetween/tap/flowlight

  2. Or download Flowlight.dmg, open it and drag Flowlight into Applications.
  3. Prefer an installer? Every release also has a .pkg.
  4. Building from source needs Xcode 16 or later and xcodegen:
brew install xcodegen
git clone https://github.com/{{repo}}.git && cd flowlight
xcodegen generate && scripts/build-local.sh
open build/Build/Products/Release/Flowlight.app

First launch

Releases from 0.1.6 are signed with a Developer ID certificate and notarized by Apple, so the first launch just works. You can check it yourself: spctl -a -vvv /Applications/Flowlight.app should answer Notarized Developer ID. Versions up to 0.1.5 were unsigned; those need System Settings › Privacy & Security › Open Anyway once.

Traffic starts appearing within a second. The ↓↑ figures in your menu bar are live download and upload rates.

Hostnames: the one-time setup

By default macOS only tells Flowlight the IP address each app talks to. To show real hostnames, Flowlight reads two things from network packets: DNS answers, and the server name a client asks for when it opens an HTTPS connection (TLS SNI). A filter in the kernel drops every other packet before Flowlight sees it, and packet contents are never stored.

macOS only lets administrators read packets, so the Name Your Traffic window asks for your password once. It installs /Library/LaunchDaemons/com.flowlight.bpf-access.plist, which gives the access_bpf group read access to /dev/bpf* at each boot, the same approach Wireshark uses. Remove it any time from Capture › Remove Packet Capture Access.

Identify network owners labels traffic with no hostname by who operates the address (Cloudflare, Inc. · AS13335). It's on by default and sends those public IP addresses (never private ones) to Team Cymru's DNS service. Turn it off in Capture.

Language

Flowlight is translated into English, 简体中文, 繁體中文, 日本語, 한국어, Français, Deutsch, Italiano, Español and Português. By default it follows your Mac: if your preferred languages include one Flowlight speaks, that is what it uses — and for Chinese it tells Simplified from Traditional by script and region, so a Mac set to zh-TW gets Traditional. Anything it hasn't been translated into falls back to English.

Pick a language explicitly in Settings ⌘, under General. It changes immediately rather than on next launch. When the choice is System, the row says underneath which language that turned out to be.

Translation is arriving screen by screen: navigation, settings and the common controls are done, and the longer explanatory passages are still English for now — a key with no translation shows correct English rather than a blank or an identifier.

AI agent rules

An app counts as an agent if Flowlight knows it by name (16 today, including Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Ollama and ZCode) or if it calls one of {{providers}} LLM API providers. Browsers are excluded.

Tools & MCP servers

Agents do much of their work through other processes: a shell tool runs curl, git or npm, and MCP servers run as their own processes. Flowlight follows each process's parents back to the agent that started it, so that traffic is counted as the agent's. In AI Agents, the agent's detail lists these under Tools & MCP servers, and destinations read via curl or via github MCP. In Reports, the process row reads via Claude Code.

MCP servers are named by matching their command line to the MCP configuration of Claude Code (~/.claude.json), Claude Desktop, Cursor (~/.cursor/mcp.json), Windsurf, VS Code, Codex (~/.codex/config.toml), Zed and Gemini CLI. Remote MCP servers are matched by the hostname in their URL, and unconfigured servers by recognizable package names such as @modelcontextprotocol/server-github.

Attribution is per process: Flowlight can't tell which individual tool call inside a long-running MCP server opened a connection.

Agent configuration: what Flowlight reads on your Mac

An agent's abilities are written down in files: the skills it can load, the subagents and slash commands it defines, the hooks that run shell commands on events, the permission rules it was given, and the MCP servers it starts. Flowlight reads those files so the Tools tab can show what each agent is set up to do, even before it makes a single request. A hook that posts to a webhook, or a rule that allows Bash(curl:*), explains traffic you'd otherwise have to guess at.

  • Where it looks by default: the agent folders in your home folder — ~/.claude, ~/.codex, ~/.cursor, ~/.gemini, ~/.agents and the like. It does not walk your whole home folder, so macOS doesn't have to ask for access to Desktop, Documents or Downloads.
  • Your projects: use Add project folder… to point Flowlight at where your code lives. macOS then grants access to that folder only. If the folder sits inside Documents or Desktop, macOS asks first, and that's the one prompt you'll see.
  • Once, not constantly: the result is remembered. Flowlight rescans only when you click Rescan, and offers one after a couple of weeks in case you've added agents or projects. Nothing is scanned in the background.
  • What it keeps: names, descriptions, the command a hook runs, and MCP server commands or URLs. It never copies your code, your prompts or your files, and none of it leaves your Mac. Forget what was found clears it.

Worth a look

A third mode in Reports, beside the breakdown and the charts. It compares the apps in the report with each other and points at the ones whose destinations don't look like the rest: many more places than their peers, addresses that never resolved to a name, hostnames that look generated rather than chosen, far more sent than received, and protocols that are a sideline rather than the app's purpose. Each finding carries the evidence behind it, and clicking one narrows the report to that app.

It is called Worth a look and not Suspicious deliberately. What the data supports is "unusual next to the other apps in this report" — a backup tool talks to a lot of places for good reasons, and a quiet Mac produces no findings at all. It says nothing about traffic every app shares.

Which way the bytes left

Not all traffic goes to the internet. AirDrop, Handoff, AirPlay, Sidecar and Universal Control go straight to a device in the room over Apple Wireless Direct Link — no router, no internet, and no address anyone else can reach. Flowlight was always counting those flows; it had no word for them, so an AirDrop of a 4 GB folder looked like a few megabytes to an address with no name.

Every flow now carries a channel: Network, Peer-to-peer Wi-Fi, This Mac (loopback, which never left the machine) or Tunnel (inside a VPN; where it went after that isn't visible here). Narrow a report to one of them from the Reports toolbar, and it travels with CSV exports and with anything sent to a collector.

Peer-to-peer rows are named by the feature that opened them — AirDrop and Handoff · nearby device, Continuity · nearby device — because a link-local address tells you nothing and the device in the room has no name this Mac can learn. An app that uses the radio directly keeps its own name, which is the truthful answer for it.

The two engines answer differently. The sampler reads the interface each socket is bound to (awdl0, llw0), which is exact. The Network Extension is handed sockets rather than interfaces, so it judges by the address instead: a link-local address is how peer-to-peer traffic is addressed. That is the coarser of the two — a printer reached over Ethernet can be addressed the same way — and Flowlight would rather say so than round it off.

Nothing here is newly recorded, and no new permission is involved. It is the same capture, finally labelled.

Other alerts

  • Traffic spike: an hour at least 3σ above the app's rolling baseline (after 24 hours of history, above 1 MB).
  • Unusual number of destinations in a day, against the app's baseline.
  • Upload above 99th percentile of the app's hourly uploads over 30 days.
  • First contact with a new domain, and non-standard ports, after a 24-hour learning period per app.
  • Traffic without UI activity: a windowed app you haven't used for 10 minutes uploads more than 5 MB a minute.

Apple's own apps are left out by default. macOS contacts Apple constantly — Software Update, iCloud, push, time, Maps tiles — on hosts and ports that are new the first time they appear, and listing all of it buries the one line worth reading. Turn it off in Settings › Alerts if you want them. Either way the traffic is still recorded, still appears in Live, Reports and Ask, and is still subject to every rule, guardrail and allowlist: the setting decides what is listed, never what is allowed.

Ask

Ask in plain language — what did Claude Code upload yesterday?, which app started talking to somewhere new this week?, summarise the last hour — and get an answer from the history recorded on this Mac.

The model never gets your history. It is handed a list of seven read-only queries it may call and nothing else: totals, top apps, top destinations, new destinations, alerts, agents, and a series over time. There is no query that takes SQL, and there will not be one — a model that can write its own query can read anything. Flowlight runs whichever the model names, locally, and hands back the totals and names. What leaves the Mac, if anything does, is your question and those numbers — never the database.

Local first. Where macOS provides an on-device model, that is the default: it costs nothing, works offline, and sends not one byte anywhere. Otherwise a model server you already run — Ollama, LM Studio, llama.cpp — does the same. Both are listed above the hosted options because a tool whose promise is no account and no cloud should not need either to answer a question about itself.

Or bring your own key for Anthropic, OpenAI, Gemini or any OpenAI-compatible endpoint. The key goes to your login Keychain, not to Flowlight's preferences. When a provider sends anything off the Mac, the screen says so before you ask, and every request is shown in full under the answer.

It answers questions about Flowlight itself, too. How do I turn on HTTPS inspection?, how do I stop an agent using its shell tool?, why am I not seeing any traffic? — those are answered from the app's own written-down guide to every feature, and from a snapshot of how this Mac is currently set up. Never from the model's memory: menu paths differ between versions, and an invented one is worse than no answer. When the answer needs a switch changed it says where the switch is and offers to open that screen, which is a click you make.

Charts when the shape matters. Change over time comes back as a line, a comparison as bars, a split of one whole as a pie. Flowlight draws them from the same rows the query returned, so the picture and the sentence cannot disagree, and the model can ask for a different shape or for none at all.

Every query is listed under the answer, and clicking one opens those rows in Reports. An answer you can't check is a guess with better grammar.

Flowlight holds itself to its own standard. Whatever this feature sends appears in Live and Reports like any other app's traffic — including when the model server is on this very Mac, which is the case it would have been easiest to quietly leave out.

HTTPS inspection (optional)

Off by default. When you turn it on in Inspect, Flowlight runs a local proxy on 127.0.0.1:8877 with its own certificate authority, created on your Mac. For apps you route through it, it decrypts HTTPS and shows each request and response: headers, bodies, status and timing. From an AI agent's model responses it reads every tool call the model asked for (Anthropic, OpenAI Chat and Responses, Gemini, and MCP tools/call requests) and the result the agent sent back, and it links each request a tool makes back to the call that caused it: curl's request to paste.example shows ← Bash: curl -s https://paste.example/up. In AI Agents, an agent's detail gets Tool calls (each call with its command, result or error, and the requests it made) and MCP servers (name and version, local or remote or via provider, the tools it offers, calls and failures) and Tools (every tool the agent declares to the model, with how often each was used). The agent's header line shows the model, the number of calls and the tokens spent, including cached ones. Bodies open as a collapsible JSON tree in their original key order; event streams show one event at a time.

Agents declare their tools on every turn, so an inspected request shows more than the calls themselves: the tools the agent offers, the ones the provider runs on its own servers (web search, code execution), and the MCP servers the provider connects to for the agent (Anthropic's mcp_servers, OpenAI's mcp tool) with their URL, token, approval setting and allowed tools. That last group never appears on your network, because the provider makes those connections, not your Mac.

Setting it up is one switch. Turn on HTTPS inspection in Inspect and Flowlight creates its certificate, asks for your password once, trusts the certificate and routes apps through the proxy. Turning the switch off undoes all of it. The proxy file falls back to a direct connection whenever Flowlight isn't running, so quitting it never cuts your Mac off.

Command-line agents ignore system proxy settings, so for Claude Code, Codex, Gemini CLI or Aider use Open Inspected Terminal and start them there. Under Advanced you can decrypt AI agents only instead of every app, edit the never-decrypt list, copy the shell setup for one shell, or remove the certificate and everything recorded.

Flowlight excludes its built-in list of Apple services and password managers from decryption (edit the list in Setup). Apps that pin their certificates may reject the Flowlight certificate; Flowlight notices and passes them through encrypted. API keys, cookies and other credential headers are never stored, recorded requests are kept 3 days, and Remove Certificate & Recorded Data deletes the certificate, its trust setting and everything recorded. Inspection is HTTP/1.1 only (Flowlight asks both sides for it) and not available in demo mode.

Mock responses

To see how an agent copes when an API fails, stalls or returns something odd, answer that endpoint yourself. In Inspect › Mock responses, a rule names a host, a path and a method, and gives the status, headers, body and an optional delay to reply with. The request is never sent: Flowlight answers it.

  • Host is exact — api.example.com — or *.example.com for a domain and its subdomains. Exact by default, because a mock aimed at one endpoint shouldn't quietly answer for a whole domain.
  • Path takes one * wildcard: /v1/*, /v1/*/items, or an exact path. The query string is ignored unless your pattern has one.
  • Method matches one verb, or any.
  • Rules are ordered and the first enabled match answers. Each switches on and off on its own.

A mocked exchange is recorded like any other and marked Mocked in the list, with the detail pane saying it was answered by Flowlight rather than by the host, and naming the rule. You can always tell later what was real.

Two things worth knowing. Only traffic Flowlight decrypts can be mocked, so the endpoint has to be going through HTTPS inspection — a rule for a host makes Flowlight decrypt that host even if your scope is agents only. And the destination is still connected to: a mock changes the answer, not whether the connection can be made, so "the API returns 500" works while "the API is entirely unreachable" does not.

Rules

An allowlist is one agent's idea of where it may go. A rule is the general version: it names a subject — an app, an agent, a destination, a URL, or a pairing of two of those — and says block or allow. Right-click any row in Live, Reports, AI Agents or Inspect to write one about what you're looking at; every one of them lands in the same editor on the Rules screen, because a rule that took effect out of sight would be a rule you could never find again.

Templates. Twenty-two of them, in five groups — stopping an agent reaching package registries or other model providers, closing the common ways data leaves (paste sites, webhook catchers, anonymous file drops, tunnels, DNS over HTTPS), product analytics and crash reporting, working-hours policies, and one-off "block this for an hour while I work out what it is". Browse them from the Rules toolbar, or right-click a row anywhere in Live, Reports, AI Agents or Inspect and apply one to what you're looking at.

Each template says what it will do before it does it. Anything that writes more than one rule opens a card listing every host and schedule; anything permanent opens the editor pre-filled; and only rules that undo themselves — an hour, or this run of Flowlight — are ever applied without being shown first. Each carries its caveats too, including which engine it needs: a template that only works with HTTPS inspection says so.

Which rule wins. The most specific match decides, and where two rules are equally narrow the block is the one that stands. So an exception written underneath a broad block works — Cursor may reach api.github.com survives nothing reaches github.com — while an exception broader than what it excepts does not quietly widen it.

For how long. Forever; until a time; until Flowlight quits; or between chosen hours on chosen days. Hours are local and judged at the moment a connection is made, so a Mac that slept through the end of a window finds it closed on waking, and a clock or timezone change moves the window with it. A window closing stops new connections — it doesn't tear down ones already open. There is also one global Pause Blocking, because the escape hatch is what makes strict rules liveable.

Unblocking is part of blocking. Every refusal carries its way out: from the alert, allow it once, for an hour, or until Flowlight quits. Each of those is itself a rule with an expiry, so the list can always answer why is this getting through? — including for the relaxation you clicked past a fortnight ago.

Where a rule bites, and where it can't. The Network Extension refuses whole connections: it knows the host, the address and the port, nothing about paths, and only in extension mode. HTTPS inspection refuses one request, so it can match a URL and answer with a status the agent can read instead of a socket that died without saying why. The nettop sampler cannot refuse anything at all. A rule the current setup can't carry out says so in the list rather than sitting there looking enforced.

The second tab is the violations feed: every connection a rule decided, with the app, where it was headed, which rule decided it and whether that was a refusal or an exception letting it through.

Allowlists

Select an agent in AI Agents and use Allowlist in its detail to say where it may connect. Enter domains (subdomains included), IP addresses or CIDR ranges, or pick a preset: GitHub, npm, PyPI, Homebrew, Docker Hub, Rust crates, Go modules or Apple. The agent's AI providers (unless you turn that off) and your local network are always allowed.

From then on, anything the agent or its tools contact that isn't listed raises a critical Allowlist violation alert (once per domain every 6 hours) and is marked Not allowed, with an Allow button that adds it. An allowlist warns rather than refuses by default connections; blocking needs the Network Extension engine and is on the roadmap.

Refusing connections

An allowlist warns by default. Turn on Refuse connections outside the list for an agent and it will also refuse them: the connection is dropped and an alert records what was refused, with Allow … from Now On to add it to the list in one click. The agent's next attempt goes through.

It needs the Network Extension. Refusing a connection means sitting in its path, which the nettop sampler cannot do — Capture will say so rather than offer a switch that does nothing.

Some things are never refused, whatever a list says: your local network, DNS, Apple's own services, and Flowlight's own traffic. A blocked Mac is a worse outcome than a blocked agent, so where there is doubt the connection is allowed and recorded. Enforcement also lapses a few seconds after Flowlight stops running — a refusal nobody can see is worse than none, and the way to undo one lives in the app.

HTTPS inspection and blocking don't combine: traffic routed through Flowlight's proxy leaves as Flowlight's own, which is never refused.

Agent guardrails: block a tool, a server or a resource

Which tools may this agent use is a different question from which hosts may it reach, so it has its own section: a Guardrails tab beside each agent in AI Agents, with a switch on every tool it declares and every MCP server it reaches, presets worth having (read-only, no shell, no writes), and a record of what has been taken away.

The strongest lever is the declaration. Agents re-send their whole tool list on every turn. Flowlight removes a refused tool from that list before the request leaves, so the model is never offered it: no refusal to argue with, no retry loop. It works the same for a tool the agent runs itself and one behind a remote MCP server, and it reads the same shapes Flowlight already parses for Anthropic, OpenAI and Gemini.

A refused call is answered properly. For MCP servers reached over HTTP, a blocked tools/call comes back as a result carrying isError: true and a plain sentence, because that is what the protocol says a failing tool looks like — the model reads it and works around it, where a transport error would look like a broken server. resources/read and prompts/get have no such shape, so they get a JSON-RPC error instead.

Connectors are narrowed, not intercepted. When the provider reaches an MCP server on the agent's behalf, that traffic never touches this Mac. The only lever is the request that sets it up, so Flowlight narrows the tools the connector is allowed to call, or drops the connector entirely.

Local stdio servers speak over pipes, and no proxy can see that. What Flowlight can do there is watch the server process's own network traffic, which is already attributed to the agent that started it, and hand you the deny list to paste into the agent's own settings — Claude Code takes mcp__server__tool in permissions.deny, and its neighbours have equivalents. That takes effect when the agent restarts.

Guardrails need HTTPS inspection, because the tool list lives inside a request body. With inspection off the tab says so rather than looking as though it is working.

This is not a sandbox. A refused tool stops being offered and stops being answered. An agent that still has a shell can do by hand what the tool would have done. Flowlight will record that; it does not pretend to prevent it.

Capture: engines and sources

Flowlight records traffic one of two ways, chosen in Capture. They differ in what they can miss, which is worth understanding before you rely on either.

nettop sampler (default)Network Extension
NeedsNothingInstalling a system extension, and your approval
How it sees trafficReads running totals once a second and records the differencemacOS calls it as each connection is made
Long transfersCounted exactly, however burstyCounted
Short connectionsCan be missed entirelyRecorded, however brief
EnergyStarts a process every secondLower — no polling

What the sampler misses is whole connections, not bytes. Because it compares running totals, nothing that lasts across two readings is lost, no matter how much arrives in between. What never appears is anything that starts and finishes between them — a quick DNS lookup, a fast API call, a script that runs curl and exits. For watching an agent that makes many short requests, that difference matters.

The extension is in the data path instead, so a request lasting five milliseconds is recorded like any other. It isn't magic either: traffic from before you enabled it isn't there, some system traffic is exempt from content filters, and its byte counts come from the filter's own statistics rather than from counting packets. It refuses a connection only where a rule or an allowlist you wrote says to.

When the extension stops answering. macOS runs whichever build of the extension was activated last, so after an app update the two can disagree — and when they do, macOS refuses the connection between them. System Settings says the filter is enabled, Flowlight says the connection was invalidated, and neither changes its mind. Flowlight now climbs out of that by itself: it redials a couple of times, then asks macOS which build it is running and reinstalls the extension if it isn't this app's, and if none of that works it captures with the nettop sampler so there is still data — saying so plainly, and leaving your chosen source alone. Try the extension again under Network Extension starts over.

It also can't run at all on some Macs. macOS allows one content filter at a time, and corporate security software normally holds it — Palo Alto Networks GlobalProtect, CrowdStrike Falcon and the like. Flowlight's filter will install and connect on those machines and then never be handed a connection. Capture lists any it finds and offers to switch you back to the sampler, which needs no filter and works alongside them. See the developer guide for how it's built.

Devices: Bluetooth, USB and external storage

A Mac sends and receives over more than TCP and UDP. The Devices screen covers the rest, and it is off until you turn it on — not because it needs a permission Flowlight doesn't already have, but because watching more of your Mac should be your decision rather than something an update did.

Bluetooth shows which devices are paired, which are connected, and when that changed, read from the system every half minute. Beside it is the list of applications built to use Bluetooth, taken from each app's own Info.plist.

What it can't tell you, and says so. There are no byte counts here. macOS keeps no per-app accounting for Bluetooth, and the byte-level HCI traces that would give one need Apple's PacketLogger profile, which an ordinary app cannot read. The app list is likewise who asked for Bluetooth, not who was granted it: macOS keeps the grants in a database an app can't open, and Flowlight would rather name that difference than blur it.

USB and external storage lists what is attached — what it is, who makes it, and a drive's capacity — and records when each one arrived and left. The two halves work differently on purpose: USB devices are read from the system periodically, while volumes come from the workspace the moment one is mounted or ejected, because a drive appearing is the event people actually care about. Throughput isn't here either, for the same reason it isn't under Bluetooth.

Focus mode

Pick a few apps and destinations and every screen shows only those — Live, Reports, Alerts, AI Agents and Inspect, and the rates in the menu bar. It's for watching one agent work without the rest of the Mac in the way.

  • Right-click any row in Live, Reports or AI Agents and choose Focus on…, or use the Focus control at the bottom of the sidebar to pick from the apps that have been active and to type destinations.
  • ⇧⌘F turns Focus on and off, and so does the menu bar, which also shows what's focused.
  • A destination takes its subdomains with it: example.com covers api.example.com. IP addresses work; ranges like 10.0.0.0/8 don't.
  • Apps and destinations are a union, not an intersection: focusing on Claude Code and github.com shows everything Claude Code does plus everything that talks to GitHub.

An app and a destination are equally a focus, and either alone is enough. Add an app by typing its name or bundle identifier — every application on the Mac is searchable, so one that has been quiet all day can still be focused, as can a command-line agent with no application bundle — or tick one from what has recently been busy. Add a destination the same way.

One thing a destination can't narrow: alerts record the app that raised them and nothing about where the traffic went, so a focus made only of destinations leaves the alert list alone. The editor says so rather than letting a screen quietly ignore it.

Focus filters what you see, never what's recorded. Flowlight keeps capturing and storing everything while it's on, and the anomaly baselines keep learning from all of it, so turning Focus off shows the traffic it was hiding. One consequence: an alert names the app that raised it and not where the traffic went, so focusing only on destinations leaves the alert list as it was.

Running in the background

Flowlight keeps recording with its window closed, and costs almost nothing while idle — it stops building charts nobody is looking at. Settings › General › Run in the background goes further and drops the Dock icon and the Cmd-Tab entry; the menu bar keeps the live rates and gains Show Dock Icon to undo it. Launch at login is in the same place.

The window opens where you left it, at the size you left it. A first run fills the screen instead, so nothing is hidden behind a small default window, and a window whose saved position is off-screen — an unplugged display — comes back on the screen you have. Hostname setup is offered a little after launch and only while a window is open, rather than greeting a first run with a request for your password; the offer returns next launch until you take or dismiss it.

Quitting Flowlight stops the sampler. It does not stop the Network Extension: a system extension runs on its own, so the filter carries on inspecting connections until you disable or uninstall it in Capture.

Export to OpenTelemetry or a SIEM

Off until you configure it, and there is no Flowlight service to send to. You name the endpoint — your own collector, your own SIEM — and nothing leaves until you do. Settings › Export.

  • OTLP over HTTP with a JSON body: rollups go to /v1/metrics, alerts to /v1/logs, because an alert is an event with a sentence attached and a metric would lose the sentence. Newline-delimited JSON is there for collectors that just want lines.
  • Exactly what leaves is listed in the panel, field by field, and a preview shows a real payload built from your own data before anything is sent.
  • Never anything from HTTPS inspection. No headers, no bodies, no tool calls — the export can only carry rollups and alerts, so there is nowhere for them to go even by accident.
  • Auth headers are kept in your login Keychain, not in preferences. Only their names are ever displayed.
  • What Flowlight sends shows up in Flowlight, in Live and Reports, like any other app's traffic — including a collector on 127.0.0.1.

Two things to expect: rollups are folded about two minutes behind, so an interval under a minute polls more often without data arriving sooner; and Test connection proves the endpoint answers, not that it validated your credentials — the "last successful export" line is the honest signal.

Your data

Everything lives in ~/Library/Application Support/Flowlight/traffic.sqlite. Per-second rows are kept 6 hours (adjustable), minute rows 14 days, hourly rows 400 days, daily rows indefinitely, and alerts 90 days. Capture › Clear all data deletes it.

Updates

When a new version appears, Flowlight tells you with a notification and a badge in the sidebar rather than interrupting what you're doing; clicking either opens the update window. A check you start yourself opens it straight away.

Flowlight checks GitHub for a new release on launch and once a day, and Check for Updates… is in the app and menu bar menus. Download fetches the disk image to Downloads and checks it against the release's published SHA-256. Nothing is installed until you choose: Quit & Install closes Flowlight, replaces it with the new version and reopens it, keeping your history and settings. Install Later keeps you working. If Flowlight was installed with the .pkg, macOS asks for an administrator password to replace it. Turn the check off in Settings › General.

Updating by hand? Quit Flowlight first (menu bar icon › Quit), then drag the new version into Applications. Finder can't replace an app that's still running and says the item is in use.

Demo mode

open /Applications/Flowlight.app --args -FLDemo YES starts Flowlight with 90 days of synthetic traffic in a separate database, so you can look around without recording your own. It's what the screenshots on this site show.

Uninstall

  1. In Capture, choose Remove Packet Capture Access (asks for your password) if you enabled it, uninstall the content filter if you installed it, and turn HTTPS inspection off in Inspect so its certificate leaves your keychain. Only Flowlight itself can withdraw those three.
  2. Quit Flowlight and move it from Applications to the Trash — or, if you installed it with Homebrew, brew uninstall --cask flowlight.
  3. Delete ~/Library/Application Support/Flowlight to remove the recorded history, or let Homebrew do it with brew uninstall --zap --cask flowlight.

Questions & answers

Why did macOS ask Flowlight for access to my Desktop or Documents?
Only because you pointed it at a project folder inside one of them. By default Flowlight reads agent configuration from the folders in your home folder and never touches those three.
Does Flowlight see all my traffic, or does it miss some?
It depends which capture engine you use, and the difference is not subtle. The default sampler reads macOS's running byte counters once a second and records the change, so a long transfer is counted exactly — but a connection that opens and closes between two readings never appears at all. The Network Extension is called by macOS as each connection is made, so even a five-millisecond request is recorded. If you're watching an AI agent that fires many short requests, install the extension from Capture. The full comparison is above.
I turned on the Network Extension and nothing appears. The sampler works fine.
Almost always because another content filter already has the slot. macOS runs one content filter at a time, and corporate security software usually claims it — Palo Alto Networks GlobalProtect, CrowdStrike Falcon and similar. Flowlight's filter still installs, activates and connects, so Capture says Connected to filter extension, but macOS never hands it a single connection and the screens stay empty. Capture lists the filters it finds and offers to switch you back to the sampler, which doesn't use a filter and works alongside them. You lose only the very short connections (the comparison); everything else is recorded the same way.
The extension stopped working after Flowlight updated.
Versions before 0.2.5 had this: macOS keeps running whichever build of the extension was last activated, so after an update the extension was the old version and macOS refuses the connection between a mismatched pair. From 0.2.5 Flowlight checks at launch and re-activates the filter itself. On an older version, press Install & enable filter in Capture once.
Something else is wrong with capture and I don't know what.
Run this and read what it prints — it reports state and counts only, never anything Flowlight recorded about your traffic:

curl -fsSL https://raw.githubusercontent.com/{{repo}}/main/scripts/diagnose.sh | zsh

It shows which extensions are installed, whether macOS actually started Flowlight's filter, and how recently anything was recorded. Paste it into an issue.
Does Flowlight send anything about me anywhere?
No. There's no account, no telemetry and no analytics. The only requests it makes are the daily update check, optional network-owner lookups, and reverse DNS — each listed, and each with an off switch, on the privacy page.
Will it slow my Mac down or drain the battery?
With the window closed Flowlight does almost nothing: it keeps the menu bar rates and writes one row a second. The Network Extension costs less than the fallback sampler, which starts a short-lived nettop process every second.
Can it block connections?
Yes, with the Network Extension. An agent's allowlist can refuse as well as warn, a rule can block an app, a destination or a URL for as long as you say, and a guardrail can take a tool away from an agent before its model is offered it. Nothing blocks until you ask it to, and every refusal carries its way out.
Do I need the Network Extension?
No. The sampler needs no entitlement and covers most traffic. The extension adds flows shorter than a second, attribution by code signature, hostnames without the packet-capture setup, and is the only engine that can refuse a connection.
What happens to my data if I uninstall?
Everything lives in ~/Library/Application Support/Flowlight. Delete that folder and it's gone; see Uninstall for the packet-capture helper and the inspection certificate.

Limitations

  • TCP and UDP only. ICMP (ping) and other raw-IP protocols aren't attributed.
  • Attribution is per process, not per thread.
  • Unless you turn on HTTPS inspection, Flowlight reads metadata only and never decrypts traffic. QUIC server names come from DNS rather than the encrypted handshake.
  • Inspection only sees apps that use the proxy, and never apps that pin their certificates.
  • Hostname capture follows the primary network interface.
