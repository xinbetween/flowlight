### What's new in 0.17.8

- **Account for every AI agent.** Agents combines installed apps, configured workspaces, known launchers, and observed traffic into one inventory. Health is explained through concrete evidence, routing, inspection, policy coverage, and unresolved alerts instead of an opaque score.
- **Take alerts from new to resolved.** Alerts supports new, acknowledged, investigating, resolved, and dismissed states, plus dispositions, notes, and bulk actions. Triage remains separate from policy Allow actions, and the sidebar badge counts only new alerts.
- **Manage inspection extensions where they work.** The Developer edition moves plugin packages into Inspect › Plugins & Providers and adds versioned local provider profiles with compatible plugin assignment, validated endpoints, non-secret options, and optional Keychain references. Raw credentials are never stored in a profile.
- **Inspect Live traffic without relying on color or a pointer.** The Live chart adds keyboard traversal, VoiceOver details for each second, strict plot hit testing, and distinct solid/circle and dashed/diamond series. Download and upload colors now pass executable light/dark contrast, chroma, and color-vision checks.
- **Keep redesigned paths within measured limits.** Fail-capable numeric budgets cover startup, a 600-edge graph, a 10,001-row History query, a 10,000-alert query, a 1,000-agent inventory, and 30,000 built-in plugin evaluations, with fixture size, observed time, and budget in every failure.
- **Carry the completed unpublished work forward.** The unpublished 0.17.4, 0.17.5, 0.17.6, and 0.17.7 changes ship here: Policies preserves every policy type's authoritative editor and evidence, Sources is one Collector–Devices–Coverage document, History clears pointer details without synthesizing a keyboard selection, and release review receipts remain valid when GitHub hides a trusted reviewer's private organization membership from the workflow token.
- **Reuse CI only when the evidence is exact.** Pull-request app jobs may reuse a successful canonical run only when its complete Git tree, app-input fingerprint, required conclusions, receipt schema, head repository, run identity, artifact digest, and expiry match. Invalid, stale, or forked evidence runs the current jobs instead of silently succeeding.
- **Deploy only the site CI verified.** Pages consumes the exact manifested site artifact from successful canonical `main` CI, performs no checkout or rebuild, and rechecks the current `main` SHA immediately before deployment. Weekly full Swift, Python, and Actions CodeQL remains in place.
- **Keep untrusted pull-request refs out of checkouts.** Merge compatibility uses GitHub's trusted `pull_request` event merge commit rather than constructing a checkout ref from pull-request input, resolving code-scanning alert 4 without moving the job to a privileged event.
- **Sign each release once.** The immutable tag run builds, signs, notarizes, Gatekeeper-verifies, stages only the exact DMG, PKG, checksums, notes, and manifest into a clean bundle, attests, and retains one artifact. Credential-free publication can only verify and publish those exact prepared bytes, authenticated review evidence is fetched directly for each exact-head pull request, and an accepted Apple ticket can survive a bounded multi-minute CloudKit delivery outage without resubmission.

### Install

Signed with Developer ID and notarized by Apple.

- `brew install --cask xinbetween/tap/flowlight`
- `Flowlight.dmg` — drag to Applications.
- `Flowlight-0.17.8.pkg` — installs to /Applications; offers to quit a running copy first.

macOS 15 or later, Apple silicon and Intel.

Full changelog: https://github.com/xinbetween/flowlight/releases
