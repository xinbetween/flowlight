### What's new in 0.18.11

- **Make advisory catalog availability verifiable.** Flowlight now ships the signed advisory catalog at the endpoint used by the app, so a missing public route no longer leaves every local artifact in the catalog-unavailable state.
- **Keep catalog trust unchanged.** The endpoint serves the exact signed envelope already bundled with Flowlight; catalog matching remains local, inventory is never uploaded, and signature, freshness, rollback, and recovery checks remain enforced.
- **Be clear about the initial catalog.** This release contains an intentionally empty signed catalog. It enables a verified catalog state but does not claim that software is safe or report CVEs until a separately reviewed and offline-signed advisory catalog with real records is published.
- **Recover HTTPS inspection safely.** Inspection remembers the user's enabled intent across relaunches and upgrades, while remaining stopped until the extension confirms the exact rule-pack generation and digest. A visible retry action helps recover from temporary synchronization failures without weakening the fail-closed barrier.
- **Make version evidence useful.** Explicit, bounded probes now use fixed profiles for common tools such as Wget, Swift, kubectl, Python, and Pip, and show why a version could not be identified instead of collapsing every result into “Unknown version.”
- **Group package inventory clearly.** Homebrew, npm, and bounded metadata-only coverage for ten language package ecosystems appear under one Packages filter while their ecosystem-qualified identities remain separate for advisory matching.
