# Flowlight 0.18.0 UI and accessibility audit

- Date: November 11, 2026
- Candidates: Developer and Mac App Store editions 0.18.0 (84)
- Minimum window: 1000 × 660 points
- Store artwork: 1440 × 900 points / 2880 × 1800 pixels

## Result

No release-blocking UI or accessibility defect was found in the exact local 0.18.0 source candidates. The audit covered the Connections redesign, Sources segmentation, restored Policies evidence and actions, Store Inspect setup and synthetic inspection activity, AI-agent inventory/detail contrast, deterministic screenshot motion, and the Developer/Store capability boundary.

Signed Store entitlement and runtime acceptance is not claimed here. It remains a blocking archive and real-Mac gate in `packaging/app-store/0.18.0-submission.md`.

## Automated gates

Coverage includes terminal acknowledgement and queue eviction for generation-stale extension decisions while app-local stale refusals remain fail-open, request-level allow/block precedence without suppressing configured mocks, and truthful HTTP-only and attribution-waiting states across app-scoped rules, allowlists, managed packs, and guardrails.
- Store-hosted suite: 32 tests, zero failures, including native DNS/IP certificate chains, effective SSL trust decisions, exact IPv4/IPv6 client-address/source-port/proxy-port/generation attribution, mismatches, unknown identity, ambiguous reused-tuple fail-open behavior, stopped-filter health, invalidation of a prior cached owner after an authoritative attribution miss, identity-independent policy without trusted app identity, durable guardrail refusal, resolved-IP/CIDR allowlists, unknown-owner TLS pinning, custom enforcing-policy ancestry, sandbox-correct data-deletion guidance, one-time Developer-to-Store migration, inherited routing preservation/detection, enablement and startup policy barriers, and the complete attribution-readiness gate.
- Developer Release and Store AppStore product graphs compile independently as 0.18.0 (84).
- Xcode project drift: committed project and schemes match `project.yml` in both the working tree and Git index.
- Site: 53 generated pages, ten languages, zero checker problems.
- Release helpers: notarization, rule-pack policy, Swift warning fixtures, CodeQL gate policy, Homebrew update, change classification, workflow evidence, release checks, artifact checks, and release workflow fixtures pass.
- Chart palette: light/dark contrast, chroma, normal-vision, protan, and deutan checks pass; adversarial fixtures pass.

## Blocking signed-Store acceptance still required

- Obtain the authorized signed archive from the exact reviewed head; do not locally re-sign it as a workaround.
- Verify distribution profiles, fully expanded App Group, protected entitlements, binary digests, exact Store-only selectors, and every forbidden helper/framework/symbol/path check.
- Install through the recorded authorized channel and prove Store extension connectivity, **Data is arriving**, native CA creation, manual import/trust, explicit Safari routing, HTTPS decryption, audit-token attribution, guardrails, mocks, request rewrites, managed packs, and visible fail-open behavior.
- Prove removal of app-owned keys/generated certificates/recordings, restore manual proxy settings, and separately remove the user-owned imported CA.
- Reconcile privacy answers, prior App Review correspondence, metadata, screenshots, uploaded archive, processed build identity, and review notes before final submission.

## Limits

- Local Store UI evidence came from an unsigned product and cannot prove protected Store entitlements or a working signed content-filter connection.
- The SDK precompiled-module path notices seen during universal Release builds are Xcode toolchain notices; the first-party Swift warning gate passes.
- App Store Connect was not mutated during this audit. No archive was uploaded, no build was selected, and **Submit for Review** was not pressed.
