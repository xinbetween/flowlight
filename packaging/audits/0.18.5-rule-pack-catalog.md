The generator accepts optionless canonical ABP block rules. Canonical hostname exceptions, including scoped exceptions Flowlight cannot represent, conservatively suppress host-layer coverage. Legacy IDs 1–12 stay permanently mapped and are never reused, but exception-overlapping parent suffixes are not forced back into the generated catalog. Mutable branches, arbitrary origins, hash drift, unsafe public suffixes, protected manual entries, PubADX overreach, and a non-superset aggressive tier are fail-capable negative fixtures.

The app never fetches raw GitHub or upstream list data. A release bundles the exact signed catalog, and accepted updates are retained as the verified last-known-good cache; source-host or feed outages delay updates without removing active enforcement.

## Lost-key signer transition

The private key for `flowlight-rule-packs-2026-01` was unavailable when sequence 3 required a new signature. Flowlight 0.18.5 therefore retains the old public key for historical sequence-2 verification and adds `flowlight-rule-packs-2026-11` as the sequence-3 production signer. This is a break-glass lost-key transition, not a normal dual-signed rotation: pre-0.18.5 clients cannot verify sequence 3 and must continue enforcing their verified sequence-2 last-known-good catalog until the app upgrade installs the new trust anchor. The replacement private key is stored outside the repository with owner-only permissions; only its public key is committed.

Do not reuse sequence 3 for changed content. Any correction after publication requires a new higher sequence and, after a public release tag, a new patch release.
